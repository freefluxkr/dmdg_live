복잡한 .md 문서를 헤매지 않고, 3대 계층(헌법·출판·개발)의 규칙과 체크리스트를 한눈에 통제하는 대시보드

🏛️ Workspace Hub 열기 ➔
CORE RULE 01
🇰🇷 한국어 진행 & 직관 해설

모든 생각 흐름, 계획, 코드 설명 및 결과 보고는 쉬운 한국어로 진행하며, 난해한 기술 용어는 일상적 비유로 1:1 매핑합니다.

CORE RULE 02
🛑 전문 정독·선답변 & 3대 승인 키워드 착수

질문 전체를 끝까지 모두 정독하고 답변·기획을 먼저 제시하며, 사장님의 "시작", "진행", "수락" 명시적 승인 전에는 첫 문장만 보고 폴더 생성이나 코드 작업을 절대 선행하지 않습니다.

CORE RULE 03
🚫 불필요 팝업 & 질문 차단

확인 모달(ask_question)로 Submit을 요구하거나 불필요한 승인 클릭을 강요하지 않고, 전문가 관점에서 최적의 방식으로 자율 완결합니다.

CORE RULE 04
⚡ 논스톱 자율 실행 & 결과 검증

작업 착수 후 멈추지 않고 파일 생성, 코드 수정, 빌드 검증까지 완결하며, 반드시 배포 후 브라우저/실서버 응답을 스스로 확인합니다.

CORE RULE 05
📱 텔레그램 실시간 원격 보고

사용자가 "알려줘", "보고해"를 요청하거나 중요 작업 완료 시, 공식 봇(@aiffall_bot)으로 핵심 요약과 링크를 즉시 전송합니다.

RULE 14 🎮
🕹️ 도서 전용 실시간 웹 시뮬레이터 필수 번들링 (Simulator Rule)

"우리 도서들만의 독보적 특화점": 모든 신규 위키독스 도서 출간 시 독자가 브라우저에서 직접 클릭하고 조작하며 원리를 체감하는 단일 HTML 실시간 웹 시뮬레이터(Kafka, Hive, 딥러닝, 레이더 차트 등)를 필수 제작하여 도서 대문 및 GitHub Pages에 동시 탑재합니다.

  • • 온보딩 가이드 모달: 최초 접속 시 3단계 핵심 가이드 팝업 및 localStorage 다시 보지 않기 제공
  • • 4대 원클릭 프리셋: 초보 독자도 클릭 한 번으로 극적인 상태 전이를 체험할 수 있는 버튼 완비
  • • 반응형 & 다크 테마: 모바일/태블릿/데스크톱 해상도 대응 및 무결점 단일 파일 번들링
RULE 15 🔒
🏛️ 비공개(Private) 보안 도서 관리 및 <<Hamilton.Kang 전용>> 표준 규격

사내 엔터프라이즈 서비스 아키텍처, 시스템 블루프린트, 내부 포털 링크는 위키독스 비공개(open_yn: 'N') 도서로 발행하며, 상단에 'CONFIDENTIAL / INTERNAL USE ONLY' 보안 헤더를 의무 장착합니다.

  • • 비공개 속성 강제: 도서 및 모든 챕터 페이지에 open_yn: 'N' 파라미터 적용
  • • 접근 통제: 외부 검색 인덱싱 차단 및 관리자/에이전트 단일 진실 공급원(SSOT) 유지
RULE 09-A 📖
📖 파트별 전문 용어 사전 & 알기 쉬운 개요는 각 Part 페이지에 게시

개별 챕터가 아닌 상위 대단원인 각 Part 페이지(depth 0)에 비전공자도 단번에 이해할 수 있는 전문 용어 해설 표와 직관적 개요 설명을 무조건 단독 게시합니다.

  • • 각 Part 페이지에 단독 게시: 단순 폴더가 아닌 전용 학습 관문 역할 수행
  • • 전문 용어 사전 (Terminology): 큐비트, 양자 얽힘, 텐서곱 등 핵심 용어 1:1 비유 해설 표
  • • 직관적 개요 (Concept Overview): 일상적 실생활 비유 및 파트 전체 작동 흐름도 상세 설명
RULE 09-B 🎮
🎮 인터랙티브 웹 시뮬레이터 4대 팝업 & 온보딩 룰

도서와 1:1 연동되는 인터랙티브 웹 시뮬레이터는 학습 효과 극대화를 위해 4대 규칙을 100% 탑재합니다:

  • • 자동 온보딩 모달: 다크 글래스모피즘 3단 가이드 + 오늘 하루 보지 않기
  • • 상단 📖 사용 안내: 헤더 우측 상시 호출 버튼 탑재
  • • Zero-Dead-Click: 반응 없는 빈 클릭 원천 차단 (상태/사운드/토스트)
  • • 원클릭 프리셋 바: 상단 5대 실습 시나리오 즉시 실행
RULE 11 🏛️
🏛️ 기획서 100% 일치 3계층 목차 (Part > 장 > 절)

위키독스 목차에 챕터를 플랫하게 나열하는 것은 엄격히 금지됩니다. 반드시 대단원(Part 1~6)을 상위 폴더(부)로 생성하고 parent_id로 바인딩합니다.

  • • 프롤로그 최상단 고정: 00장. 접두사 또는 FrontPage로 최상단 배치
  • • Part (대단원): depth 0, parent_id None (용어 사전 & 개요 수록)
  • • 장 (중단원): depth 1, parent_id Part_ID
  • • 절 (소단원): 본문 내 ## 1.1, ## 1.2 표준 2단계 헤딩

  • • HTML 0칸 들여쓰기: 태그 앞 4칸 공백 금지 (469건 경고 및 네모(□) 깨짐 차단)
  • • 구분선 격리: --- 수평선 위아래 1줄 이상 공백 행 확보
  • • LaTeX 짝 맞춤: $ / $$ 기호 무결성 검증 및 1:1 파이썬 코드 매핑
  • • 깨진 링크 제로: 상대경로 404 및 내부 하이퍼링크 단절 원천 방지

🚀 위키독스(위키북스) 10대 무결점 사전/사후 전수 검사 체크리스트

도서 원고 집필 및 출간 작업 시 단 하나의 결함도 없이 아래 10대 항목을 100% 통과해야 합니다.

1. 각 Part 페이지(depth 0) 본문에 전문 용어 사전(Terminology) 표 단독 수록 완료 용어 사전
2. 각 Part 페이지(depth 0) 본문에 일상적 비유와 알기 쉬운 개요(Overview) 상세 설명 수록 완료 개념 개요
3. 기획서 기준 Part > Chapter 3계층 목차 구조 및 프롤로그(00장.) 최상단 배치 완료 3계층 목차
4. 연계 인터랙티브 시뮬레이터 4대 팝업 룰 (온보딩 모달, 📖 안내 버튼, Zero-Dead-Click, 프리셋) 준수 완료 시뮬레이터
5. 모든 페이지 본문 최상위 헤딩이 ## (2단계)로 시작 (# 1단계 본문 사용 0건, 38건 빌드 오류 차단) 헤딩 2단계
6. 모든 HTML 태그 블록 좌측 0칸 정렬 (4칸 들여쓰기 0건, 469건 경고 및 네모(□) 깨짐 차단) HTML 0칸
7. 구분선(---) 상하 1줄 이상 빈 줄 확보 (테이블 헤더 오인 방지) 구분선 격리
8. LaTeX 수식 짝 맞춤($ / $$) 및 비전공자용 1:1 파이썬 구현 매핑 완료 수식 무결성
9. 책소개글(BOOK_INTRO.md), 프롤로그, 전 챕터 최하단 필수 4대 푸터 배너(추천/커피/로드맵/피드백) 결합 완료 4대 푸터 배너
10. 출간 시 6대 연동 MD 문서(포털, 메인 README, 구조도, 북카드, 체크포인트, 크로스배너) 동기화 완료 6대 MD 동기화
