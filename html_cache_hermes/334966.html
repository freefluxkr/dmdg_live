자기 진화 시스템

Hermes Agent의 자기 개선은 사용 중의 스킬 생성/수정에 그치지 않습니다. NousResearch는 별도의 자기 진화(self-evolution) 시스템을 개발했습니다.

메인 저장소와의 관계

tip

소스 코드 분석 결과: 자기 진화 시스템(DSPy + GEPA)은 메인 hermes-agent 저장소에 포함되어 있지 않습니다. 메인 저장소에서 "GEPA"나 "self-evolution"을 검색하면 관련 코드가 전혀 나오지 않습니다. DSPy는 optional-skills/mlops/research/dspy/ 경로에 옵션 참조 스킬 형태로만 존재하며, 이는 DSPy 프레임워크 사용법을 안내하는 일반 스킬일 뿐 에이전트 자기 진화 기능과는 무관합니다.

자기 진화 시스템은 GitHub 저장소 NousResearch/hermes-agent-self-evolution에서 별도 프로젝트로 관리됩니다. 일상적인 Hermes Agent 사용에는 이 별도 저장소가 필요하지 않습니다.

hermes-agent-self-evolution

이 별도 시스템은 DSPy + GEPA(Genetic-Pareto Prompt Evolution)를 사용하여 에이전트의 구성요소를 자동으로 최적화합니다.

최적화 대상

  • 스킬: 더 효과적인 절차로 진화
  • 도구 설명: LLM이 도구를 더 정확하게 선택하도록 설명 개선
  • 시스템 프롬프트: 더 효과적인 프롬프트로 진화
  • 코드: 에이전트의 코드 자체를 개선

작동 방식

  1. 현재 스킬/프롬프트/코드의 성능을 측정합니다
  2. 변형(mutation)을 생성합니다
  3. 각 변형의 성능을 평가합니다
  4. 파레토 최적(Pareto optimal) 변형을 선택합니다
  5. 다음 세대로 진행합니다

이 과정을 반복하면 측정 가능하게 더 나은 변형이 산출됩니다.

비용과 요구사항

  • API 호출 기반이므로 GPU 학습이 필요 없습니다
  • 최적화 한 번에 약 \$2~\$10 정도 소요됩니다
  • 모델의 가중치를 변경하지 않습니다 (프롬프트/스킬 수준 최적화)

GEPA의 출처

hermes-agent-self-evolution 저장소의 README에는 "ICLR 2026 Oral"이라는 문구가 있습니다. 이것은 Hermes Agent 자체가 학회에 발표되었다는 뜻이 아닙니다.

GEPA(Genetic-Pareto)는 Stanford DSPy 팀이 개발한 독립적인 프롬프트 최적화 기법입니다. 논문 정보는 다음과 같습니다.

  • 논문: "GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning"
  • 저자: Lakshya A Agrawal, Shangyin Tan 외 15명 (Stanford, Berkeley, UT Austin 등)
  • 학회: ICLR 2026 Oral
  • arXiv: https://arxiv.org/abs/2507.19457
  • 코드: https://github.com/gepa-ai/gepa

논문의 핵심 결과는, GEPA가 GRPO 대비 평균 6%(최대 20%) 높은 성능을 35배 적은 롤아웃으로 달성했다는 것입니다. 에이전트의 실행 궤적(추론, 도구 호출, 도구 출력)을 자연어로 반성(reflect)하여 프롬프트 개선점을 진단하는 방식입니다.

정리하면, Hermes Agent의 자기 진화 시스템은 이 GEPA 논문의 기법을 활용하는 관계입니다. NousResearch가 GEPA를 만든 것이 아니라, 학회에서 검증된 외부 기법을 에이전트 최적화에 적용한 것입니다.

메인 저장소에서의 자기 개선 메커니즘

메인 저장소에서 확인할 수 있는 자기 개선 관련 기능은 다음과 같습니다.

스킬 자동 생성/수정 + 큐레이터

에이전트는 복잡한 작업(도구를 여러 번 호출하는 작업)을 완료하면 그 절차를 스킬로 저장하도록 유도됩니다. 기존 스킬이 오래되었거나 불완전하면 즉시 수정합니다. 또한 도구 호출이 일정 횟수 누적되면 백그라운드에서 리뷰 에이전트가 스킬 생성 여부를 검토합니다 (7-2절 참조).

v0.12에서는 이 위에 백그라운드 큐레이터가 추가됐습니다. 7일에 한 번씩 라이브러리 전체를 리뷰해서 비슷한 스킬을 합치고(consolidated), 오랫동안 쓰이지 않은 스킬을 솎아냅니다(pruned). 자세한 내용은 7-6절 참고.

리뷰 포크 자체도 v0.12에서 정비됐습니다.

  • 자유 형식 판단 대신 클래스 우선 루브릭으로 등급을 매김
  • 직전에 로드된 스킬을 우선 갱신 대상으로 선택(active-update bias)
  • references/·templates/ 하위 파일까지 갱신 범위에 포함
  • 리뷰 포크가 부모 대화의 프로바이더·모델·자격증명을 그대로 상속(이전에는 일부 환경에서 다른 모델로 폴백되어 품질이 흔들렸음)
  • 리뷰 포크는 memory·skills 도구 셋만 활성화 — 셸·웹·터미널로 새지 않음
  • 리뷰가 보는 컨텍스트에는 메인 대화의 이전 턴 도구 메시지가 빠짐 → 잡음 없는 평가

메모리 자동 저장

일정 턴 수가 지나면 백그라운드 리뷰 에이전트가 메모리 저장 여부를 검토합니다. 다만 이것은 사용자 선호도와 환경 정보를 기억하는 것이지, 에이전트의 행동 자체를 최적화하는 메커니즘은 아닙니다.

궤적 저장과 RL 파이프라인

메인 저장소에는 에이전트의 작업 궤적을 학습 데이터로 변환하는 도구와, Atropos 기반 RL 학습 인터페이스가 포함되어 있습니다. 궤적 압축은 완료된 대화를 후처리하여 토큰 예산 내로 줄이는 것으로, 대화 중에 작동하는 컨텍스트 압축(5장 참조)과는 별개의 시스템입니다. 이들은 에이전트 런타임의 일부가 아니라 별도의 학습 워크플로우입니다.

일반 사용자에게의 의미

대부분의 사용자는 자기 진화 시스템을 직접 사용할 필요가 없습니다. 일상적인 사용에서는 에이전트의 내장 스킬 자동 생성/수정 메커니즘(7장 참조)으로 충분합니다.

하지만 이 시스템의 존재는 Hermes Agent가 단순한 엔지니어링 프로젝트가 아니라, 연구 기반의 프레임워크임을 보여줍니다. RL 학습 파이프라인(Atropos)을 자체 구축하고, 학회에서 검증된 외부 기법(GEPA)을 프롬프트 최적화에 적용하는 등 여러 방향의 자기 개선을 시도하고 있습니다.
