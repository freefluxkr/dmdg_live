Discord 봇으로 Hermes Agent를 연동하는 방법입니다.

봇 생성

  1. Discord Developer Portal에 접속해 New Application으로 애플리케이션을 만듭니다.
  2. Bot 탭에서 봇 토큰을 생성·복사합니다. 이 토큰은 아래 「게이트웨이에 연결」 단계에서 입력하므로 잠시 보관해 둡니다.
  3. 같은 Bot 탭의 Privileged Gateway Intents에서 Message Content Intent를 켜고, 하단의 Save Changes까지 누릅니다. 안 켜면 봇이 메시지 내용을 읽지 못하고(멘션은 감지해도 내용은 모름), 게이트웨이가 PrivilegedIntentsRequired 오류로 접속하지 못합니다. 허용 목록을 숫자 ID로만 쓰면 Server Members Intent는 필요 없고, 사용자명·역할로 지정할 때만 켭니다.
  4. 봇을 들일 서버를 준비합니다. Discord에서는 채널이든 DM이든 봇과 대화하려면 봇이 들어간 서버가 하나는 있어야 합니다. 서버가 없으면 왼쪽 막대의 + → 직접 만들기로 개인 서버를 먼저 만듭니다.
  5. OAuth2 → URL Generator에서 bot 스코프와 메시지 권한을 골라 초대 URL을 만든 뒤, 그 서버로 봇을 초대합니다.

게이트웨이에 연결

가장 간단한 길은 대화형 마법사입니다.

hermes setup gateway

Discord를 고른 뒤 차례로 입력합니다.

  1. 봇 토큰 — Bot 탭에서 받은 토큰입니다(General Information의 Application ID·Public Key가 아닙니다). 토큰은 비밀이라 노출되면 Reset Token으로 무효화합니다.
  2. 허용 사용자 — 본인 Discord 사용자 ID(숫자, 개발자 모드 → 우클릭 → ID 복사). 기본이 "전부 차단"이라 비우면 open access가 되어 누구나 봇을 조종할 수 있습니다. 터미널 접근 봇이므로 반드시 본인 ID를 넣습니다.
  3. 홈 채널(선택) — 크론 결과·크로스플랫폼 메시지를 보낼 채널. 비워 두고 나중에 원하는 채널에서 /set-home으로 정해도 됩니다.

마법사 끝에 "Restart the gateway to pick up changes?"가 나오면 Y를 누릅니다. 서비스로 설치돼 있으면(9-1절) 이 재시작으로 설정이 반영됩니다.

직접 편집으로 설정하기

마법사 대신 설정 파일을 직접 편집해도 됩니다. 시크릿과 허용 목록 두 곳에 나눠 들어갑니다.

시크릿 — ~/.hermes/.env

DISCORD_BOT_TOKEN=발급받은_봇_토큰

허용 목록 — ~/.hermes/config.yaml (또는 .env의 DISCORD_ALLOWED_USERS)

discord:
  allow_from:
    - "본인_discord_user_id"

allow_from은 기본값이 "전부 차단"이라 비워 두면 모든 요청이 거부됩니다. 직접 고친 뒤에는 hermes gateway restart로 반영합니다.

연결 상태를 확인합니다.

hermes gateway status                      # active (running)인지
journalctl --user -u hermes-gateway -f     # Discord 로그인·메시지 처리 로그 (Linux)

PrivilegedIntentsRequired 오류가 보이면 Developer Portal에서 Message Content Intent를 켜고 저장(Save Changes) 했는지 확인한 뒤 다시 재시작합니다. macOS에서는 로그가 ~/.hermes/logs/gateway.log에 쌓입니다.

봇이 온라인으로 뜨면, 초대한 서버의 텍스트 채널에서 봇을 멘션하거나 봇에게 DM을 보내 대화를 시작하면 됩니다.

채널 멘션 응답 불안정과 우회 방법

v0.17.0에서는 채널에서 봇을 멘션할 때 첫 멘션만 응답하고, 같은 채널의 이후 멘션은 응답 없이 무시됩니다. Hermes 디스코드 어댑터의 알려진 문제로 보이며, 업스트림 GitHub에 #8487로 보고돼 있습니다. 이후 대화는 자동 생성된 스레드에서 이어 가거나 봇에게 DM을 보내 진행합니다.

사용

  • 봇을 멘션하거나 DM으로 대화를 시작합니다
  • 슬래시 명령어(/new, /model 등)를 사용할 수 있습니다
  • 에이전트가 선택지를 물으면 클릭 가능한 버튼으로 표시됩니다
  • 파일 첨부 → 파일 분석
  • 이미지 첨부 → 비전 분석

팀 운영

Discord의 강점은 여러 사용자가 하나의 Hermes Agent 봇을 공유하는 팀 환경입니다. 세션을 어떻게 분리하고 어떤 채널 구조로 운영할지를 모았습니다.

그룹 채팅 — 세션 분리 vs 공유

group_sessions_per_user: true   # true: 사용자별 세션(기본값), false: 공유 세션

그룹 채널에서 true(기본값)이면 각 사용자가 독립된 세션을 가지고, false이면 채널의 모든 사용자가 하나의 세션을 공유합니다.

스레드 기반 세션

Discord 스레드에서 봇을 멘션하면 해당 스레드 내에서 독립된 대화가 유지됩니다. 이를 활용하면 하나의 채널에서 여러 주제의 작업을 동시에 정리할 수 있습니다.

  • 메인 채널에서 봇을 멘션하면 기본 세션으로 응답
  • 스레드 안에서 멘션하면 스레드별 세션으로 응답
  • 스레드 제목으로 작업 주제를 명확히 구분 가능

스레드는 Discord에서 Hermes Agent를 사용하는 가장 깔끔한 방법입니다. 주제별로 대화를 분리하면서도 하나의 채널에서 모든 것을 관리할 수 있습니다.

채널 구조 예시

#hermes-general     — 공유 세션, 팀 공통 질문
#hermes-devops      — 배포/인프라 관련 작업 전용
#hermes-private     — 관리자 전용 (allow_from 제한)

팀 운영 설정

# config.yaml
discord:
  allow_from:
    - "팀원1_id"
    - "팀원2_id"
    - "팀원3_id"

group_sessions_per_user: false  # 팀 채널은 공유 세션 권장

공유 세션(false)을 사용하면 한 팀원이 시작한 작업의 맥락을 다른 팀원이 이어받을 수 있습니다. 예를 들어, 팀원 A가 로그 분석을 요청한 뒤 팀원 B가 추가 조치를 지시하는 흐름이 가능합니다.

권한 분리

채널별로 다른 수준의 접근을 설정하려면 Discord의 역할(Role) 시스템과 allow_from를 조합합니다.

  • 일반 채널 — 모든 팀원이 읽기·쓰기 가능, 위험 명령은 에이전트의 승인 모드(approvals.mode: manual)로 차단
  • 관리자 채널 — 특정 사용자만 접근, 자동 실행 모드(approvals.mode: off) 허용

고급 옵션

옵트인 도구 셋

Discord 도구 셋은 discord(메시지 조회·답글)와 discord_admin(채널/역할 관리) 둘 다 기본 비활성입니다. 쓰려면 최상위 platform_toolsets에서 플랫폼별로 명시해 켭니다.

platform_toolsets:
  discord:
    - discord            # 메시지 조회·답글 (기본 비활성)
    - discord_admin      # 채널/역할 관리 (기본 비활성)

슬래시 명령 자동완성과 32자 한계

활성 스킬은 Telegram과 마찬가지로 Discord 슬래시 명령으로 등록되며, 외부 디렉터리(external_dirs)에 둔 스킬도 자동완성에 포함됩니다(/reload-skills 후 즉시 반영). Discord 명령 이름은 32자가 한계인데, 같은 32자 클램핑 규칙을 거쳐 두 스킬이 같은 이름이 되면 게이트웨이가 경고를 남깁니다 — 이런 경우 한쪽 스킬 이름을 짧게 다듬어야 합니다.

Discord vs Telegram 비교

항목 Telegram Discord
최적 사용 개인, 1:1 사용 팀, 다수 사용자
설정 난이도 BotFather로 2분 Developer Portal에서 5분
그룹 기능 기본적 채널/스레드/역할 등 풍부
음성 메시지 기본 지원 지원
파일 크기 제한 50MB (봇 API) 25MB (부스트·Nitro 시 최대 500MB)
봇 멘션 불필요 (DM) 멘션 또는 DM 필요
알림 커스터마이징 제한적 채널/역할별 세밀한 제어

간단 정리:

  • 혼자 쓸 때는 Telegram이 설정도 쉽고 DM으로 바로 대화할 수 있어 편리합니다.
  • 팀에서 공유할 때는 Discord가 채널 분리, 역할 관리, 스레드 등의 기능으로 더 적합합니다.
  • 두 플랫폼을 동시에 운영하는 것도 가능합니다. 관리자는 Telegram DM, 팀은 Discord 채널을 사용하는 조합이 실용적입니다.
