10-2. 실습: 자동 리포트 생성

⚠️ 부분 검증: 크론 저장 구조와 동작(저장 경로·동시 실행 방지·게이트웨이 의존·수동 tick)은 v0.16.0 소스 코드와 대조해 확인했습니다. 다만 다섯 가지 실습의 실제 등록·실행 흐름은 실행 테스트로 검증하지 않았습니다.

  • 크론 저장 구조
  • 실습 1: 간단한 크론 작업
  • 실습 2: 일일 시스템 리포트
  • 실습 3: 조건부 알림 (SILENT 패턴)
  • 실습 4: 크론 + 메시징 연동
  • 실습 5: 크론 작업 관리
  • 주의사항

이 절에서는 크론 기능의 기본 사용법, 자동 시스템 리포트 생성, 조건부 알림, 메시징 연동, 작업 관리까지 다섯 가지 실습을 차례로 진행합니다.

크론 저장 구조

크론 작업의 데이터는 다음 위치에 저장됩니다.

~/.hermes/cron/
├── jobs.json                        # 모든 크론 작업 정의
└── output/
    └── {job_id}/
        └── {timestamp}.md           # 각 실행 결과
  • jobs.json: 모든 크론 작업이 하나의 JSON 파일에 저장됩니다. 스케줄, 프롬프트, 활성화 상태, 마지막 실행 시각 등이 포함됩니다.
  • output/{job_id}/{timestamp}.md: 각 실행 결과가 작업 ID별 디렉터리에, 실행 시각을 파일명으로 하여 마크다운 파일로 저장됩니다.
동시 실행 방지

크론 스케줄러는 실행 중인 작업 ID를 추적해 동일 작업의 동시 실행을 방지합니다. 이전 실행이 아직 끝나지 않았다면 다음 틱에서 그 작업은 건너뜁니다. 오래 걸리는 작업이라도 중복 실행 걱정 없이 안전합니다. 이와 별개로, 게이트웨이의 자동 틱과 수동 hermes cron tick이 겹쳐도 한 번에 하나의 틱만 돌도록 파일 락(~/.hermes/cron/.tick.lock)이 쓰입니다.

실습 1: 간단한 크론 작업

> 30분마다 현재 시각과 시스템 업타임을 /tmp/status.log에 기록하는 크론을 만들어줘

등록 후 확인:

> 등록된 크론 작업 목록을 보여줘

등록된 작업은 ~/.hermes/cron/jobs.json에서 직접 확인할 수도 있습니다.

cat ~/.hermes/cron/jobs.json | python3 -m json.tool

실습 2: 일일 시스템 리포트

> 매일 오전 9시에 다음 내용을 포함하는 시스템 리포트를 ~/reports/ 디렉터리에 생성해줘:
> - 디스크 사용량
> - 가장 큰 파일 TOP 10
> - 최근 24시간 내 수정된 파일
> 파일명은 report-YYYY-MM-DD.md 형식으로

리포트 결과는 두 곳에 저장됩니다.

  1. 에이전트가 생성한 ~/reports/report-YYYY-MM-DD.md 파일
  2. 크론 시스템의 실행 기록: ~/.hermes/cron/output/{job_id}/{timestamp}.md

실습 3: 조건부 알림 (SILENT 패턴)

이상이 있을 때만 알림을 받는 크론 작업입니다.

> 매 시간마다 디스크 사용량을 확인해줘. 80% 이하이면 [SILENT]로 시작하는 응답을 작성하고,
> 80%를 초과하면 경고 메시지를 보내줘.

정상 상태에서는 알림이 오지 않고, 문제가 발생했을 때만 메시지를 받게 됩니다.

실습 4: 크론 + 메시징 연동

메시징 게이트웨이가 실행 중이라면, 크론 결과를 메시징으로 받을 수 있습니다.

  1. Telegram이나 Discord에서 /sethome 실행
  2. 크론 작업 결과가 해당 채널로 전송됨

실습 5: 크론 작업 관리

> 등록된 크론 작업 중 status.log 관련 작업을 삭제해줘
> 일일 리포트의 실행 시간을 오전 8시로 변경해줘

주의사항

  • 게이트웨이 필수: 크론 작업이 자동 실행되려면 hermes gateway가 실행 중이어야 합니다. 게이트웨이 없이는 hermes cron tick으로 수동 실행만 가능합니다.
  • 비용: 크론 작업은 LLM을 호출하므로, 빈번한 스케줄은 토큰(또는 컴퓨팅) 비용이 발생합니다.
  • 로컬 LLM: 비용 부담은 없지만, 동시 요청 시 응답 속도가 느려질 수 있습니다.
  • 에러 처리: 중요한 작업의 크론은 에러 처리를 포함하도록 지시하세요.
  • 격리: 각 크론 작업은 독립된 세션에서 실행됩니다. 이전 실행 결과를 참조하려면 파일로 저장하도록 지시해야 합니다.
  • 재귀 방지: 크론 실행 중에는 새로운 크론 작업을 등록할 수 없습니다.
