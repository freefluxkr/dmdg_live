Hermes Agent는 대화 중 /로 시작하는 슬래시 명령어를 제공합니다. CLI와 메시징 플랫폼 모두에서 사용할 수 있으며, 접두사 매칭을 지원합니다(예: /ver만 입력해도 /verbose로 확장).

명령어는 ~/hermes-agent/hermes_cli/commands.py의 COMMAND_REGISTRY가 단일 진실의 원천입니다. 이 절은 v0.13.0 기준으로 정리한 것입니다.

세션 관리

명령어 설명
/new (별칭: /reset) 새 세션 시작 (세션 ID와 히스토리 초기화)
/clear 화면 지우고 새 세션 시작
/redraw 터미널 화면이 깨졌을 때 강제 재페인트
/history 대화 히스토리 표시
/save 현재 세션 저장
/retry 마지막 메시지 재전송
/undo 마지막 사용자/어시스턴트 교환 제거
/title [name] 세션 제목 설정/표시
/branch [name] (별칭: /fork) 현재 세션을 분기해 다른 경로 탐색
/compress [focus] 컨텍스트 수동 압축. 주제를 인자로 주면 그 주제 중심으로 요약
/compress here [N] 경계 인식형 부분 압축. 최근 N개 교환은 그대로 두고 그 이전만 요약 (5장 참고)
/rollback [number] 파일 시스템 체크포인트 목록/복원
/snapshot [create|restore <id>|prune] (별칭: /snap) Hermes 설정·상태의 스냅숏
/stop 실행 중인 백그라운드 프로세스 모두 종료
/resume [name] 이전 세션 재개
/status 세션 정보 표시
/profile 활성 프로파일과 홈 디렉터리 표시(전환은 CLI에서, 11-6절 참고)
/sessions 이전 세션 목록 탐색 및 재개
/handoff <target> 현재 세션을 라이브 이관 — 메시지·도구 호출·컨텍스트를 전부 보존한 채 다른 모델, 성격, 프로파일, 또는 메시징 플랫폼(Telegram, Discord 등)으로 옮김. 디버깅 중 빠른 모델에서 깊은 추론 모델로 넘기는 식으로 사용
/sethome (별칭: /set-home) 현재 채널을 홈 채널로 지정(게이트웨이 전용)

백그라운드·다중 작업

여러 작업을 동시에 진행하거나, 실행 중인 에이전트를 살짝 돌려세우는 명령어들입니다.

명령어 설명
/background <prompt> (별칭: /bg, /btw) 서브에이전트로 백그라운드 작업 시작. 메인 대화는 계속 진행
/queue <prompt> (별칭: /q) 다음 턴에 처리할 프롬프트를 큐에 넣음(현재 턴은 끊지 않음)
/steer <prompt> 실행 중인 에이전트가 다음 도구 호출 후에 받아 보도록 메시지 주입(인터럽트 없음, 프롬프트 캐시 유지)
/goal [text|pause|resume|clear|status] 영속 목표 설정 — 매 턴 후 백그라운드에서 진행 점검(Ralph loop). 한 턴에 끝나지 않는 작업을 며칠에 걸쳐 누적 진행할 때 사용
/agents (별칭: /tasks) 활성 서브에이전트와 진행 중 작업 표시

모델·응답 작동

명령어 설명
/model [model] [--provider name] [--global] (별칭: /provider) 모델·프로바이더 전환. 인자 없이 부르면 인터랙티브 피커가 뜨고, 모든 게이트웨이 플랫폼(텔레그램·디스코드·슬랙)에서도 작동
/fast [normal|fast|status|on|off] Fast Mode 토글 — OpenAI Priority Processing / Anthropic Fast Mode 사용 여부
/codex-runtime [on|off|auto] OpenAI/Codex 모델 턴을 Codex app-server로 위임하는 런타임 전환(4-4절)
/reasoning [level|show|hide] 추론 노력 수준(none/minimal/low/medium/high/xhigh) 또는 추론 과정 표시/숨김
/footer [on|off|status] 게이트웨이 최종 응답에 런타임 메타데이터 푸터(모델·토큰·소요시간) 표시 토글
/yolo 위험 명령 자동 승인 토글(세션 한정, 프로세스 종료 시 초기화)

표시·입력 작동

명령어 설명
/verbose 도구 표시 수준 순환 (off → new → all → verbose)
/voice [on|off|tts|status] 음성 모드 토글(자세한 내용은 3-5절)
/busy [queue|steer|interrupt|status] 작업 중 Enter 키 작동 변경
/indicator [kaomoji|emoji|unicode|ascii] TUI의 busy 인디케이터 스타일
/skin [name] 디스플레이 테마(스킨) 변경
/statusbar (별칭: /sb) 컨텍스트/모델 상태바 토글
/personality [name] 성격 프리셋 적용(없이 부르면 현재 표시)
/usage 현재 세션 토큰 사용량과 레이트 리밋
/insights [days] 사용 통계 분석

성격 프리셋(14가지): helpful, concise, technical, creative, teacher, kawaii, catgirl, pirate, shakespeare, surfer, noir, uwu, philosopher, hype. /personality none 또는 /personality default로 초기화합니다.

/personality는 세션을 넘어 지속됩니다

공식 문서에는 세션 수준의 임시 변경이라고 되어 있지만, 소스 코드에서는 config 파일에 저장되어 다음 세션에도 유지됩니다.

도구·스킬·MCP

명령어 설명
/tools [list|disable|enable] [name...] 도구 활성/비활성
/toolsets 사용 가능한 도구 세트 목록
/skills [search|browse|inspect|install] 스킬 검색·설치·관리
/<skill-name> 특정 스킬 실행
/cron [list|add|create|edit|pause|resume|run|remove] 크론 작업 관리
/curator [status|run|pause|resume|pin|unpin|restore] 백그라운드 스킬 큐레이터(7장 참고)
/kanban [list|show|create|claim|complete|...] 다중 프로필 협업 보드
/reload-mcp (별칭: /reload_mcp) MCP 서버 재로드. 프롬프트 캐시 무효화 비용 경고 후 진행
/reload-skills (별칭: /reload_skills) ~/.hermes/skills/ 재스캔 — 새로 설치하거나 삭제한 스킬 즉시 반영
/reload .env 변수 재로드(현재 세션에 반영)
/browser [connect|disconnect|status] Chrome CDP 연결 관리
/plugins 설치된 플러그인 상태
/platforms (별칭: /gateway) 게이트웨이/메시징 플랫폼 상태

정보·도움말

명령어 설명
/help 사용 가능한 명령어 도움말
/whoami 현재 사용자의 슬래시 명령 접근 수준(admin/user) 표시
/commands [page] 전체 명령어/스킬 목록 페이지네이션(게이트웨이 전용)
/config 현재 설정 표시
/copy [number] 마지막 어시스턴트 응답을 클립보드로
/paste 클립보드 이미지를 다음 프롬프트에 첨부
/image <path> 로컬 이미지 파일을 다음 프롬프트에 첨부
/gquota Google Gemini Code Assist 할당량
/debug 시스템 정보 + 로그를 묶어 공유용 디버그 리포트 업로드

게이트웨이 전용

메시징 플랫폼에서 추가로 쓰는 명령어:

명령어 설명
/topic [off|help|session-id] Telegram DM 토픽 세션 관리
/approve [session|always] 보류 중인 위험 명령 승인
/deny 보류 중인 위험 명령 거부
/restart 진행 중 작업 정리 후 게이트웨이 재시작
/update Hermes Agent 업데이트

종료

명령어 설명
/quit (별칭: /exit) CLI 종료(/q는 /queue 별칭이므로 종료에는 /quit 사용)

💡 사라진 명령어: 이전 버전에 있던 /plan은 v0.11에서 제거됐습니다. /provider는 별도 명령이 아니라 /model의 별칭으로 통합됐습니다(인터랙티브 모델 피커가 뜹니다).

퀵 커맨드

config.yaml에 사용자 정의 명령어를 등록하면 LLM을 거치지 않고 바로 셸 명령을 실행할 수 있습니다.

quick_commands:
  status:
    type: exec
    command: systemctl status hermes-agent
  disk:
    type: exec
    command: df -h /

등록 후 /status, /disk로 실행합니다. type은 exec(셸 명령 실행)과 alias(다른 명령 별칭) 두 가지를 지원합니다. 토큰 소비 없이 즉시 결과를 볼 수 있습니다.
