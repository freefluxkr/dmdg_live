복잡한 프로젝트를 처음부터 Hermes Agent에 맡기는 것보다, Claude Code로 기틀을 잡은 뒤 Hermes에 인계하는 것이 효율적인 경우가 많습니다. 이 페이지에서는 그 이유와 실용적인 인계 방법을 정리합니다.

왜 Claude Code부터 시작하는가

초기 작업에서의 강점

Claude는 아키텍처 설계, 프로토타입 작성, 디버깅, 테스트 케이스 생성 등 창의적이고 복잡한 초기 작업에 강합니다. 세션 기반으로 빠르게 반복(iterate)할 수 있어 실험 비용이 낮습니다.

Hermes의 학습 곡선

Hermes Agent는 persistent memory와 self-improving이 핵심이지만, 프로젝트에 대한 기억과 스킬이 쌓이기까지 시간이 필요합니다. 처음부터 던지면 학습 기반 없이 비효율적으로 작동할 수 있습니다. Claude로 프로젝트 구조, 핵심 로직, 규칙 문서를 먼저 만들어 두면 Hermes가 더 빠르게 적응합니다.

인계 타이밍

  • MVP나 핵심 코드베이스 + 문서(아키텍처, 규칙, 예시)가 완성된 후
  • 업무가 반복적이거나 장기 유지보수 성격으로 전환될 때
  • 자율 실행(cron 태스크, 대규모 분석, 배포 자동화)이 필요해질 때

인계 방법

  1. Claude Code에서 만든 산출물(코드, spec, CLAUDE.md, 학습 내용)을 Hermes workspace에 넣습니다.
  2. SOUL.md에 프로젝트 맥락과 역할을 명시합니다.
  3. 작은 작업부터 시켜서 Hermes가 메모리와 스킬을 축적하게 합니다.

24/7 자율 실행 불가 크론, 메시징 게이트웨이
장기 학습 세션 간 단절 self-improving

복잡한 신규 작업은 Claude Code로, 지속적·반복적 운영은 Hermes로 나누는 것이 실용적입니다. 필요하면 언제든 복잡한 부분만 Claude로 돌아가서 처리하고 다시 인계할 수 있습니다.
