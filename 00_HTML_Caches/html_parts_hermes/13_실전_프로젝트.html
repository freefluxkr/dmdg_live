프로젝트: 코드 분석 에이전트

이 프로젝트에서는 Hermes Agent를 사용하여 코드 저장소를 자동으로 분석하는 에이전트를 구성합니다. 별도 설정 없이 바로 시작할 수 있는 가장 간단한 프로젝트입니다.

이 문서에서 다루는 내용

이 프로젝트는 다음을 다룹니다.

  • Git 저장소를 클론해 구조·의존성·아키텍처를 분석
  • 결과를 마크다운 리포트(report.md)로 정리
  • 같은 분석을 반복하면 스킬(repo-analysis)로 굳혀 다음부터는 한 줄로 실행

사전 준비

  • Git 설치 여부 확인: git --version
  • Hermes Agent를 실행할 수 있어야 합니다.
  • AGENTS.md를 저장할 작업 디렉터리를 준비합니다. 예: ~/analysis-workspace/. 이 디렉터리에 분석 대상 저장소를 클론합니다.

AGENTS.md 설정

작업 디렉터리에 AGENTS.md를 둡니다. AGENTS.md가 프로젝트 디렉터리 안에 있으면 Hermes Agent가 자동으로 읽으므로, 따로 설치할 필요는 없습니다. 같은 분석을 다른 머신에서도 반복하려면 이 파일을 함께 복사하거나, 「프로파일」 절에서 설명하는 방식으로 설정을 묶어 관리할 수 있습니다.

# AGENTS.md

## 코드 분석 규칙

### 분석 순서
1. 파일 구조를 먼저 파악할 것 (tree 또는 ls -R)
2. 의존성 파일 확인: package.json, requirements.txt, Cargo.toml, go.mod 등
3. README.md가 있으면 읽을 것
4. 진입점(entry point)을 찾을 것
5. 테스트 구조를 파악할 것

### 출력 규칙
- 결과는 마크다운 형식으로 report.md에 저장
- 각 섹션에 구체적인 파일 경로를 포함
- 의존성은 표(table) 형식으로 정리
- 개선 제안을 최소 3개 포함

실습: 저장소 분석

기본 분석 요청

> https://github.com/NousResearch/hermes-agent 저장소를 클론해서 분석해줘.
> 다음 항목을 포함하는 리포트를 만들어줘:
> 1. 프로젝트 구조 (디렉터리 트리)
> 2. 사용된 프로그래밍 언어 비율
> 3. 주요 의존성 목록
> 4. 진입점(entry point) 파일
> 5. 테스트 구조

에이전트가 터미널 도구로 저장소를 클론하고, 파일을 읽고, 분석 결과를 리포트로 정리하는 과정을 관찰합니다.

심화 분석 요청

기본 분석이 끝나면 다음과 같은 추가 질문을 할 수 있습니다.

> 이 프로젝트에서 보안 관련 코드를 찾아줘
> 에러 처리 패턴이 일관적인지 확인해줘

분석 품질 높이기

AGENTS.md에 분석 규칙을 구체적으로 작성할수록 리포트 품질이 올라갑니다. 예를 들어 "보안 취약점도 체크할 것", "라이선스 호환성을 확인할 것" 같은 규칙을 추가해 보세요. 단, 컨텍스트 파일은 소스별로 최대 20,000자까지만 주입되고 초과분은 절단되므로(6장 참조), 핵심 규칙 위주로 간결하게 작성하는 것이 좋습니다.

반복 작업을 스킬로 만들기

같은 작업을 여러 저장소에서 반복한다면, 이 분석 절차를 repo-analysis 스킬로 저장해 둘 수 있습니다.

> 이 분석 작업을 스킬로 만들어줘. 이름은 "repo-analysis"로.

에이전트가 만든 스킬은 ~/.hermes/skills/repo-analysis/ 디렉터리 아래 SKILL.md 파일로 저장되며, 다음과 같은 구조입니다.

---
name: repo-analysis
description: Git 저장소를 클론하여 구조, 의존성, 아키텍처를 분석하고 리포트를 생성합니다.
---

## 실행 절차
1. 대상 저장소를 임시 디렉터리에 클론
2. 디렉터리 구조 파악 (tree -L 3)
3. 의존성 파일 분석
4. 진입점 탐색
5. 테스트 구조 확인
6. report.md 생성

## 출력 형식
마크다운 리포트: 구조, 스택, 의존성, 진입점, 테스트, 개선 제안

다음부터는 스킬 이름만 입력해 분석할 수 있습니다.

> repo-analysis https://github.com/some/project

활용 아이디어

  • PR 리뷰 보조: 변경된 파일만 분석하여 리뷰 코멘트 초안 작성
  • 기술 부채 추적: 주기적으로 분석하여 코드 품질 변화 모니터링
  • 온보딩 문서 생성: 새 팀원을 위한 프로젝트 구조 설명서 자동 생성
  • 의존성 감사: 오래된 패키지, 보안 취약점이 있는 의존성 탐지

프로젝트: 일일 뉴스 브리핑 자동화

이 프로젝트에서는 크론과 메시징을 결합하여, 매일 아침 뉴스를 요약해서 메시징 앱으로 보내는 시스템을 구축합니다.

목표

  • 매일 지정된 시간에 특정 주제의 뉴스를 검색
  • 결과를 요약하여 마크다운으로 정리
  • Telegram 또는 Discord로 전송

사전 준비

  • Telegram 봇 설정 완료 (9장 참조)
  • 웹 검색 도구 준비 (4장 참조)
  • 크론 기능 이해 (10장 참조)

설정 단계

1. 웹 검색 준비

뉴스 검색에는 Hermes에 내장된 web_search 도구를 씁니다. 별도 MCP 서버를 붙일 필요 없이 바로 쓸 수 있고, 백엔드로 Brave Search·Tavily·SearXNG·DuckDuckGo 등을 고를 수 있습니다(4장 참조). 예를 들어 Brave Search를 쓰려면 API 키를 환경 변수에 넣습니다.

# ~/.hermes/.env
BRAVE_SEARCH_API_KEY=your_api_key
무료 검색 API

Brave Search API는 월 2,000회까지 무료라, 일일 브리핑 용도로는 충분합니다.

2. 메시징 게이트웨이 설정

Telegram 봇을 설정합니다 (9장 참조).

# 게이트웨이 실행
hermes gateway

Telegram에서 봇과 대화를 시작한 뒤, 크론 결과를 받을 채널을 홈 채널로 지정합니다.

/sethome

3. 크론 작업 등록

자연어로 크론 작업을 등록합니다.

> 매일 오전 8시에 "AI agent framework" 관련 뉴스를 검색하고,
> 한국어로 3줄 요약을 만들어서 Telegram으로 보내줘

크론 시스템에 별도의 자연어 파서가 있는 것이 아닙니다. LLM이 자연어를 해석하여 parse_schedule() 함수가 받아들이는 구조화된 형식(크론 표현식, 기간 문자열, ISO 타임스탬프)으로 변환합니다(10장 참조). 위 요청은 대략 다음과 같은 크론 작업으로 등록됩니다.

스케줄: 0 8 * * *    (매일 오전 8시, 크론 표현식)
작업: brave-search MCP로 "AI agent framework" 최신 뉴스 검색 →
      상위 5개 기사 선별 → 한국어 3줄 요약 → Telegram 전송 (검색은 내장 web_search 도구 사용)

브리핑 메시지 예시

Telegram으로 수신되는 메시지는 다음과 같은 형태입니다.

📰 AI Agent 뉴스 브리핑 (2025-01-15)

1. Hermes Agent v2.1 릴리스

   - 실제 업무 시나리오 5개로 테스트

여러 주제 브리핑 설정

주제별로 다른 시간에 브리핑을 설정할 수 있습니다.

> 매일 오전 8시: AI/LLM 관련 뉴스 브리핑
> 매일 오전 8시 30분: 한국 주식시장 주요 뉴스 브리핑
> 매주 금요일 오후 6시: 이번 주 오픈소스 트렌드 주간 요약

고급: 키워드 감지 즉시 알림

특정 키워드가 감지되면 즉시 알림을 보내는 설정도 가능합니다.

> 30분마다 "hermes agent" 키워드로 뉴스를 검색하고,
> 새로운 기사가 발견되면 즉시 Telegram으로 알려줘.
> 이전에 보낸 기사는 중복 전송하지 마.

이 경우 에이전트는 메모리를 활용하여 이미 전송한 기사 URL을 기록하고, 중복을 방지합니다.

메모리 활용

크론 작업에서 메모리를 활용하면 상태를 유지할 수 있습니다. "이전에 전송한 기사 목록을 메모리에 저장해줘"라고 지시하면, 에이전트가 ~/.hermes/memories/ 아래에 상태 파일을 관리합니다.

확장 아이디어

  • RSS 피드 모니터링: 특정 블로그나 사이트의 RSS를 주기적으로 체크
  • 주간 종합 리포트: 일일 브리핑을 모아 주간 트렌드 분석
  • 멀티 채널 전송: 같은 브리핑을 Telegram + Discord에 동시 전송
  • 감성 분석: 뉴스의 긍정/부정 톤을 분석하여 시장 분위기 파악

  • AGENTS.md로 프로젝트 규칙을 에이전트에게 전달
  • 공용 스킬로 팀 워크플로 자동화

아키텍처

팀원 (Discord) → Hermes Gateway → 에이전트 → 도구 실행
                                      ↓
                                   스킬/메모리

팀원은 Discord DM으로 에이전트와 대화합니다. 게이트웨이가 메시지를 중계하고, 에이전트가 도구를 실행하여 결과를 반환합니다.

설정

1. Discord 봇 설정

Discord Developer Portal에서 봇을 생성합니다 (9장 참조). Message Content Intent를 반드시 활성화해야 합니다. 이 설정이 꺼져 있으면 봇이 메시지 내용을 읽을 수 없습니다.

# .env
DISCORD_BOT_TOKEN=your_token

필요한 봇 권한:

  • Send Messages
  • Read Message History
  • Manage Messages (선택)

2. 사용자 인증

DISCORD_ALLOWED_USERS를 설정하지 않으면 모든 사용자의 요청이 거부됩니다. 보안을 위해 기본값이 "전부 차단"이므로, 반드시 허용할 팀원의 Discord 사용자 ID를 명시해야 합니다(9장 참조).

# config.yaml
discord:
  allowed_users:
    - "팀원1_discord_id"
    - "팀원2_discord_id"

# 또는 DM 페어링 사용 (새 팀원이 자주 추가될 때 편리)
unauthorized_dm_behavior: pair
DM 페어링 vs 허용 목록

팀 규모가 작고 고정적이면 allowed_users로 직접 관리하는 것이 안전합니다. 팀원이 자주 바뀌는 환경에서는 pair 모드가 편리하지만, 페어링 코드를 팀 내부 채널로만 공유하세요.

3. 프로젝트 규칙 (AGENTS.md)

팀의 컨벤션과 업무 규칙을 정의합니다.

# AGENTS.md

## 팀 프로젝트 규칙

### 기본 원칙
- 응답은 한국어로
- 코드 블록에는 항상 언어를 명시
- 불확실한 정보는 "확인 필요"라고 표시

### 코드 리뷰
- 보안 취약점 체크 (SQL 인젝션, XSS 등)
- 성능 이슈 지적
- 코딩 컨벤션 준수 여부 확인

### 안전 규칙
- DB 변경 작업은 반드시 사용자 확인 후 실행
- 프로덕션 서버 접근 명령은 거부
- 환경변수나 시크릿을 메시지에 포함하지 않음

보안 고려사항

팀 봇 운영 시 반드시 확인해야 할 사항:

  • 정기 감사: 메모리, 스킬, 크론 작업을 주기적으로 점검

프로젝트: Mac Mini 홈 인텔리전스 허브

이 프로젝트에서는 Mac Mini(또는 항상 켜 놓는 macOS 기기)에서 Hermes Agent를 실행하여, Apple 생태계와 스마트홈을 통합 관리하는 개인 AI 비서를 구축합니다.

목표

  • Apple 미리알림, 메모, iMessage를 에이전트로 제어
  • HomeAssistant 연동으로 스마트홈 기기 제어
  • 크론으로 모닝 브리핑, 야간 루틴 자동화
  • Telegram으로 외출 중에도 에이전트와 소통

아키텍처

iPhone/iPad ←(iCloud 동기화)→ Mac Mini (Hermes Agent)
                                    ↕
                              Ollama LLM 서버
                                    ↕
Telegram ←(메시징 게이트웨이)→ HomeAssistant

1단계: Apple 스킬 설정

Homebrew와 CLI 도구 설치

Apple 스킬 중 3개는 Homebrew로 설치하는 CLI 도구가 필요합니다(7장 참조). 테스트 Mac에는 Homebrew가 이미 설치되어 있으므로 CLI 도구만 설치하면 됩니다. Homebrew가 없는 환경이라면 brew.sh에서 먼저 설치하세요.

# Apple 스킬 CLI 도구 설치
brew install steipete/tap/remindctl    # 미리알림 (apple-reminders 스킬)
brew install steipete/tap/imsg         # iMessage (imessage 스킬)
brew install antoniorodr/memo/memo     # Apple 메모 (apple-notes 스킬)

미리알림 테스트

> 내일 오전 10시에 "치과 예약" 미리알림을 추가해줘
> 이번 주 미리알림 목록을 보여줘
> "장보기" 리스트에 우유, 빵, 계란을 추가해줘

iCloud를 통해 iPhone의 미리알림 앱에도 즉시 동기화됩니다.

iMessage 테스트

> 최근 iMessage 목록을 보여줘
> 아내에게 "오늘 늦을 것 같아" 메시지 보내줘
전체 디스크 접근 권한

iMessage 스킬을 사용하려면 터미널 앱에 시스템 설정 > 개인정보 보호 및 보안 > 전체 디스크 접근 권한을 부여해야 합니다. findmy 스킬은 별도 CLI 도구 없이 AppleScript로 Find My 앱 화면을 캡처한 뒤 멀티모달 LLM으로 읽는 방식을 사용합니다(7장 참조).

2단계: HomeAssistant 연동

HomeAssistant가 설치되어 있다면, Hermes Agent의 내장 HomeAssistant 도구로 연결할 수 있습니다.

설정

# ~/.hermes/.env에 추가
HASS_TOKEN=your_long_lived_access_token
HASS_URL=http://homeassistant.local:8123

사용 예시

> 거실 조명을 켜줘
> 현재 실내 온도가 몇 도야?
> 현관문 잠금 상태를 확인해줘

이 프로젝트의 의미

이 구성은 OpenClaw의 네이티브 iOS 앱이 제공하는 경험과 다른 방식으로 같은 목표를 달성합니다. OpenClaw는 앱으로, Hermes Agent는 시스템 레벨 접근으로 Apple 생태계와 통합합니다. Hermes Agent만의 장점은:

  • FindMy 통합: OpenClaw에 없는 기능 (AppleScript + 비전 LLM 방식)
  • HomeAssistant 내장 도구: 4개의 전용 도구로 스마트홈 직접 제어
  • 자기 개선: 반복 사용 시 자동으로 스킬 생성 (예: "야간 루틴" 스킬)
  • 비용: 로컬 LLM 사용 시 API 비용 없음
