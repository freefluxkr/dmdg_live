11-3. 운영 환경 보안 체크리스트

Hermes Agent를 운영 환경에 배포할 때 확인해야 할 항목들입니다. 공식 문서의 권장사항과 소스 코드 분석에서 발견한 실질적 주의점을 함께 정리합니다.

어떻게 검증했나

체크리스트 각 항목은 다음 기준으로 검토했습니다.

  • 공식 문서 매칭: NousResearch 공식 문서 또는 RELEASE 노트에 같은 권고가 있는지
  • 소스 코드 대조: 보안 플래그·기본값은 agent/redact.py·tools/approval.py·tools/website_policy.py·hermes_cli/config.py 소스에서 직접 확인
  • 버전 표기: 항목 안의 버전 메모(v0.9·v0.12 등)는 달라진 지점만 한 줄로 남기고, 자세한 이력은 페이지 맨 아래 「버전별 변경 이력」 절로 분리

체크리스트 본문이 길어지지 않도록, 항목 설명 안에는 방식·이유만 남기고 시점은 별도 절에서 다룹니다.

필수 체크리스트

  • [ ] 사용자 인증: TELEGRAM_ALLOWED_USERS 등 플랫폼별 허용 목록을 명시적으로 설정하거나, DM 페어링을 활성화합니다
  • [ ] GATEWAY_ALLOW_ALL_USERS 비활성화: 운영 환경에서는 절대 true로 설정하지 않습니다
  • [ ] 컨테이너 백엔드 사용: terminal.backend: docker 또는 SSH/Modal/Daytona 사용 (local 백엔드 지양)
  • [ ] 리소스 제한: container_cpu, container_memory 설정
  • [ ] API 키 보안: ~/.hermes/.env 파일에 chmod 600 적용
  • [ ] 비root 실행: root가 아닌 일반 사용자로 게이트웨이 실행
  • [ ] 작업 디렉터리 제한: terminal.cwd(config.yaml)로 작업 디렉터리를 한정합니다(과거의 MESSAGING_CWD 환경변수는 제거됐고, .env에 남아 있으면 경고가 출력됩니다)
  • [ ] docker_forward_env 최소화: 꼭 필요한 변수만 컨테이너로 전달합니다
  • [ ] 정기 업데이트: hermes update로 보안 패치를 적용합니다

권장 체크리스트

  • [ ] DM 페어링 사용: 사용자 ID 하드코딩보다 페어링 코드가 유연합니다
  • [ ] command_allowlist 감사: config.yaml의 영구 허용 목록을 주기적으로 점검합니다
  • [ ] 로그 모니터링: ~/.hermes/logs/ 디렉터리의 비인가 접근 시도를 모니터링합니다
  • [ ] 웹사이트 차단: 내부 서비스, 관리자 패널 등에 대한 website_blocklist 설정
  • [ ] Tirith 보안 스캔: 기본 활성화되어 있는지 확인 (security.tirith_enabled: true)
  • [ ] 시크릿 마스킹: security.redact_secrets는 기본값이 ON입니다(agent/redact.py). 운영에서 끄지 않았는지 확인하고, 끈 상태라면 로그·도구 출력의 시크릿 노출 위험을 검토합니다
  • [ ] 승인 버튼 사용: Slack/Telegram 통합을 쓰면 위험 명령 승인이 인라인 버튼으로 뜨므로, 채널을 잠시도 자리를 비워도 잘못된 자동 승인이 발생하지 않도록 채널 권한을 좁게 둡니다
  • [ ] 승인 훅 활용: pre_approval_request / post_approval_response 훅으로 외부 감사 로그·SOC 시스템에 승인 이벤트를 흘려 보냅니다
  • [ ] Twilio 웹훅 시그니처 검증: SMS 어댑터를 쓰면 TWILIO_AUTH_TOKEN을 설정해 시그니처 검증이 작동하도록 합니다(없으면 webhook 엔드포인트가 누구든 호출 가능)
  • [ ] API 서버 인증: 내장 API 서버는 노출 시 반드시 토큰 인증을 켭니다(설정 누락에 주의 — 「버전별 변경 이력」 v0.9 항목 참고)
  • [ ] 체크포인트 매니저 경로: checkpoints/가 작업 디렉터리 외부 경로 traversal로 빠져나가지 않도록 기본 경로 사용을 권장

웹사이트 차단 설정

에이전트가 접근할 수 있는 웹사이트를 제한합니다.

# ~/.hermes/config.yaml
security:
  website_blocklist:
    enabled: true
    domains:
      - "*.internal.company.com"
      - "admin.example.com"
    shared_files:
      - "/etc/hermes/blocked-sites.txt"

차단된 URL 요청 시 에이전트에게 에러 메시지가 반환됩니다. web_search, web_extract, browser_navigate 등 모든 URL 관련 도구에 적용됩니다. 공유 파일은 줄 단위로 도메인 규칙을 포함하며, 30초 캐시로 설정 변경이 빠르게 반영됩니다.

API 키 보안

# .env 파일 권한 설정
chmod 600 ~/.hermes/.env

# 페어링 데이터 파일도 자동으로 chmod 0600 적용됨
# ~/.hermes/pairing/ 디렉터리 확인
ls -la ~/.hermes/pairing/

주요 주의점

  • .env 파일을 버전 관리에 커밋하지 않습니다
  • MCP 서버의 env 섹션에는 해당 서버에 필요한 키만 설정합니다
  • docker_forward_env에는 작업에 필요한 최소한의 변수만 추가합니다

승인 모드 설정

운영 환경에서의 권장 설정입니다.

# 컨테이너 사용 시 (위험 명령 승인 자동 생략)
terminal:
  backend: docker

# 로컬/SSH 백엔드 사용 시
approvals:
  mode: smart    # 보조 LLM이 안전한 명령을 자동 승인
approvals.mode 설정 키 주의

설정 키는 approvals.mode(중첩 키)이고 기본값은 "manual"입니다(값: manual | smart | off). 코드에서는 "smart"와 "off"만 특별히 처리하고, 그 외 값은 모두 수동 승인으로 작동합니다.

네트워크 격리 구성

최대 보안을 원한다면, 게이트웨이와 명령 실행을 분리합니다.

# 게이트웨이 서버 (메시징 연결 담당)
terminal:
  backend: ssh
  ssh_host: "agent-worker.local"
  ssh_user: "hermes"
  ssh_key: "~/.ssh/hermes_agent_key"

또는 Docker + 네트워크 비활성화로 완전한 격리를 구성합니다.

terminal:
  backend: docker
  docker_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  docker_extra_args: ["--network=none"]  # 외부 네트워크 접근 차단
  container_persistent: false    # 임시 파일시스템 (종료 시 삭제)
  docker_forward_env: []         # 환경변수 미전달

실전 함정 (gotchas)

소스 코드 분석에서 발견한 실질적인 주의점입니다.

1. 디스크 제한이 작동하지 않을 수 있습니다

container_disk 설정은 overlay2 + XFS + pquota 조건을 모두 만족해야 합니다. macOS Docker Desktop, 대부분의 Ubuntu 기본 설치에서는 작동하지 않습니다. 소스 코드에서 런타임 프로빙을 수행하고, 미지원 시 경고 로그만 출력하며 제한 없이 실행합니다.

2. Tirith의 fail-open 기본값

Tirith 바이너리가 설치되지 않았거나, 타임아웃이 발생하면 기본적으로 명령을 허용합니다. 보안을 강화하려면:

security:
  tirith_fail_open: false  # 실패 시 차단 (기본값: true)

3. SSH 백엔드의 StrictHostKeyChecking

SSH 백엔드는 StrictHostKeyChecking=accept-new로 설정되어 있어, 첫 연결 시 호스트 키를 자동 수락합니다. 보안이 중요한 환경에서는 사전에 known_hosts를 설정해 두는 것이 좋습니다.

4. 시크릿 마스킹의 한계

agent/redact.py는 알려진 패턴(접두사, 환경변수명, JSON 필드명)만 탐지합니다. 커스텀 API 키 형식이나 비정형 시크릿은 마스킹되지 않을 수 있습니다. 컨테이너 격리와 함께 사용하는 것이 가장 안전합니다.

5. docker_forward_env 유효성 검사

docker_forward_env의 항목은 정규식 ^[A-Za-z_][A-Za-z0-9_]*$로 유효성을 검사합니다. 잘못된 형식의 항목은 경고 로그와 함께 무시됩니다. 하지만 유효한 이름이면 어떤 환경변수든 전달되므로, 목록을 최소화하는 것이 중요합니다.

버전별 변경 이력

체크리스트 안에 흩어져 있던 시점 정보를 한 곳에 모았습니다.

  • redact_secrets 기본값 — 한때 기본 OFF로 운영되던 시기가 있었으나(시크릿 모양의 가짜 일치로 패치 결과가 손상되는 사고 대응), 현재 소스에서는 기본값이 ON입니다(hermes_cli/config.py, agent/redact.py). 운영에서는 끄지 않은 상태를 유지하는 것이 안전합니다.
  • v0.9 — 내장 API 서버의 미인증 노출 경로가 막힘. 인증 토큰 설정을 누락하지 않도록 운영에서 명시적으로 확인합니다.
