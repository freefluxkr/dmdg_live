09-4. Microsoft Teams 연동

⚠️ 부분 검증: 이 페이지는 v0.16.0 소스(microsoft-teams-apps SDK 기반 Bot Framework 어댑터 plugins/platforms/teams/adapter.py)와 공식 문서(website/docs/user-guide/messaging/teams.md)를 대조해 작성했습니다. 봇 등록·실제 메시지 송수신은 외부 의존성(Microsoft Teams 앱 등록, 공용 HTTPS 엔드포인트)이 필요해 직접 운영 테스트는 하지 않았습니다. 환경에 따라 절차가 달라질 수 있습니다.

Microsoft Teams 봇으로 Hermes Agent를 연결하는 방법입니다. Hermes의 Teams 연동은 microsoft-teams-apps SDK를 쓰는 Bot Framework 봇으로, 봇의 메시지 엔드포인트(/api/messages, 기본 포트 3978)로 들어오는 메시지를 받아 처리합니다.

메시지 파이프라인

  1. 인증 — Azure AD 앱의 클라이언트 시크릿으로 Bot Framework 토큰을 발급받습니다(SDK가 처리).
  2. 메시지 수신 — Teams Bot Framework가 봇의 메시지 엔드포인트(/api/messages, 기본 포트 3978)로 메시지를 전달하고, 어댑터의 HTTP 서버가 이를 받습니다. 엔드포인트는 Bot Framework JWT로 인증되며, 별도의 Microsoft Graph 구독 갱신은 필요 없습니다.
  3. 필터링 — 수신 메시지에서 사용자 식별자(AAD object ID)를 뽑아 TEAMS_ALLOWED_USERS로 거른 뒤, 통과한 메시지를 에이전트 세션에 전달합니다.
  4. 송신 — 에이전트의 응답을 Bot Framework를 통해 같은 대화(채널·그룹·DM)로 보냅니다.

할 수 있는 일

  • Teams 채널·그룹·1:1 DM 어디에서나 에이전트와 대화할 수 있습니다(DM은 멘션 없이, 그룹·채널은 봇을 멘션해야 응답).
  • 위험 명령 승인을 Adaptive Card 버튼으로 받을 수 있습니다.
  • 크론 작업 결과를 지정한 채널(홈 채널)로 보낼 수 있습니다.
  • 별도의 Teams 회의 요약 파이프라인(Microsoft Graph 기반)도 제공됩니다.
  • Telegram, Discord 같은 다른 메시징 플랫폼과 함께 운영할 수 있습니다.

사전 준비

봇 등록은 Teams CLI로 합니다.

  1. Teams CLI를 설치합니다.
npm install -g @microsoft/teams.cli@preview
teams login

  1. 게이트웨이가 들을 포트(기본 3978)를 공용 HTTPS로 노출합니다. 로컬 개발에서는 devtunnel·ngrok·cloudflared 같은 터널을 씁니다.

  2. 봇을 생성하면서 메시지 엔드포인트를 지정합니다.

teams app create --name "Hermes" --endpoint "https://<tunnel>/api/messages"
  1. 출력된 CLIENT_ID·CLIENT_SECRET·TENANT_ID를 저장하고, 설치 링크로 워크스페이스에 추가합니다.
teams app get <app-id> --install-link

설정

~/.hermes/.env에 인증 정보와 허용 사용자를 저장합니다.

TEAMS_CLIENT_ID=<client-id>
TEAMS_CLIENT_SECRET=<client-secret>
TEAMS_TENANT_ID=<tenant-id>
# 접근을 허용할 사용자(AAD object ID). teams status --verbose로 확인
TEAMS_ALLOWED_USERS=<your-aad-object-id>

config.yaml에서 플랫폼을 켜고 포트 등 세부를 지정할 수 있습니다.

platforms:
  teams:
    enabled: true
    extra:
      client_id: "your-client-id"
      client_secret: "your-secret"
      tenant_id: "your-tenant-id"
      port: 3978
기본값은 전체 차단입니다

TEAMS_ALLOWED_USERS를 설정하지 않고 TEAMS_ALLOW_ALL_USERS=true도 주지 않으면, 봇은 모든 요청을 거부합니다(기본 차단). 승인 카드 클릭도 같은 정책을 따릅니다. *를 넣으면 전체 허용입니다. 봇이 터미널·파일 권한을 가질 수 있다는 점을 고려해 신중하게 설정합니다.

게이트웨이 시작

hermes gateway

봇 메시지를 받으려면 게이트웨이가 실행 중이어야 하고, 3978 포트(또는 TEAMS_PORT로 지정한 포트)가 공용 HTTPS 엔드포인트로 노출돼 있어야 합니다.

메시지 보내기

채널이나 사용자를 지정하면 에이전트가 직접 메시지를 보낼 수 있습니다. 크론 작업 결과를 받을 채널을 설정하는 방법은 9장 도입부의 /sethome 안내를 참고합니다.

한계와 주의 사항

  • 봇 등록과 워크스페이스 설치에는 조직(테넌트) 권한이 필요할 수 있습니다. 회의 요약 파이프라인처럼 Microsoft Graph 권한을 쓰는 기능은 별도로 관리자 동의가 필요합니다.
  • 봇이 받은 메시지는 Microsoft 측 로그에 남습니다. 사내 컴플라이언스 정책과 맞는지 미리 확인합니다.
  • 메시지 본문은 약 28,000자까지 처리됩니다. 큰 파일은 외부 스토리지에 올린 뒤 링크로 공유합니다.

다른 플랫폼과의 차이

Telegram이나 Discord는 봇 API 구조가 단순하고 설정 절차도 짧습니다. 반면 Teams는 Bot Framework와 Teams CLI, 공용 엔드포인트를 함께 써야 하므로 초기 설정이 더 복잡합니다. 대신 한 번 설정해 두면 사내 업무 흐름에 자연스럽게 녹아듭니다. 동료들은 채널에서 봇을 멘션하는 방식으로 에이전트를 사용할 수 있습니다.
