첫 실행

설치가 끝났으면 터미널에서 hermes 한 줄이면 됩니다.

hermes

ASCII 아트 배너와 함께 시작 화면이 뜹니다. 왼쪽에 현재 모델·세션 정보가, 오른쪽에 사용 가능한 도구와 스킬 목록이 보이고, 화면 아래쪽 프롬프트(>)에 자연어로 지시하면 됩니다. 화면 맨 아래의 N tools · M skills 줄에 환경 기준의 활성 도구·스킬 수가 표시됩니다(위 예시에서는 30개 도구·91개 스킬). 번들 스킬은 약 90개이며, 외부 디렉터리·MCP·스킬 허브로 더 늘릴 수 있습니다.

두 가지 인터페이스: 클래식 REPL과 Ink-based TUI

Hermes에는 진입점이 두 가지 있습니다.

진입점 명령 특징
클래식 REPL hermes (옵션 없이) 가벼움. 스크립트·파이프와 잘 맞고, 비대화형 환경에서도 안전
Ink-based TUI hermes --tui React/Ink 기반의 풀 화면 TUI. 스티키 컴포저, OSC-52 클립보드, 라이브 스트리밍, LaTeX 렌더링, 라이트/다크 자동 감지 등

TUI는 마우스 휠 라인 스크롤, /resume 피커에서 d 키로 세션 삭제, ? 입력 시 미니 헬프 같은 편의 기능이 추가로 들어가 있습니다. 가시 cold start는 lazy import·캐시 등으로 클래식 대비 약 절반 수준입니다. tmux나 SSH 같은 환경에서는 클래식이 더 안정적인 경우도 있으므로, 두 인터페이스를 상황에 맞게 골라 쓰면 됩니다.

무엇을 시킬 수 있나

사람에게 부탁하듯 말하면 됩니다. 에이전트가 어떤 도구를 쓸지, 어떤 순서로 처리할지는 알아서 판단합니다.

"내일 회의 준비 좀 도와줘"

> 내일 팀 회의 안건을 정리해줘. 주제는 "신규 프로젝트 킥오프"이고,
> 목표, 일정, 역할 분담, 리스크, 다음 단계 정도로 항목을 잡아줘.
> 파일로 저장도 해줘.

에이전트가 안건을 작성하고, 파일로 저장까지 해줍니다. 사용자는 원하는 결과물만 말하면 됩니다. 같은 종류의 작업을 반복하면, Hermes Agent는 그 절차를 스킬로 저장해서 다음에는 더 빠르게 처리합니다. (→ 7장)

"이 서버 에러 좀 봐줘"

> 서버 에러 로그에서 최근에 뭐가 문제인지 파악하고,
> 가장 빈번한 문제 3가지와 해결 방안을 알려줘

에이전트가 로그 파일을 찾아 읽고, 에러 패턴을 분류하고, 해결 방안까지 제시합니다. 구체적인 파일 경로나 분석 명령을 몰라도, 원하는 것만 말하면 에이전트가 방법을 찾습니다.

"매일 아침 이것 좀 해줘"

> 매일 아침 9시에 GitHub 이슈 중 버그를 요약해서 Telegram으로 보내줘

이 한마디로 자동화가 설정됩니다. "매일 아침 9시"라는 일정 해석, 이슈 필터링, 메시지 전달 — 모든 세부사항은 에이전트가 처리합니다. 결과는 Telegram, Discord, Slack 등으로 받을 수 있습니다. (→ 10장)

이것이 단순한 챗봇이나 명령줄 도구와 다른 점입니다. 사용자는 원하는 것만 말하고, 에이전트가 방법을 찾아 실행합니다. 게다가 사용할수록 사용자의 패턴을 학습하여 점점 빨라집니다.

OpenClaw에서 전환하려면

hermes claw migrate 명령으로 OpenClaw의 설정, 메모리, API 키를 그대로 가져올 수 있습니다. 기존 환경을 버리지 않고 전환할 수 있습니다.

알아두면 좋은 것들

종료

대화를 끝내려면 /quit 또는 /q를 입력합니다. Ctrl+D도 작동합니다.

일시 중단

Ctrl+Z를 누르면 Hermes 프로세스가 일시 중단됩니다. 셸로 돌아가 다른 작업을 한 뒤, fg 명령으로 다시 돌아올 수 있습니다. Unix 계열(macOS, Linux)에서만 지원되며 Windows에서는 작동하지 않습니다.

실행 옵션

대화형 세션 대신 한 번만 질문하고 끝낼 수도 있습니다.

hermes chat -q "오늘 날짜가 며칠이야?"

스크립트나 파이프에 끼워 넣을 때는 더 좋은 방법이 있습니다. hermes -z(--oneshot) 모드는 배너·스피너·도구 미리보기·세션 ID 줄을 모두 끄고, 최종 응답 텍스트만 stdout으로 내보냅니다. 승인 프롬프트도 자동으로 우회되므로 비대화형 자동화에 적합합니다.

hermes -z "오늘 사람들이 SNS에서 가장 많이 얘기한 IT 키워드 3개를 한 줄씩 나열해줘"

-z에 -m/--model, --provider, -t/--toolsets 같은 옵션을 함께 쓰면 인보케이션 단위로 모델과 도구 셋을 바꿀 수 있습니다(HERMES_INFERENCE_MODEL·HERMES_INFERENCE_PROVIDER 환경 변수도 동일하게 작동).

특정 모델로 실행하려면 --model 옵션을 사용합니다. 해당 모델이 Ollama에 미리 다운로드되어 있어야 합니다(ollama pull <모델명>).

hermes chat --model "qwen3:14b"

턴 수를 제한하려면 --max-turns 옵션을 사용합니다. 자동화 스크립트에서 에이전트가 무한 루프에 빠지는 것을 방지할 때 유용합니다.

hermes chat --max-turns 10

💡 /fast 모드: 대화 중 /fast를 입력하면 OpenAI Priority Processing 또는 Anthropic Fast 티어를 통해 응답 지연을 줄입니다. 같은 모델·같은 요청이지만 우선 처리 큐로 보내는 방식이며, OpenAI(GPT·Codex)와 Anthropic(Claude) 모델에만 적용됩니다. 자세한 내용은 3-3절을 참고하세요.

웹 대시보드

CLI를 켜는 대신 브라우저로 설정·세션·플러그인을 관리할 수도 있습니다.

hermes dashboard            # 기본 포트 9119, 자동으로 브라우저 오픈
hermes dashboard --status   # 실행 중인 대시보드 목록
hermes dashboard --stop     # 모든 대시보드 종료

대시보드는 기본적으로 127.0.0.1:9119에 바인드되어 로컬 전용입니다. Models 탭에서 메인·보조 모델을 그대로 바꿀 수 있고, Plugins 탭에서 플러그인 활성화/비활성화·인증·설치/삭제를 한자리에서 합니다. --insecure 플래그로 비루프백 호스트에 노출할 수도 있지만 API 키가 LAN에 노출되므로 신뢰된 네트워크에서만 사용하세요.

이전 대화 이어가기

대화 세션은 자동 저장됩니다. 터미널을 닫았다가 다시 열어도 이어서 대화할 수 있습니다.

hermes -c                # 마지막 세션 이어서

도구 호출 과정 보기

에이전트가 어떤 도구를 왜 쓰는지 보고 싶다면, 대화 중에 /verbose를 입력하세요. 도구 호출 과정이 상세히 표시됩니다. 처음에는 켜두고 관찰하는 것을 권장합니다.

클릭 가능한 URL (OSC8)

v0.14부터 에이전트 출력의 URL은 단순 텍스트가 아니라 OSC8 하이퍼링크로 렌더링됩니다. iTerm2·Kitty·Ghostty·최신 Windows Terminal 같은 OSC8 지원 터미널에서 호버 강조가 뜨고, 클릭하면 브라우저로 열립니다. 긴 URL을 복사·붙여넣기 하다가 일부가 잘려 나가는 사고가 사라집니다. OSC8을 지원하지 않는 터미널에서는 평범한 텍스트로 보입니다.

@ 컨텍스트 참조

메시지에 @ 접두사를 붙이면 파일, 코드, 변경 사항 등을 대화에 직접 주입할 수 있습니다.

> @file:src/main.py 이 코드에서 버그를 찾아줘
> @diff 이 변경 사항을 리뷰해줘
> @git:5 최근 5개 커밋을 요약해줘

지원하는 참조 형식은 다음과 같습니다.

참조 설명
@file:경로 파일 내용 주입
@file:경로:10-50 특정 줄 범위만 주입
@folder:경로 디렉터리 구조와 파일 주입
@diff 커밋되지 않은 변경 사항
@staged 스테이징된 변경 사항
@git:N 최근 N개 커밋
@url:주소 웹 페이지 내용

토큰 예산 보호도 내장되어 있어서, 참조한 내용이 컨텍스트의 25%를 넘으면 경고가, 50%를 넘으면 차단이 됩니다. 파일을 복사-붙여넣기하는 대신 @file:로 가리키면 훨씬 효율적입니다.

이 밖의 슬래시 명령어와 단축키는 3-3절에서 자세히 다룹니다.

웹 UI도 가능합니다

터미널이 불편하다면, Hermes Agent에 내장된 OpenAI 호환 API 서버를 통해 Open WebUI 같은 웹 프런트엔드를 연결할 수 있습니다. 다만 이 기능은 아직 초기 단계이며, CLI의 /verbose처럼 사고 과정을 관찰하기는 어렵습니다.
