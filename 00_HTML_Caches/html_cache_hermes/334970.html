프로젝트: 팀 협업 봇 구축

이 프로젝트에서는 Hermes Agent를 팀이 공유하는 Discord/Slack 봇으로 운영하는 방법을 다룹니다. 가장 복잡한 프로젝트이지만, 팀 생산성을 크게 높일 수 있습니다.

목표

  • 팀원들이 Discord에서 에이전트에게 질문할 수 있는 환경 구성
  • DM 페어링으로 인증된 팀원만 접근 허용
  • AGENTS.md로 프로젝트 규칙을 에이전트에게 전달
  • 공용 스킬로 팀 워크플로 자동화

아키텍처

팀원 (Discord) → Hermes Gateway → 에이전트 → 도구 실행
                                      ↓
                                   스킬/메모리

팀원은 Discord DM으로 에이전트와 대화합니다. 게이트웨이가 메시지를 중계하고, 에이전트가 도구를 실행하여 결과를 반환합니다.

설정

1. Discord 봇 설정

Discord Developer Portal에서 봇을 생성합니다 (9장 참조). Message Content Intent를 반드시 활성화해야 합니다. 이 설정이 꺼져 있으면 봇이 메시지 내용을 읽을 수 없습니다.

# .env
DISCORD_BOT_TOKEN=your_token

필요한 봇 권한:

  • Send Messages
  • Read Message History
  • Manage Messages (선택)

2. 사용자 인증

DISCORD_ALLOWED_USERS를 설정하지 않으면 모든 사용자의 요청이 거부됩니다. 보안을 위해 기본값이 "전부 차단"이므로, 반드시 허용할 팀원의 Discord 사용자 ID를 명시해야 합니다(9장 참조).

# config.yaml
discord:
  allowed_users:
    - "팀원1_discord_id"
    - "팀원2_discord_id"

# 또는 DM 페어링 사용 (새 팀원이 자주 추가될 때 편리)
unauthorized_dm_behavior: pair
DM 페어링 vs 허용 목록

팀 규모가 작고 고정적이면 allowed_users로 직접 관리하는 것이 안전합니다. 팀원이 자주 바뀌는 환경에서는 pair 모드가 편리하지만, 페어링 코드를 팀 내부 채널로만 공유하세요.

3. 프로젝트 규칙 (AGENTS.md)

팀의 컨벤션과 업무 규칙을 정의합니다.

# AGENTS.md

## 팀 프로젝트 규칙

### 기본 원칙
- 응답은 한국어로
- 코드 블록에는 항상 언어를 명시
- 불확실한 정보는 "확인 필요"라고 표시

### 코드 리뷰
- 보안 취약점 체크 (SQL 인젝션, XSS 등)
- 성능 이슈 지적
- 코딩 컨벤션 준수 여부 확인

### 안전 규칙
- DB 변경 작업은 반드시 사용자 확인 후 실행
- 프로덕션 서버 접근 명령은 거부
- 환경변수나 시크릿을 메시지에 포함하지 않음

4. 팀 스킬 생성

자주 사용하는 작업을 스킬로 만듭니다.

> 다음 스킬을 만들어줘:
> 이름: deploy-check
> 내용: 배포 전 체크리스트 - 테스트 통과 여부, 린트 통과 여부,
>       환경변수 설정 확인, DB 마이그레이션 확인

팀에서 유용한 스킬 예시:

  • deploy-check: 배포 전 체크리스트 실행
  • pr-review: PR URL을 받아 코드 리뷰 수행
  • incident-report: 장애 보고서 템플릿 생성
  • onboarding: 새 팀원용 환경 설정 가이드 안내

5. 퍼스널리티 설정 (SOUL.md)

팀 봇에 적합한 성격을 설정합니다.

보안 고려사항

팀 봇 운영 시 반드시 확인해야 할 사항:

  • 컨테이너 백엔드 사용: terminal.backend: docker 또는 ssh로 설정하여 호스트 시스템을 보호
  • DISCORD_ALLOWED_USERS 필수 설정: 미설정 시 모든 요청이 거부됩니다. GATEWAY_ALLOW_ALL_USERS를 true로 설정하면 인증 없이 누구나 접근 가능하므로 절대 금지
  • 승인 모드: approvals.mode: manual (위험한 명령 실행 전 확인). 값은 manual·smart·off이며 기본은 manual입니다
  • 리소스 제한 설정: CPU, 메모리 제한으로 남용 방지
  • 정기 감사: 메모리, 스킬, 크론 작업을 주기적으로 점검
컨테이너 백엔드 필수

팀 봇에서는 반드시 컨테이너 백엔드를 사용하세요. 봇이 실행하는 명령이 호스트 시스템에 직접 영향을 주면 보안 사고로 이어질 수 있습니다. Docker 백엔드 설정은 11장을 참조하세요.

스킬 버전 관리

팀 스킬은 Git으로 관리하면 변경 이력을 추적할 수 있습니다.

cd ~/.hermes/skills
git init
git add .
git commit -m "팀 스킬 초기 설정"

사용량 관리

API 기반 LLM을 사용할 경우, 팀 봇의 사용량을 모니터링하세요. Ollama 로컬 모델을 사용하면 비용 걱정 없이 운영할 수 있습니다.
