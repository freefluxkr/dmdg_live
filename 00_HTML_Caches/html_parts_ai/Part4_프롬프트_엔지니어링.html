10.1 프롬프트란 무엇인가

프롬프트(Prompt)란 AI 모델에게 전달하는 입력 텍스트 전체를 가리킵니다. 단순한 질문 한 줄일 수도 있고, 역할·맥락·규칙을 수백 단어로 서술한 복합 지시문일 수도 있습니다. AI는 이 프롬프트를 해석해 응답을 생성하기 때문에, 프롬프트는 AI와 인간 사이의 실질적인 소통 인터페이스라 할 수 있습니다.

일상 대화로 비유하면 이렇습니다. 식당에서 "뭔가 먹을 것"이라고 말하는 것과 "오늘 점심으로 칼로리가 낮고 채소 위주의 따뜻한 음식을 추천해 주세요"라고 말하는 것은 전혀 다른 결과를 낳습니다. AI와의 대화도 마찬가지입니다.

📌 프롬프트의 정의: AI 모델에게 전달하는 모든 입력 텍스트. 질문, 지시, 예시, 맥락 정보를 포함할 수 있습니다.

프롬프트는 크게 세 가지 형태로 나눌 수 있습니다.

  • 지시형: "~을 작성해 주세요", "~을 요약해 주세요"처럼 특정 작업을 요청하는 형태
  • 질문형: "~은 무엇인가요?", "~의 차이점은?"처럼 정보를 묻는 형태
  • 대화형: 이전 맥락을 이어받아 계속 대화를 이어가는 형태

이 챕터에서는 주로 지시형과 질문형 프롬프트를 다루며, ChatGPT와 Gemini 웹 UI에서 직접 실습합니다.

10.2 왜 프롬프트가 중요한가 — 같은 모델, 다른 결과

AI 모델의 성능은 고정되어 있지만, 프롬프트에 따라 출력 품질은 극적으로 달라집니다. 이것이 프롬프트 엔지니어링이 중요한 핵심 이유입니다.

💡 핵심 원리: AI는 주어진 프롬프트를 최대한 충실히 완성하려 합니다. 모호한 입력에는 모호한 출력으로, 명확한 입력에는 명확한 출력으로 반응합니다.

10.3 좋은 프롬프트 vs 나쁜 프롬프트 (Before/After 사례)

좋은 프롬프트와 나쁜 프롬프트의 차이를 구체적인 사례로 살펴봅니다. 아래 표에서 "나쁜 프롬프트"의 공통점을 찾아보시면 패턴이 보일 것입니다.

아래 표는 동일한 목적을 가진 나쁜 프롬프트와 좋은 프롬프트를 비교한 것입니다.

# 나쁜 프롬프트 좋은 프롬프트 개선 포인트
1 이메일 써줘 고객에게 환불 지연을 정중히 사과하는 이메일을 200자 이내로 써줘 대상·목적·분량 명시
2 파이썬 알려줘 파이썬을 처음 배우는 고등학생에게 변수와 자료형을 예시 코드와 함께 설명해줘 대상·범위·형식 명시
3 요리 레시피 재료: 달걀 3개, 양파 반 개, 치즈. 15분 안에 만들 수 있는 간단한 아침 식사 레시피를 단계별로 알려줘 재료·시간·형식 명시
4 번역해줘 다음 문장을 격식체 한국어로 번역해줘: "The meeting has been postponed to next Monday." 언어 방향·문체 명시
5 운동 추천 무릎 부상 이력이 있는 30대 여성에게 집에서 할 수 있는 유산소 운동 3가지를 추천해줘 조건·제약·수량 명시

💡 패턴 발견: 나쁜 프롬프트의 공통점은 모호함입니다. "누가", "무엇을", "어떻게", "얼마나"가 빠져 있습니다.

나쁜 프롬프트가 만들어지는 이유는 대부분 "AI가 알아서 해주겠지"라는 기대 때문입니다. AI는 강력하지만, 당신의 머릿속에 있는 기대치를 읽을 수는 없습니다. 명시하지 않은 정보는 AI가 임의로 채웁니다.

10.4 프롬프트의 6가지 구성요소

효과적인 프롬프트는 다음 6가지 요소를 필요에 따라 조합합니다. 모든 요소를 항상 써야 하는 것은 아니지만, 원하는 결과가 나오지 않을 때 빠진 요소가 무엇인지 점검하는 체크리스트로 활용할 수 있습니다.

역할(Role)

역할(Role)은 AI에게 어떤 페르소나로 응답할지 지정하는 요소입니다. "당신은 ~입니다"라는 형태로 설정합니다. 역할을 부여하면 AI는 해당 전문가의 어투, 지식 수준, 관점으로 응답합니다.

당신은 10년 경력의 마케팅 카피라이터입니다.
당신은 초등학생도 이해할 수 있게 설명하는 과학 선생님입니다.
당신은 스타트업 투자 전문 벤처 캐피탈리스트입니다.

역할 설정은 특히 전문적인 내용, 특정 톤이 필요한 글쓰기, 교육 목적의 설명에서 효과적입니다.

작업(Task)

작업(Task)은 AI에게 무엇을 해달라는지 지시하는 핵심 요소입니다. 동사를 명확히 써야 합니다.

[나쁜 예] 마케팅
[좋은 예] 신제품 출시를 알리는 SNS 광고 문구 3개를 작성해 주세요.

작업 기술 시 주의할 점은 동사의 구체성입니다. "알려줘"보다 "요약해줘", "설명해줘", "작성해줘", "분석해줘", "비교해줘"처럼 행동을 명시하는 것이 좋습니다.

맥락(Context)

맥락(Context)은 작업을 올바르게 수행하기 위해 AI가 알아야 할 배경 정보입니다. 대상 독자, 현재 상황, 관련 데이터 등이 포함됩니다.

[나쁜 예] 이력서 자기소개서 써줘.
[좋은 예] 저는 3년차 백엔드 개발자로, Python과 Django 경험이 있습니다.
          네이버 계열사의 데이터 엔지니어 포지션에 지원하려 합니다.
          이 포지션의 자기소개서 첫 문단(200자)을 써주세요.

형식(Format)

형식(Format)은 출력 결과의 구조와 스타일을 지정합니다. 형식을 명시하면 후처리 작업이 크게 줄어듭니다.

- 글머리 기호 목록으로 작성해 주세요.
- 표(table) 형태로 정리해 주세요.
- 서론-본론-결론 구조로 작성해 주세요.
- JSON 형식으로 출력해 주세요.
- 500자 이내로 요약해 주세요.

제약조건(Constraints)

제약조건(Constraints)은 AI가 하지 말아야 할 것, 또는 반드시 지켜야 할 조건을 명시합니다.

- 전문 용어는 사용하지 마세요.
- 실존 인물의 이름을 언급하지 마세요.
- 반드시 한국어로만 작성하세요.
- 경쟁사 제품명은 언급하지 마세요.
- 의학적 진단이나 처방 내용은 포함하지 마세요.

제약조건은 AI가 의도치 않은 방향으로 흘러가는 것을 방지하는 가이드레일 역할을 합니다.

목표(Goal)

목표(Goal)는 이 작업의 궁극적인 목적이 무엇인지 알려주는 요소입니다. AI가 전체 목적을 이해하면 세부 판단에서 더 적합한 선택을 합니다.

[목표] 독자가 이 글을 읽고 제품 구매 페이지를 클릭하도록 유도하는 것입니다.
[목표] 면접관이 저의 문제 해결 능력에 깊은 인상을 받도록 하는 것입니다.
[목표] 초등학생이 광합성의 원리를 그림 없이도 이해할 수 있게 하는 것입니다.

📌 6가지 요소 요약표: 역할(Role), 작업(Task), 맥락(Context), 형식(Format), 제약조건(Constraints), 목표(Goal). 영어 첫 글자를 모으면 RT-CFG 로 기억할 수 있습니다.

아래 표는 6가지 요소를 적용한 완성형 프롬프트 예시입니다.

요소 내용
역할(Role) 당신은 대입 수험생을 위한 국어 논술 강사입니다.
작업(Task) 아래 주제로 논술 개요를 작성해 주세요.
맥락(Context) 주제: "SNS가 청소년의 정신 건강에 미치는 영향" / 대상: 고3 수험생
형식(Format) 서론 1문단, 본론 2문단(찬성/반대), 결론 1문단으로 구성. 각 문단 2~3문장.
제약조건(Constraints) 특정 SNS 플랫폼 이름은 언급하지 마세요.
목표(Goal) 논리적 흐름이 명확해 실제 논술 답안 초안으로 사용할 수 있도록.

10.5 구성요소 배치 전략 (5가지 배치 패턴)

6가지 요소를 어떤 순서로 배치하느냐에 따라 AI의 이해도와 응답 품질이 달라질 수 있습니다. 아래 5가지 패턴은 상황별 권장 순서입니다.

패턴 1: 역할 → 작업 → 맥락 (기본형)

가장 범용적인 패턴입니다. 먼저 AI에게 페르소나를 부여하고, 할 일을 지시한 뒤, 필요한 배경 정보를 제공합니다.

[역할] 당신은 경험 많은 HR 전문가입니다.
[작업] 아래 지원자의 이력서를 검토하고 개선점 3가지를 알려주세요.
[맥락] 지원 포지션: 스타트업 마케팅 매니저 / 경력 2년차 지원자의 이력서 내용: (이하 생략)

패턴 2: 맥락 → 작업 → 형식 (정보 처리형)

기존 문서나 데이터를 분석·요약·변환할 때 적합합니다. 처리할 원본 자료를 먼저 제시합니다.

[맥락] 다음은 회의록입니다: (회의록 내용)
[작업] 위 회의록에서 액션 아이템만 추출해 주세요.
[형식] 담당자, 내용, 마감일 세 열로 구성된 표로 정리해 주세요.

패턴 3: 작업 → 제약조건 → 목표 (창작형)

글쓰기, 카피라이팅, 콘텐츠 제작처럼 창의적 결과물이 필요할 때 사용합니다.

[작업] 새로운 친환경 텀블러 브랜드의 슬로건 5개를 만들어 주세요.
[제약조건] 10글자 이내, 영어 단어 포함 가능, 부정적인 표현 사용 금지
[목표] MZ세대가 SNS에 올리고 싶어질 만큼 감성적이고 공유하기 쉬운 문구

패턴 4: 역할 → 맥락 → 제약조건 → 작업 (전문 분야형)

Zero-Shot 프롬프팅(Zero-Shot Prompting)은 AI에게 아무런 예시를 주지 않고 작업을 지시하는 가장 기본적인 방식입니다. "제로(0)샷"이란 말 그대로 예시가 0개라는 뜻입니다.

현대의 대형 언어 모델(LLM)은 방대한 데이터로 사전 학습되어 있기 때문에, 많은 일반적인 작업에서 예시 없이도 상당히 좋은 결과를 냅니다.

11.2 Few-Shot 프롬프팅

Few-Shot 프롬프팅(Few-Shot Prompting)은 AI에게 작업 예시를 몇 개 제공하여 원하는 형식과 패턴을 학습시키는 기법입니다. "몇(Few)번의 샷(Shot)"처럼 몇 가지 예시를 보여주는 방식입니다.

One-Shot vs Few-Shot

구분 예시 개수 특징
Zero-Shot 0개 예시 없음, 빠르지만 불안정
One-Shot 1개 예시 1개, 기본 방향 제시
Few-Shot 2~5개 예시 여러 개, 패턴 명확화

일반적으로 예시는 3~5개가 가장 효과적입니다. 너무 많으면 프롬프트가 길어지고, 너무 적으면 패턴 파악이 어렵습니다.

  • 다양성: 다양한 케이스를 포함하여 AI가 여러 상황을 파악하게 합니다.

11.3 Chain-of-Thought (CoT) 프롬프팅

Chain-of-Thought(CoT) 프롬프팅은 AI가 최종 답을 바로 내놓는 대신, 단계별 사고 과정을 거쳐 답에 도달하도록 유도하는 기법입니다. 사람이 복잡한 문제를 풀 때 "먼저 이것을 계산하고, 다음에 저것을 고려하고..." 하는 방식과 같습니다.

"단계별로 생각해 봐(Let's think step by step)"라는 한 마디가 AI의 정확도를 크게 높입니다.

Zero-Shot CoT vs Few-Shot CoT

Zero-Shot CoT는 예시 없이 "단계별로 생각하라"고만 지시합니다.

Few-Shot CoT는 단계별 사고 과정이 담긴 예시를 함께 제공합니다.

구분 예시 유무 특징
Zero-Shot CoT 없음 빠르게 적용 가능, "단계별로 생각해봐" 한 줄 추가
Few-Shot CoT 있음 더 정확하고 안정적, 예시 준비 필요

Zero-Shot CoT 예시

사과가 15개 있습니다. 3명이 똑같이 나눠 가지면 한 사람당 몇 개를 가지게 될까요?

단계별로 생각해 보세요.

AI가 "15 ÷ 3 = 5이므로 한 사람당 5개"라는 과정을 보여주며 답합니다.

Few-Shot CoT 예시 — 수학 문제

1단계: 빵 한 개 가격 = 1,200원

3단계: 총 금액 = 1,200 × 5 = 6,000원

ReAct (Reasoning + Acting)

ReAct는 추론(Reasoning)과 행동(Acting)을 번갈아 수행하는 기법입니다. AI가 생각하고(Thought), 행동하고(Action), 결과를 관찰(Observation)하는 과정을 반복합니다.

주로 외부 도구(검색, 계산기, API 등)와 연동된 AI 에이전트에서 사용됩니다.

11.7 2025년 최신 LLM 심화 활용 기법

앞서 살펴본 기법들이 "프롬프트를 어떻게 쓰는가"에 초점을 맞췄다면, 이 절에서는 최신 LLM이 제공하는 모델·API 차원의 심화 기능을 다룹니다. 같은 모델이라도 이 기능들을 활용하면 정확도, 비용, 안정성 면에서 큰 차이를 만들 수 있습니다.

📌 왜 이 절이 필요한가: 2024~2025년 사이 GPT-5, Claude 4.5/Opus 4.7, Gemini 2.5 같은 최신 모델은 단순한 텍스트 입력·출력을 넘어 확장 사고, 캐싱, 구조화 출력, 도구 호출, 외부 컨텍스트 연결 등 5가지 핵심 기능을 보편적으로 지원합니다. 이 기능들을 모르면 최신 모델을 절반밖에 활용하지 못합니다.

Extended Thinking (확장 사고)

Extended Thinking은 모델이 응답을 생성하기 전, 별도의 "사고(thinking)" 토큰 공간에서 충분히 추론한 뒤 최종 답을 내놓는 기능입니다. Claude 4.5/Opus 4.7의 thinking 파라미터, OpenAI o-series의 reasoning_effort 등이 대표적입니다.

  • 언제 효과적인가: 수학·논리·코드 디버깅·복잡한 의사결정처럼 단계적 추론이 필요한 작업
  • CoT와의 차이: CoT는 프롬프트로 "생각하라"고 유도하는 기법이지만, Extended Thinking은 모델이 내부적으로 수천~수만 토큰의 추론 공간을 별도로 할당받습니다. 사용자에게는 정제된 답만 보여지거나 사고 과정이 함께 공개됩니다.
  • 비용 주의: 사고 토큰도 과금됩니다. 단순 작업에는 끄고, 복잡 작업에만 켜는 것이 비용 효율적입니다.
# Anthropic Claude — Extended Thinking 예시
response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=4096,
    thinking={"type": "enabled", "budget_tokens": 8000},
    messages=[{"role": "user", "content": "복잡한 수학 문제를 풀어주세요..."}],
)

Prompt Caching (프롬프트 캐싱)

Prompt Caching은 동일한 시스템 프롬프트나 대용량 컨텍스트를 여러 번 호출할 때, 모델 측에서 토큰화·임베딩 결과를 캐싱하여 비용과 지연을 크게 줄이는 기능입니다.

  • 비용 절감 효과: 캐시 적중 부분은 일반 입력 토큰의 약 10% 가격으로 청구 (OpenAI/Anthropic 기준, 모델별 상이)
  • 지연 단축: 첫 응답 시간(Time to First Token)이 절반 이하로 단축되는 경우가 많음
  • 활용 사례: 챗봇의 긴 시스템 프롬프트, 장문 문서를 반복 참조하는 RAG, 동일 코드베이스에 대한 연속 질문
# Anthropic — cache_control로 캐싱 영역 지정
messages=[{
    "role": "user",
    "content": [
        {"type": "text", "text": "긴 문서 전체...",
         "cache_control": {"type": "ephemeral"}},
        {"type": "text", "text": "이 문서에서 ~를 찾아주세요"},
    ],
}]

Structured Output (구조화 출력)

Structured Output은 모델 응답이 반드시 지정된 JSON 스키마에 부합하도록 강제하는 기능입니다. OpenAI의 response_format={"type": "json_schema", ...}, Anthropic Tool Use를 활용한 JSON 강제, Gemini의 responseSchema 등이 있습니다.

  • 왜 필요한가: 프롬프트로 "JSON으로 답해주세요"라고 부탁하면 가끔 형식이 깨집니다. Structured Output은 모델 디코딩 단계에서 스키마를 강제하므로 100% 파싱 가능
  • 활용 사례: 폼 자동 채우기, 데이터 추출 파이프라인, 도구 호출 인자 생성
# OpenAI — JSON Schema 강제
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer"},
        "skills": {"type": "array", "items": {"type": "string"}},
    },
    "required": ["name", "age", "skills"],
}
response = client.responses.create(
    model="gpt-5",
    input=[{"role": "user", "content": "이력서에서 이름·나이·기술을 추출하세요..."}],
    response_format={"type": "json_schema", "json_schema": {"name": "Profile", "schema": schema}},
)

Tool Use (도구 호출)

Tool Use(또는 Function Calling)는 LLM이 외부 함수·API·DB를 호출할 수 있도록 하는 기능입니다. 사용자가 도구 명세(이름·설명·인자 스키마)를 제공하면, 모델은 필요 시 도구 호출 JSON을 출력합니다. 애플리케이션이 그 도구를 실행한 결과를 다시 모델에 전달하면, 모델이 최종 답변을 생성합니다.

  • 활용 사례: 실시간 검색, 데이터베이스 질의, 계산기, 캘린더·이메일 자동화, 코드 실행
  • 앞서 본 ReAct와의 관계: ReAct는 "생각·행동·관찰"이라는 사고 패턴이고, Tool Use는 이를 모델·API 레벨에서 지원하는 공식 메커니즘입니다.
  • 상세 학습: Chapter 16에서 OpenAI Function Calling을 코드와 함께 본격적으로 다룹니다.

MCP (Model Context Protocol)

MCP(Model Context Protocol)는 2024년 Anthropic이 제안하고 2025년에 OpenAI·Google·주요 IDE 진영이 채택한 AI 에이전트와 외부 도구·데이터를 연결하는 표준 프로토콜입니다. "AI 시대의 USB-C"라고도 비유됩니다.

  • 왜 필요한가: 각 도구를 모델마다 별도로 통합하면 N×M 조합 문제가 발생합니다. MCP는 도구 제공자와 모델 호출자가 모두 동일한 규격을 따르도록 표준화합니다.
  • MCP 서버: 도구·데이터·프롬프트를 노출하는 측 (예: GitHub MCP, PostgreSQL MCP, Slack MCP, Linear MCP)
  • MCP 클라이언트: Claude Desktop, Cursor, VS Code 등 LLM 애플리케이션
  • 개인 사용자도 활용 가능: Claude Desktop에 MCP 서버를 등록하면 로컬 파일·DB·API를 Claude가 직접 다룰 수 있습니다.

Self-Consistency 다수결로 신뢰도 향상 정확도가 매우 중요한 경우
Prompt Chaining 작업을 단계별 연결 긴 콘텐츠, 복잡한 워크플로

Prompt Caching 반복 호출 비용·지연 감소 긴 시스템 프롬프트·RAG

12.1 프롬프트 디버깅 — 원하는 결과가 안 나올 때

왜 프롬프트가 실패하는가

AI에게 완벽한 지시를 내리는 사람은 없습니다. 처음에는 대부분 기대와 다른 결과가 나옵니다. 이때 포기하거나 반복해서 같은 프롬프트를 보내는 것은 시간 낭비입니다. 프롬프트 디버깅(Prompt Debugging)은 결과가 왜 틀렸는지 진단하고 체계적으로 수정하는 과정입니다.

실패의 5가지 주요 원인을 알면 진단이 쉬워집니다.

실패 유형 증상 원인
모호한 지시(Ambiguous Instruction) 너무 일반적인 답변 원하는 것을 구체적으로 명시하지 않음
컨텍스트 부족(Lack of Context) 엉뚱한 방향의 답변 상황·배경 정보가 없음
역할 미설정(No Role Assignment) 전문성 없는 답변 AI가 어떤 전문가인지 모름
형식 미지정(No Format Spec) 구조 없는 긴 글 출력 형식을 요청하지 않음
과도한 요청(Overloaded Request) 일부만 처리된 답변 한 번에 너무 많은 것을 요구

디버깅 3단계 프레임워크

[1단계] 진단 — 무엇이 문제인가?

결과물을 보고 다음 질문을 던집니다.

  • 방향이 맞는가? (틀렸다면 → 컨텍스트 또는 역할 문제)
  • 깊이가 있는가? (얕다면 → 구체성 또는 전문성 문제)
  • 형식이 맞는가? (지저분하다면 → 형식 지정 문제)
  • 분량이 맞는가? (너무 짧거나 길다면 → 제약 조건 문제)

[2단계] 수술 — 어느 부분을 고칠 것인가?

문제 부위만 정밀 수정합니다. 전체를 다시 쓰면 무엇이 효과가 있었는지 알 수 없습니다.

[3단계] 검증 — 고쳐졌는가?

수정 후 결과를 이전 버전과 비교합니다. 개선됐다면 무엇이 효과가 있었는지 기록해 둡니다.

실전 디버깅 예시

시나리오: 팀 회의 요약을 부탁했는데 너무 길고 핵심이 없는 결과가 나왔습니다.

실패한 프롬프트:

회의 내용을 요약해줘.

[회의록 원문 붙여넣기]

진단: 형식 미지정 + 컨텍스트 부족 + 분량 미제한

수정된 프롬프트:

당신은 기업 회의록 전문 에디터입니다.

아래 회의록을 다음 형식으로 요약해 주세요:

**요약 형식:**
- 회의 목적: 1문장
- 핵심 결정 사항: 번호 목록 3~5개
- 담당자별 할 일(Action Item): 표 형식 (담당자 | 업무 | 마감일)
- 다음 회의 안건: 1~3개

**제약 조건:**
- 전체 300자 이내
- 불필요한 인사말 제외

[회의록 원문 붙여넣기]

📌 디버깅 체크리스트

프롬프트를 보내기 전, 다음 5가지를 확인합니다.

  • [ ] 역할(Role)이 지정되어 있는가?
  • [ ] 상황(Context)이 충분히 설명되어 있는가?
  • [ ] 원하는 출력 형식(Format)이 명시되어 있는가?
  • [ ] 분량이나 수량 제약(Constraint)이 있는가?
  • [ ] 요청이 하나의 명확한 과제로 집중되어 있는가?

12.2 반복 개선(Iterative Refinement) 전략

반복 개선이란

반복 개선(Iterative Refinement)은 처음부터 완벽한 프롬프트를 만들려 하지 않고, 빠르게 초안을 얻은 뒤 단계적으로 개선해 나가는 방법론입니다. 소프트웨어 개발의 애자일(Agile) 방식을 프롬프트에 적용한 것입니다.

💡 핵심 원칙

"첫 번째 결과는 출발점이지, 도착점이 아닙니다." 완벽을 기다리지 말고 일단 실행하고 수정합니다.

반복 개선 5단계 사이클

각 단계에서 사용하는 구체적인 표현을 익혀두면 효율이 크게 오릅니다.

[1단계] 초안 요청 — 빠르게 시작하기

복잡하게 생각하지 말고 핵심 요청만 담은 짧은 프롬프트로 시작합니다.

신제품 출시를 위한 이메일 마케팅 문구를 작성해 줘.
제품: 무선 노이즈 캔슬링 이어폰
대상: 재택근무자

[2단계] 결과 평가 — 무엇이 좋고 나쁜가?

결과물의 좋은 점과 나쁜 점을 구체적으로 파악합니다.

✅ 좋은 점: 제품 특징을 잘 언급함
❌ 나쁜 점: 너무 딱딱하고 감성이 없음, 행동 유도 문구(CTA)가 약함

[3단계] 피드백 제공 — 구체적으로 수정 요청

"더 좋게 해줘"는 금물입니다. 구체적으로 무엇을 어떻게 바꿀지 지시합니다.

좋은 시도입니다. 다음을 수정해 주세요:

1. 톤을 "친근하고 공감하는" 느낌으로 바꿔 주세요
2. 재택근무자의 고충(집중력 방해, 회의 중 소음)을 첫 문장에 반영해 주세요
3. 마지막에 "지금 주문하면 20% 할인" 내용을 포함한 강한 CTA를 추가해 주세요
4. 전체 길이는 150자 이내로 줄여 주세요

[4단계] 재생성 — 결과 확인

수정된 결과를 받고 이전과 비교합니다.

[5단계] 반복 — 만족할 때까지

보통 2~4회의 반복으로 원하는 품질에 도달합니다. 더 이상 개선이 없다면 다른 접근법을 시도합니다.

반복 개선 시 유용한 명령 표현

상황 프롬프트 표현
전반적으로 너무 길 때 "핵심만 남기고 30% 압축해 주세요"
톤이 맞지 않을 때 "전문적인(또는 친근한/유머러스한) 톤으로 다시 써 주세요"
방향은 맞지만 깊이가 부족할 때 "2번 항목을 구체적인 예시를 들어 더 자세히 설명해 주세요"
완전히 다른 방향을 시도할 때 "지금까지와 완전히 다른 접근법으로 처음부터 다시 작성해 주세요"
두 버전 중 선택할 때 "A버전의 구조에 B버전의 톤을 결합해 주세요"
특정 부분만 수정할 때 "나머지는 유지하고 세 번째 문단만 수정해 주세요"

⚠️ 반복 개선의 함정

대화가 길어질수록 AI는 초반 맥락을 잊거나 일관성을 잃을 수 있습니다. 5~7회 이상 수정이 이어진다면 새 대화창을 열고 지금까지의 최선 버전을 기반으로 새 프롬프트를 작성하는 것이 더 효율적입니다.

12.3 도메인별 프롬프트 설계 워크숍

워크숍 소개

각 도메인마다 AI에게 기대하는 결과물의 성격이 다릅니다. 이 절에서는 마케팅 카피, 코드 리뷰, 교육 콘텐츠, 비즈니스 보고서 4가지 도메인의 프롬프트 설계 원칙과 실전 템플릿을 익힙니다.

워크숍 1. 마케팅 카피(Marketing Copy)

핵심 원칙: 감성 + 명확한 타깃 + 강한 행동 유도(CTA, Call To Action)

마케팅 카피에서 AI는 "창의적인 카피라이터"여야 합니다. 브랜드 목소리, 타깃 고객, 핵심 메시지를 명확히 주어야 합니다.

프롬프트 템플릿:

당신은 10년 경력의 디지털 마케팅 카피라이터입니다.

**브랜드 정보:**
- 제품/서비스: [제품명 및 간단한 설명]
- 브랜드 톤: [예: 젊고 활기찬 / 신뢰할 수 있는 전문가 / 친근한 이웃]
- 핵심 가치 제안(USP): [경쟁사와 다른 점]

**타깃 고객:**
- 연령/직업: [예: 30대 직장인]
- 주요 고충(Pain Point): [예: 시간 부족, 복잡한 절차]
- 원하는 것(Desire): [예: 간편함, 시간 절약]

**작성 요청:**
- 채널: [예: 인스타그램 광고 / 이메일 제목 / 랜딩 페이지 헤드라인]
- 분량: [예: 50자 이내 / 3문장]
- CTA 포함: [예: "지금 무료 체험" / "7일 무료 시작"]

위 정보를 바탕으로 [채널]용 카피 3가지 버전을 작성해 주세요.
각 버전은 서로 다른 감성적 접근법을 사용해 주세요.

실전 예시 — 영어 학습 앱 인스타그램 광고:

당신은 10년 경력의 디지털 마케팅 카피라이터입니다.

브랜드 정보:
- 제품: 하루 10분 영어 학습 앱 "퀵잉글리시"
- 브랜드 톤: 바쁜 현대인에게 공감하는 친근한 코치
- USP: 출퇴근 시간만 활용해도 6개월 안에 회화 가능

타깃 고객:
- 연령/직업: 25~35세 직장인
- 고충: 영어 공부하고 싶지만 시간이 없음
- 욕구: 승진, 해외여행 시 자신감

작성 요청:
- 채널: 인스타그램 광고 (이미지 하단 텍스트)
- 분량: 각 버전 40자 이내
- CTA: "지금 무료 시작"

카피 3가지 버전을 작성해 주세요.

워크숍 2. 코드 리뷰(Code Review)

핵심 원칙: 역할 명확화 + 리뷰 기준 제시 + 건설적인 피드백 요청

코드 리뷰에서 AI는 "시니어 개발자"여야 합니다. 단순히 "코드 좀 봐줘"는 표면적인 답변만 돌아옵니다.

프롬프트 템플릿:

당신은 [언어] 개발 경력 10년의 시니어 백엔드 엔지니어입니다.

**리뷰 요청 코드:**
```[언어]
[코드 붙여넣기]

리뷰 기준 (우선순위 순): 1. 버그 및 잠재적 오류 (보안 취약점 포함) 2. 성능 최적화 가능성 3. 가독성 및 유지보수성 4. 코딩 컨벤션 준수 여부

**실전 예시 — 직장인 대상 엑셀 피벗테이블 강의:**

## 12.4 ChatGPT vs Gemini 비교 실습

### 모델별 특성 이해

AI 도구를 효과적으로 쓰려면 각 모델의 특성을 알아야 합니다. 같은 프롬프트라도 모델에 따라 결과가 크게 다를 수 있습니다.

> 📌 **비교 기준 안내**
>
> 아래 비교는 **2026년 5월 기준** 대표 플래그십 모델을 기준으로 정리한 것입니다. 모델 라인업과 컨텍스트 길이, 가격은 매우 빠르게 바뀌므로 실제 사용 시점에 각 공식 문서를 다시 확인하는 것을 권장합니다.

---

### 모델 특성 비교표

| 특성 | **ChatGPT (GPT-5 계열)** | **Gemini (2.5 / 3 계열)** | **Claude (4.5 / Opus 4.7)** |
|---|---|---|---|
| **강점 분야** | 통합 추론, 창의적 글쓰기, 코드 생성 | 멀티모달(이미지·영상), 실시간 검색, 초장문 분석 | 코딩 SOTA, Extended Thinking, 안전한 장문 분석 |
| **컨텍스트 창** | 400K 토큰 내외 | 1M~2M 토큰 | 200K 기본 / Opus 4.5·4.7은 1M 옵션 |
| **인터넷 검색** | 기본 내장(웹 검색) | 기본 내장(Google 검색) | 기본 내장(웹 검색·도구 사용) |
| **한국어 처리** | 자연스러운 한국어 | 한국어 처리 양호, 한국 실시간 정보 강점 | 자연스러운 한국어, 긴 문서 일관성 강함 |
| **코드 작성** | 매우 강함, 코드 인터프리터 내장 | Google 서비스/Colab 연동 유리 | 코딩 벤치마크 1위권, Claude Code 통합 |
| **이미지 생성** | gpt-image-1 등 | Imagen 4, Nano Banana 등 | (Claude.ai에서 외부 모델 연동) |
| **추론 모드** | reasoning_effort 옵션 | Thinking 모드 | Extended Thinking (think hard / ultrathink) |
| **가격 정책** | 유료(Plus/Pro), 무료 GPT-5 mini 제공 | 무료(Gemini), 유료(Advanced) | 유료(Pro/Max), 일부 무료 Sonnet 제공 |
| **특이점** | 시스템 프롬프트·도구 호출 강력 | Workspace·YouTube 등 Google 생태계 | MCP·에이전트 SDK 등 도구 표준화 선도 |

---

### 동일 프롬프트 응답 차이 실험

**실험 프롬프트 1 — 창의적 글쓰기:**

한국의 작은 섬마을을 배경으로 한 단편 소설의 첫 문단을 써줘. 주인공은 30년 만에 고향으로 돌아온 60대 어부입니다. 분위기는 쓸쓸하지만 따뜻한 희망이 느껴지는 방향으로.


| 항목 | ChatGPT 경향 | Gemini 경향 |
|---|---|---|
| **문체** | 섬세한 감성적 묘사, 은유 풍부 | 명확하고 현실적인 묘사 |
| **구조** | 자유로운 문학적 흐름 | 기승전결이 명확한 구성 |
| **언어** | 다채로운 어휘, 시적 표현 | 읽기 편한 평이한 문장 |

**실험 프롬프트 2 — 사실 정보 검색:**

2025년 현재 국내에서 가장 많이 사용되는 생성형 AI 도구 TOP 5를 사용자 수 기준으로 알려줘.


| 항목 | ChatGPT 경향 | Gemini 경향 |
|---|---|---|
| **정보 출처** | 훈련 데이터 기반 (최신성 한계) | Google 실시간 검색 반영 가능 |
| **신뢰도** | 오래된 정보일 수 있음 | 더 최신 정보 제공 가능 |
| **권고** | 최신 정보는 다른 소스 확인 필요 | 뉴스·통계 등 실시간 정보에 유리 |

**실험 프롬프트 3 — 코드 생성:**

Python으로 CSV 파일을 읽어 나이 컬럼 기준으로 평균, 중앙값, 최빈값을 계산하고 막대 그래프로 시각화하는 코드를 작성해 줘.


| 항목 | ChatGPT 경향 | Gemini 경향 |
|---|---|---|
| **코드 품질** | 완성도 높은 코드, 에러 처리 포함 | 간결하고 실용적인 코드 |
| **설명** | 각 코드 블록에 상세 주석 | 핵심 부분만 간략히 설명 |
| **실행 검증** | Code Interpreter로 직접 실행 가능 | 코드 제안 후 확인 필요 |

### 모델 선택 가이드

> 💡 **어떤 모델을 선택해야 할까요? (2026년 기준)**
>
> - **복잡한 코드·리팩토링·에이전트 자동화** → Claude (Sonnet 4.5 / Opus 4.7)
> - **창의적 글쓰기, 멀티모달 통합, 추론 작업** → ChatGPT (GPT-5)
> - **최신 뉴스·정보 검색, 초장문 분석, Google 서비스 연동** → Gemini (2.5 Pro / 3)
> - **일반 업무 자동화, 이메일 작성** → 무료 모델(GPT-5 mini, Gemini, Claude Sonnet) 중 익숙한 것
> - **가장 좋은 방법** → 중요한 작업은 두세 모델에 모두 요청하고 결과를 교차 비교

## 12.5 나만의 프롬프트 템플릿 라이브러리 만들기

### 템플릿 라이브러리가 필요한 이유

좋은 프롬프트를 한 번 만들었다면, 매번 처음부터 다시 작성하는 것은 비효율적입니다. **프롬프트 라이브러리(Prompt Library)**는 자주 사용하는 프롬프트를 카테고리별로 정리한 개인 도구 모음입니다.

라이브러리를 만들면:

- 반복 작업 시간을 80% 이상 단축할 수 있습니다
- 팀원과 공유하여 업무 일관성을 높일 수 있습니다
- 검증된 프롬프트를 기반으로 새 프롬프트를 빠르게 만들 수 있습니다

---

### 템플릿 구조 설계

좋은 템플릿은 **변수(Variable)** 와 **고정 구조(Fixed Structure)** 를 명확히 분리합니다. `[대괄호]`로 채워야 할 변수를, 나머지는 고정 텍스트로 작성합니다.

**표준 템플릿 구조:**

[템플릿 이름]

용도: [언제 사용하는가] 예상 소요 시간: [AI 응답 생성 시간] 버전: v[번호] / 마지막 수정: [날짜]

프롬프트

당신은 [역할]입니다.

맥락: [상황 설명 — 변수 포함]

요청: [구체적인 작업 지시 — 변수 포함]

출력 형식: [형식 지정]

제약 조건: - [제약 1] - [제약 2]

사용 예시

[변수를 실제 값으로 채운 예시 1개]

메모

[이 템플릿 사용 시 주의사항 또는 팁]

## [종합 실습] 실무 시나리오 최적 프롬프트 설계

### 실습 개요

지금까지 배운 모든 것을 종합하여 **실무 시나리오 3개**를 선택하고 최적 프롬프트를 설계합니다. 혼자 또는 팀으로 진행할 수 있습니다.

**실습 절차:**

[1] 시나리오 선택 (아래 6개 중 3개) ↓ [2] 각 시나리오에 맞는 프롬프트 초안 작성 ↓ [3] AI에 실제 적용 및 결과 평가 ↓ [4] 반복 개선 (최소 2회) ↓ [5] 최종 프롬프트를 템플릿으로 정리 ↓ [6] 발표 또는 공유 (팀 실습의 경우)


---

### 실습 시나리오 목록

**시나리오 A. 신입사원 온보딩 교육 자료 제작**

상황: 다음 달 신입사원 5명이 입사합니다. 첫 2주 동안의 온보딩 프로그램 일정표와 첫날 오리엔테이션 발표 자료 개요를 만들어야 합니다.

사용할 기법: 역할 부여 + 형식 지정 + 반복 개선


**시나리오 B. 경쟁사 제품 비교 분석 보고서**

상황: 다음 주 임원 회의에서 경쟁사 3곳의 제품 특징과 가격 정책을 비교한 보고서를 발표해야 합니다. 데이터는 직접 조사한 내용을 AI에 입력합니다.

사용할 기법: 페르소나 부여 + 구조화된 출력 + 표 형식


**시나리오 C. 고객 불만 이메일 대응 템플릿**

상황: 고객 서비스팀이 매일 받는 불만 유형이 5가지로 분류됩니다. 각 유형에 맞는 공감하고 해결책을 제시하는 이메일 템플릿이 필요합니다.

사용할 기법: 퓨샷 예시 + 다중 버전 생성


**시나리오 D. 사내 뉴스레터 콘텐츠 기획**

상황: 월 1회 발행하는 사내 뉴스레터의 편집장이 됐습니다. 이번 달 주제는 "AI 도구 도입 3개월 성과"입니다. 기사 구성안과 각 섹션 초안을 작성해야 합니다.

사용할 기법: 역할 부여 + 단계별 접근 + 반복 개선


**시나리오 E. 팀 회의 어젠다 및 후속 액션 아이템 자동화**

상황: 주간 팀 회의를 더 효율적으로 만들고 싶습니다. 회의 전 어젠다 작성, 회의 중 노트 → 회의록 변환, 회의 후 액션 아이템 추출까지 AI로 자동화합니다.

사용할 기법: 연속 대화 흐름 설계 + 형식 표준화
