24.1 Hugging Face 플랫폼 소개

Hugging Face(허깅 페이스)는 NLP(자연어 처리)를 비롯한 다양한 AI 모델을 공유하고 협업하는 오픈소스 플랫폼입니다. 2016년 설립 이후 빠르게 성장하여 현재 AI 커뮤니티의 핵심 인프라로 자리잡았습니다.

주요 구성 요소

Hugging Face는 크게 세 가지 핵심 서비스로 구성됩니다.

  • Model Hub(모델 허브): 50만 개 이상의 사전 학습 모델이 공개되어 있으며, 텍스트·이미지·오디오 등 다양한 모달리티를 지원합니다.
  • Datasets(데이터셋): 수만 개의 공개 데이터셋을 제공하며, datasets 라이브러리로 손쉽게 로드할 수 있습니다.
  • Spaces(스페이스): Gradio 또는 Streamlit 기반의 AI 데모 앱을 배포하고 공유할 수 있는 호스팅 환경입니다.

왜 Hugging Face를 사용하는가

오픈소스 AI 모델을 처음부터 학습하는 것은 막대한 비용과 시간이 필요합니다. Hugging Face는 이미 학습된 고성능 모델을 몇 줄의 코드만으로 활용할 수 있도록 해 줍니다.

Hugging Face를 활용하면 다음과 같은 이점이 있습니다.

  • 빠른 프로토타이핑: 검증된 모델을 즉시 사용하여 아이디어를 빠르게 검증할 수 있습니다.
  • 비용 절감: 클라우드 LLM API 비용 없이 로컬 또는 자체 서버에서 모델을 실행할 수 있습니다.
  • 커스터마이징: 공개 모델을 파인튜닝하여 도메인 특화 모델을 만들 수 있습니다.
  • 투명성: 오픈소스이므로 모델의 구조와 학습 방법을 직접 확인할 수 있습니다.

24.2 Transformers 라이브러리 사용법

Transformers 라이브러리는 Hugging Face의 핵심 파이썬 라이브러리로, BERT, GPT, T5 등 수백 가지 트랜스포머 기반 모델을 통일된 API로 사용할 수 있게 해 줍니다.

설치

pip install transformers
pip install transformers[torch]    # PyTorch와 함께 설치
pip install transformers[tf]       # TensorFlow와 함께 설치

핵심 구성 요소

Transformers 라이브러리는 세 가지 핵심 클래스를 중심으로 동작합니다.

텍스트 입력 → AutoTokenizer가 토큰 ID로 변환 → AutoModel* 클래스가 임베딩/로짓/생성 토큰을 산출 → 후처리 결과 반환. Auto* 클래스는 모델 ID만으로 적합한 구현을 자동 선택하므로, 동일한 코드로 BERT·GPT·T5·LLaMA·Mistral 등 수백 가지 모델을 다룰 수 있습니다.

1. Tokenizer(토크나이저)

텍스트를 모델이 이해할 수 있는 토큰 ID 시퀀스로 변환합니다.

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

text = "Hello, Hugging Face!"
tokens = tokenizer(text, return_tensors="pt")

print(tokens)
# {'input_ids': tensor([[101, 7592, 1010, 17662, 2227, 999, 102]]),
#  'attention_mask': tensor([[1, 1, 1, 1, 1, 1, 1]])}

2. Model(모델)

사전 학습된 가중치를 로드하고 추론(inference)을 수행합니다.

from transformers import AutoModel, AutoTokenizer
import torch

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")

inputs = tokenizer("Hello, world!", return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

# last_hidden_state: 각 토큰의 임베딩 벡터
print(outputs.last_hidden_state.shape)  # [1, 5, 768]

3. Auto Classes(오토 클래스)

AutoTokenizer, AutoModel, AutoModelForSequenceClassification 등의 Auto 클래스는 모델 이름만으로 적합한 클래스를 자동으로 선택해 줍니다.

from transformers import (
    AutoTokenizer,
    AutoModelForSequenceClassification,
    AutoModelForSeq2SeqLM,
    AutoModelForCausalLM,
)

# 태스크별 적절한 모델 클래스 자동 선택
# 분류 모델
clf_model = AutoModelForSequenceClassification.from_pretrained("distilbert-base-uncased-finetuned-sst-2-english")

# 시퀀스-투-시퀀스 모델 (번역, 요약)
seq2seq_model = AutoModelForSeq2SeqLM.from_pretrained("facebook/bart-large-cnn")

# 인과적 언어 모델 (텍스트 생성)
causal_model = AutoModelForCausalLM.from_pretrained("gpt2")

모델 저장과 로컬 로드

네트워크 없이 사용하거나 반복 실행 시 다운로드 시간을 절약하기 위해 모델을 로컬에 저장할 수 있습니다.

from transformers import AutoTokenizer, AutoModel

model_name = "bert-base-uncased"
save_path = "./local_models/bert-base-uncased"

# 다운로드 및 저장
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModel.from_pretrained(model_name)

tokenizer.save_pretrained(save_path)
model.save_pretrained(save_path)

# 로컬에서 로드
tokenizer = AutoTokenizer.from_pretrained(save_path)
model = AutoModel.from_pretrained(save_path)

24.3 모델 허브에서 모델 검색 및 다운로드

Model Hub(모델 허브)에서는 웹 브라우저와 코드 두 가지 방법으로 모델을 검색하고 다운로드할 수 있습니다.

웹에서 검색하기

https://huggingface.co/models에 접속하면 다음 필터를 활용하여 모델을 탐색할 수 있습니다.

  • Task(태스크): Text Classification, Summarization, Translation, Question Answering 등
  • Library(라이브러리): Transformers, PyTorch, TensorFlow 등
  • Language(언어): 한국어(ko), 영어(en) 등 특정 언어 필터링
  • License(라이선스): Apache 2.0, MIT 등 상업적 이용 가능 여부 확인

huggingface_hub 라이브러리로 검색하기

from huggingface_hub import HfApi

api = HfApi()

# 한국어 텍스트 분류 모델 검색
models = api.list_models(
    filter="text-classification",
    language="ko",
    sort="downloads",
    direction=-1,   # 내림차순 (다운로드 많은 순)
    limit=10,
)

for model in models:
    print(f"{model.id} - Downloads: {model.downloads}")

모델 카드(Model Card) 확인

모델을 사용하기 전에 반드시 Model Card(모델 카드)를 확인하는 것이 좋습니다. 모델 카드에는 다음 정보가 담겨 있습니다.

  • 모델의 학습 데이터와 방법론
  • 성능 벤치마크 결과
  • 라이선스 및 사용 제한 사항
  • 편향성(bias)과 한계에 대한 설명

24.4 Pipeline API로 간편하게 모델 사용하기

Pipeline API는 복잡한 전처리·추론·후처리 과정을 한 줄의 코드로 처리할 수 있는 고수준 인터페이스입니다. 다양한 NLP 태스크를 빠르게 실험하고 프로토타이핑하는 데 최적화되어 있습니다.

Pipeline 기본 사용법

from transformers import pipeline

# 태스크 이름만으로 파이프라인 생성 (기본 모델 자동 선택)
classifier = pipeline("text-classification")
result = classifier("I love using Hugging Face!")
print(result)  # [{'label': 'POSITIVE', 'score': 0.9998}]

텍스트 분류 (Text Classification)

텍스트 분류(Text Classification)는 입력 텍스트에 카테고리 레이블을 부여하는 태스크입니다. 감성 분석이 대표적인 예입니다.

from transformers import pipeline

# 감성 분석
sentiment = pipeline(
    "text-classification",
    model="snunlp/KR-FinBert-SC",  # 한국어 금융 감성 분석 모델
    device=0,  # GPU 사용 (CPU는 -1)
)

texts = [
    "이 제품 정말 훌륭해요! 강력 추천합니다.",
    "배송이 너무 늦고 품질도 실망스럽네요.",
    "가격 대비 무난한 것 같습니다.",
]

results = sentiment(texts)
for text, result in zip(texts, results):
    print(f"텍스트: {text}")
    print(f"  레이블: {result['label']}, 점수: {result['score']:.4f}\n")

다중 레이블 분류 및 제로샷 분류(Zero-shot Classification)도 지원합니다.

# 제로샷 분류: 학습 데이터 없이 임의 레이블로 분류
zero_shot = pipeline("zero-shot-classification", model="facebook/bart-large-mnli")

result = zero_shot(
    "오늘 코스피가 2% 상승하며 강세를 보였습니다.",
    candidate_labels=["경제", "스포츠", "정치", "문화"],
)

print(result["labels"])  # ['경제', '정치', '문화', '스포츠']
print(result["scores"])  # [0.92, 0.04, 0.03, 0.01]

텍스트 요약 (Summarization)

텍스트 요약(Summarization)은 긴 문서를 짧은 핵심 내용으로 압축하는 태스크입니다.

from transformers import pipeline

summarizer = pipeline(
    "summarization",
    model="facebook/bart-large-cnn",
    device=0,
)

article = """
The tower is 324 metres (1,063 ft) tall, about the same height as an 81-storey building, 
and the tallest structure in Paris. Its base is square, measuring 125 metres (410 ft) on each side. 
During its construction, the Eiffel Tower surpassed the Washington Monument to become the tallest 
man-made structure in the world, a title it held for 41 years until the Chrysler Building in New York 
City was finished in 1930. It was the first structure in the world to reach a height of 300 metres. 
Due to the addition of a broadcasting aerial at the top of the tower in 1957, it is now taller than 
the Chrysler Building by 5.2 metres (17 ft).
"""

summary = summarizer(
    article,
    max_length=130,
    min_length=30,
    do_sample=False,
)

print(summary[0]["summary_text"])
# The Eiffel Tower is 324 metres tall, about the same height as an 81-storey building.
# It is the tallest structure in Paris and was the first structure to reach 300 metres.

번역 (Translation)

번역(Translation)은 소스 언어 텍스트를 타겟 언어로 변환하는 태스크입니다.

from transformers import pipeline

# 영어 → 한국어 번역
translator = pipeline(
    "translation",
    model="Helsinki-NLP/opus-mt-en-ko",
)

texts = [
    "Artificial intelligence is transforming every industry.",
    "Machine learning models can now understand human language.",
]

translations = translator(texts)
for original, translated in zip(texts, translations):
    print(f"원문: {original}")
    print(f"번역: {translated['translation_text']}\n")

다국어 모델(Multilingual Model)을 사용하면 다양한 언어 쌍을 하나의 모델로 처리할 수 있습니다.

# Helsinki-NLP/opus-mt-tc-big-ko-en: 한국어 → 영어
ko_en_translator = pipeline(
    "translation",
    model="Helsinki-NLP/opus-mt-tc-big-ko-en",
)

result = ko_en_translator("인공지능은 미래를 바꾸고 있습니다.")
print(result[0]["translation_text"])
# Artificial intelligence is changing the future.

질의응답 (Question Answering)

질의응답(Question Answering, QA)은 주어진 컨텍스트(지문)에서 질문에 대한 답을 추출하는 태스크입니다.

from transformers import pipeline

qa = pipeline(
    "question-answering",
    model="deepset/roberta-base-squad2",
)

context = """
Hugging Face was founded in 2016 by Clément Delangue, Julien Chaumond, and Thomas Wolf.
The company is headquartered in New York City and Paris. Hugging Face is known for its 
Transformers library, which provides thousands of pretrained models for natural language 
processing, computer vision, and audio tasks.
"""

questions = [
    "When was Hugging Face founded?",
    "Where is Hugging Face headquartered?",
    "What is Hugging Face known for?",
]

for question in questions:
    result = qa(question=question, context=context)
    print(f"질문: {question}")
    print(f"답변: {result['answer']} (신뢰도: {result['score']:.4f})\n")

텍스트 생성 (Text Generation)

텍스트 생성(Text Generation)은 입력 프롬프트를 이어받아 자연스러운 텍스트를 생성하는 태스크입니다.

from transformers import pipeline

generator = pipeline(
    "text-generation",
    model="gpt2",
    device=0,
)

prompt = "Once upon a time in a land far away,"

outputs = generator(
    prompt,
    max_new_tokens=100,
    num_return_sequences=2,    # 2개의 다양한 결과 생성
    temperature=0.8,           # 창의성 조절 (높을수록 다양)
    do_sample=True,
    pad_token_id=50256,
)

for i, output in enumerate(outputs, 1):
    print(f"[결과 {i}]")
    print(output["generated_text"])
    print()

Pipeline 공통 매개변수

매개변수 설명 기본값
model 사용할 모델 이름 또는 경로 태스크별 기본 모델
device 실행 디바이스 (0=GPU, -1=CPU) -1
batch_size 배치 크기 (처리 속도 향상) 1
max_length 출력 최대 토큰 수 모델별 상이
truncation 입력이 최대 길이 초과 시 자르기 False

LLaMA (라마)

LLaMA(Large Language Model Meta AI)는 Meta에서 개발한 오픈소스 LLM 시리즈입니다.

from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_id = "meta-llama/Meta-Llama-3.1-8B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,   # 메모리 절약
    device_map="auto",             # GPU/CPU 자동 배분
)

messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "파이썬에서 리스트 컴프리헨션이란 무엇인가요?"},
]

input_ids = tokenizer.apply_chat_template(
    messages,
    add_generation_prompt=True,
    return_tensors="pt",
).to(model.device)

outputs = model.generate(
    input_ids,
    max_new_tokens=512,
    temperature=0.7,
    do_sample=True,
)

response = tokenizer.decode(outputs[0][input_ids.shape[-1]:], skip_special_tokens=True)
print(response)

LLaMA 3.1 모델은 Hugging Face에서 다운로드하려면 Meta의 라이선스 동의가 필요합니다. huggingface-cli login 명령으로 토큰을 설정한 후 사용하세요.

Mistral / Mixtral (미스트랄 / 믹스트랄)

Mistral 7B은 7B 파라미터임에도 13B 모델에 필적하는 성능을 보이며 Apache 2.0 라이선스로 상업적 이용이 가능합니다. Mixtral 8x7B은 MoE(Mixture of Experts) 아키텍처를 사용하여 8개의 전문가 네트워크 중 2개를 선택적으로 활성화함으로써 효율성을 극대화합니다.

from transformers import pipeline
import torch

# Mistral Instruct 모델로 대화
pipe = pipeline(
    "text-generation",
    model="mistralai/Mistral-7B-Instruct-v0.3",
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

messages = [{"role": "user", "content": "머신러닝과 딥러닝의 차이점을 설명해 주세요."}]

output = pipe(messages, max_new_tokens=256)
print(output[0]["generated_text"][-1]["content"])

Gemma는 Google DeepMind가 Gemini 기술을 기반으로 개발한 경량 오픈소스 모델입니다. 2B, 9B, 27B 크기로 제공되며 특히 소형 모델에서 뛰어난 성능을 발휘합니다.

Phi (파이)

Phi는 Microsoft Research에서 개발한 소형 언어 모델 시리즈입니다. Phi-4는 14B 파라미터로 GPT-3.5 수준의 추론 능력을 달성했으며, MIT 라이선스로 완전한 상업적 활용이 가능합니다.

from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_id = "microsoft/phi-4"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

inputs = tokenizer(
    "<|user|>\n수학 문제를 풀어 주세요: 2x + 5 = 15, x는?\n<|assistant|>\n",
    return_tensors="pt",
).to(model.device)

outputs = model.generate(**inputs, max_new_tokens=256)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

Qwen (치엔)

Qwen(Qianwen, 千問)은 Alibaba Cloud에서 개발한 다국어 LLM 시리즈입니다. Qwen 2.5는 0.5B부터 72B까지 다양한 크기로 제공되며, 한국어를 포함한 29개 언어에서 뛰어난 성능을 보입니다.

from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "Qwen/Qwen2.5-7B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype="auto",
    device_map="auto",
)

messages = [
    {"role": "system", "content": "당신은 유용한 AI 어시스턴트입니다."},
    {"role": "user", "content": "한국의 전통 음식 5가지를 소개해 주세요."},
]

text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)

inputs = tokenizer([text], return_tensors="pt").to(model.device)
outputs = model.generate(**inputs, max_new_tokens=512)

response = tokenizer.decode(outputs[0][inputs.input_ids.shape[-1]:], skip_special_tokens=True)
print(response)

from transformers import pipeline

def analyze_text(text: str, lang: str = "ko") -> dict:
    """텍스트를 분석하여 감성, 키워드 등을 반환하는 함수."""

    results = {}

    # 1단계: 제로샷 분류로 주제 파악
    topic_classifier = pipeline(
        "zero-shot-classification",
        model="facebook/bart-large-mnli",
        device=-1,
    )

    topic_result = topic_classifier(
        text,
        candidate_labels=["경제/비즈니스", "기술/IT", "사회/문화", "스포츠", "정치"],
    )
    results["topic"] = topic_result["labels"][0]
    results["topic_score"] = round(topic_result["scores"][0], 4)

    # 2단계: 영문 번역 후 요약 (한국어 모델 제한 극복)
    if lang == "ko":
        translator = pipeline(
            "translation",
            model="Helsinki-NLP/opus-mt-ko-en",
            device=-1,
        )
        translated = translator(text)[0]["translation_text"]
    else:
        translated = text

    summarizer = pipeline("summarization", model="facebook/bart-large-cnn", device=-1)
    if len(translated.split()) > 30:
        summary = summarizer(translated, max_length=50, min_length=10, do_sample=False)
        results["summary"] = summary[0]["summary_text"]
    else:
        results["summary"] = translated

    return results


# 테스트 실행
test_text = """
삼성전자가 3나노 공정 기반의 차세대 AI 반도체 개발에 성공했다고 발표했습니다.
이 칩은 기존 대비 30% 향상된 성능과 25% 낮은 전력 소비를 실현하며,
2025년 하반기부터 스마트폰과 데이터센터용 AI 가속기에 탑재될 예정입니다.
"""

print("텍스트 통합 분석 시작...")
analysis = analyze_text(test_text, lang="ko")
print(f"\n주제: {analysis['topic']} (신뢰도: {analysis['topic_score']})")
print(f"요약: {analysis['summary']}")

25.1 로컬 LLM 실행의 의의 — 비용, 프라이버시, 오프라인

로컬 LLM(Local LLM)이란 OpenAI, Anthropic 등 외부 서버를 거치지 않고 자신의 하드웨어에서 직접 실행하는 언어 모델을 말합니다. 클라우드 API가 편리하지만, 로컬 실행이 더 나은 선택인 경우가 분명히 존재합니다.

비용 절감

클라우드 API는 토큰(token) 단위로 과금됩니다. 프로토타이핑 단계나 대용량 텍스트를 반복 처리할 때는 비용이 빠르게 누적됩니다. 로컬 LLM은 초기 하드웨어 비용만 지불하면 이후 사용량에 따른 추가 비용이 없습니다.

프라이버시와 보안

금융 데이터, 의료 기록, 내부 문서 등 민감한 정보를 외부 서버로 전송할 수 없는 경우가 많습니다. 로컬 LLM은 데이터가 자신의 장비를 벗어나지 않으므로 데이터 컴플라이언스(data compliance) 요구사항을 충족하기 훨씬 유리합니다.

오프라인 환경

인터넷이 불안정하거나 차단된 환경(보안 시설, 원격지, 항공기 내 등)에서도 AI 기능을 제공할 수 있습니다. 한 번 모델을 내려받으면 네트워크 없이도 완전하게 동작합니다.

모델 커스터마이징

클라우드 API는 제공자가 정해놓은 모델만 사용할 수 있지만, 로컬 환경에서는 파인튜닝(fine-tuning)된 전용 모델이나 특수 목적 모델을 자유롭게 교체할 수 있습니다.

정리: 로컬 LLM은 비용, 보안, 가용성, 유연성 네 가지 측면에서 클라우드 API와 상호 보완적인 관계입니다. 두 방식을 상황에 맞게 선택하는 것이 핵심입니다.

25.2 하드웨어 요구사항 (GPU, RAM, VRAM)

로컬 LLM의 성능은 하드웨어에 직결됩니다. 모델 크기와 실행 방식에 따라 요구사항이 크게 달라집니다.

모델 크기와 파라미터

파라미터(parameter) 수는 모델 크기를 나타내는 주요 지표입니다. 일반적으로 다음과 같이 분류합니다.

양자화(Quantization)

양자화(quantization)는 모델의 가중치를 더 낮은 정밀도로 압축해 메모리 사용량을 줄이는 기법입니다. 품질을 약간 희생하는 대신 훨씬 적은 VRAM으로 큰 모델을 실행할 수 있습니다.

양자화 형식 설명 메모리 절감 품질 손실
FP32 32비트 부동소수점 (원본) 기준 없음
FP16 / BF16 16비트 부동소수점 ~50% 거의 없음
GGUF Q8 8비트 양자화 ~75% 매우 낮음
GGUF Q4 4비트 양자화 ~87% 낮음
GGUF Q2 2비트 양자화 ~93% 중간

실용 팁: 일반적으로 Q4_K_M 또는 Q5_K_M 형식이 품질과 메모리 효율의 균형이 가장 좋습니다.

7B 모델을 기준으로 양자화를 적용하면 FP32 대비 메모리를 최대 87% 절감(28GB → 4GB)할 수 있으며, 품질 손실은 약 12%p 수준에 그칩니다. 8GB VRAM에서 7B 모델을 실행하려면 Q4_K_M, 12GB 이상이면 Q5_K_M을 권장합니다.

CPU vs GPU 실행

  • GPU 실행: VRAM(Video RAM)에 모델을 올려 병렬 처리하므로 속도가 빠릅니다. NVIDIA GPU는 CUDA, AMD GPU는 ROCm을 활용합니다.
  • CPU 실행: GPU가 없어도 시스템 RAM을 이용해 실행 가능합니다. 속도는 느리지만 접근성이 높습니다.
  • 하이브리드: 일부 레이어는 GPU VRAM에, 나머지는 RAM에 올리는 혼합 방식도 지원합니다.

Python으로 API 호출

import requests
import json

def chat_with_ollama(prompt: str, model: str = "llama3.2") -> str:
    """Ollama REST API를 통해 모델과 대화합니다."""
    url = "http://localhost:11434/api/generate"

    payload = {
        "model": model,
        "prompt": prompt,
        "stream": False  # 스트리밍 비활성화로 전체 응답 한 번에 수신
    }

    response = requests.post(url, json=payload)
    response.raise_for_status()

    return response.json()["response"]

# 사용 예시
answer = chat_with_ollama("파이썬 리스트와 튜플의 차이점은?")
print(answer)

스트리밍 응답 처리

import requests
import json

def stream_chat(prompt: str, model: str = "llama3.2"):
    """응답을 실시간으로 스트리밍합니다."""
    url = "http://localhost:11434/api/generate"

    payload = {
        "model": model,
        "prompt": prompt,
        "stream": True  # 스트리밍 활성화
    }

    with requests.post(url, json=payload, stream=True) as response:
        for line in response.iter_lines():
            if line:
                chunk = json.loads(line)
                print(chunk["response"], end="", flush=True)
                if chunk.get("done"):
                    break
    print()  # 줄바꿈

# 실행
stream_chat("머신러닝과 딥러닝의 차이를 설명해주세요.")

25.7 로컬 모델을 기존 앱에 연결하기

로컬 LLM의 진가는 기존 애플리케이션과 연동할 때 발휘됩니다. OpenAI 호환 API 덕분에 기존 코드를 거의 수정하지 않고도 로컬 모델로 전환할 수 있습니다.

LangChain과 연동

LangChain은 Ollama를 공식 지원합니다.

from langchain_ollama import OllamaLLM
from langchain_core.prompts import ChatPromptTemplate

# Ollama 모델 초기화
llm = OllamaLLM(model="llama3.2")

# 프롬프트 템플릿 정의
prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 {topic} 전문가입니다."),
    ("human", "{question}")
])

# 체인 구성
chain = prompt | llm

# 실행
response = chain.invoke({
    "topic": "파이썬",
    "question": "데코레이터 패턴을 설명해주세요."
})
print(response)

환경 변수로 API 전환

운영 환경에 따라 클라우드 API와 로컬 LLM을 유연하게 전환하는 패턴입니다.

import os
from openai import OpenAI

# 환경 변수로 백엔드 선택
USE_LOCAL = os.getenv("USE_LOCAL_LLM", "false").lower() == "true"

    client = OpenAI(
        base_url="http://localhost:11434/v1",
        api_key="ollama"
    )
    MODEL = "llama3.2"
else:
    client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
    MODEL = "gpt-4o-mini"

def ask(question: str) -> str:
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": question}]
    )
    return response.choices[0].message.content

# USE_LOCAL_LLM=true python app.py 로 로컬 모드 실행
print(ask("파이썬이란 무엇인가요?"))

생성형 AI 분야는 매우 빠르게 변화하고 있습니다. 현재 가장 주목받는 세 가지 방향을 살펴봅니다.

AI 에이전트 (AI Agent)

AI 에이전트(AI Agent) 는 단순히 질문에 답하는 것을 넘어, 스스로 계획을 세우고 도구를 사용하여 복잡한 작업을 수행하는 시스템입니다.

에이전트는 "지시를 따르는 AI"가 아니라 "목표를 향해 스스로 행동하는 AI"입니다. 사용자가 "여행 계획을 짜줘"라고 하면, 에이전트는 웹 검색, 일정 확인, 예약 시스템 호출 등을 자율적으로 수행합니다.

핵심 구성 요소:

  • 계획(Planning): 큰 목표를 작은 하위 작업으로 분해합니다.
  • 메모리(Memory): 단기(대화 히스토리)와 장기(외부 데이터베이스) 기억을 활용합니다.
  • 도구 사용(Tool Use): 웹 검색, 코드 실행, API 호출 등 외부 도구를 활용합니다.
  • 행동(Action): 계획에 따라 실제 작업을 실행합니다.

멀티모달 AI (Multimodal AI)

멀티모달(Multimodal) AI는 텍스트, 이미지, 음성, 영상 등 여러 형태의 입력을 통합적으로 이해하고 생성합니다.

현재 주요 멀티모달 능력:

  • 이미지를 보고 텍스트로 설명하기 (Image Captioning)
  • 텍스트 설명으로 이미지 생성하기 (Text-to-Image)
  • 음성을 텍스트로, 텍스트를 음성으로 변환하기 (STT/TTS)
  • 영상을 분석하고 요약하기 (Video Understanding)

GPT-4o, Gemini 1.5 Pro, Claude 3.5 Sonnet 등은 이미 텍스트와 이미지를 함께 처리합니다. 앞으로는 실시간 음성·영상 상호작용이 일반화될 것으로 전망됩니다.

소형 언어 모델 (SLM, Small Language Model)

SLM(Small Language Model) 은 수십억 파라미터 규모의 작은 모델로, 특정 영역에 특화되어 높은 성능을 냅니다.

"작지만 강하다" — SLM은 모든 것을 잘하는 거대 모델 대신, 특정 분야에서 GPT-4 수준의 성능을 훨씬 적은 자원으로 달성하는 것을 목표로 합니다.

SLM의 장점:

  • 엣지 디바이스(스마트폰, IoT)에서 실행 가능
  • 응답 속도가 빠르고 비용이 낮음
  • 특정 도메인 데이터로 파인튜닝 시 뛰어난 성능
  • 개인정보 보호 강화 (데이터가 외부로 나가지 않음)

생성형 AI의 주요 윤리 이슈

1. 환각(Hallucination) 문제

LLM은 사실이 아닌 내용을 마치 사실인 것처럼 생성할 수 있습니다. 이를 환각(Hallucination) 이라고 합니다.

AI가 생성한 정보를 그대로 신뢰하지 마십시오. 특히 의료, 법률, 금융 분야에서는 반드시 전문가의 검증이 필요합니다.

대응 방법:

  • RAG를 활용해 신뢰할 수 있는 문서 기반으로 답변 생성
  • 출처 명시를 프롬프트에 요구
  • 중요한 정보는 외부 소스에서 직접 확인

2. 편향(Bias) 문제

LLM은 학습 데이터에 존재하는 편향을 그대로 학습합니다. 성별, 인종, 문화적 편향이 출력에 반영될 수 있습니다.

대응 방법:

  • 다양한 관점을 요청하는 프롬프트 설계
  • 출력 결과의 편향 여부를 주기적으로 검토
  • 편향 탐지 도구 활용

3. 저작권과 데이터 프라이버시

  • AI가 생성한 콘텐츠의 저작권 귀속은 아직 법적으로 명확하지 않습니다.
  • 개인정보가 포함된 데이터를 외부 API에 전송하는 것은 개인정보보호법 위반 소지가 있습니다.
  • 기업 기밀을 공개 AI 서비스에 입력하지 않도록 주의합니다.

4. AI 생성 콘텐츠 표시 의무

AI가 작성하거나 생성한 콘텐츠임을 명시하는 것이 투명성과 신뢰를 높입니다. 일부 국가와 플랫폼에서는 이를 의무화하고 있습니다.

책임 있는 AI 개발 원칙

원칙 내용
투명성(Transparency) AI 사용 여부와 작동 방식을 명확히 공개합니다.
공정성(Fairness) 특정 집단에 불이익을 주는 편향을 최소화합니다.
안전성(Safety) 악의적 사용을 방지하는 가드레일을 설계합니다.
책임성(Accountability) AI 출력의 결과에 대한 책임 소재를 명확히 합니다.
프라이버시(Privacy) 개인정보를 수집·처리할 때 동의와 최소화 원칙을 따릅니다.

26.5 개인 프로젝트 진행

이 책에서 배운 기술을 활용해 직접 프로젝트를 완성해 봅니다. 실제로 만들어보는 것이 가장 강력한 학습 방법입니다.

주제 선정 가이드라인

좋은 프로젝트 주제의 조건은 다음과 같습니다.

1. 나에게 의미 있는 문제를 선택합니다.

관심 없는 주제는 오래 지속하기 어렵습니다. 일상에서 불편함을 느끼거나 반복적으로 하는 작업 중에서 AI로 해결할 수 있는 것을 찾습니다.

2. 범위를 명확히 제한합니다.

처음부터 큰 시스템을 만들려 하면 완성하지 못합니다. MVP(Minimum Viable Product), 즉 핵심 기능만 담은 최소 기능 제품으로 시작합니다.

3. 기술 스택을 현재 수준에 맞춥니다.

수준 추천 기술 스택
입문 Streamlit + OpenAI API
중급 FastAPI + LangChain + Chroma
고급 FastAPI + LangGraph + Pinecone + 클라우드 배포

프로젝트 아이디어 예시:

아이디어 핵심 기술 예상 구현 기간
나만의 논문 요약봇 RAG + PDF 파싱 1~2주
고객 리뷰 감성 분석 대시보드 LLM + Streamlit 1주
회사 내부 문서 Q&A 챗봇 RAG + FastAPI 2~3주
코드 리뷰 자동화 도구 OpenAI API + GitHub API 2주
개인 일기 분석 및 감정 트래킹 LLM + 데이터 시각화 2주
특정 도메인 뉴스 요약 뉴스레터 LLM + 스케줄러 1~2주

프로젝트 기획서 작성법

프로젝트를 시작하기 전에 반드시 기획서를 작성합니다. 한 페이지 분량으로 충분합니다.

기획서 필수 항목:

1. 프로젝트 제목
   - 한 문장으로 설명할 수 있는 이름

2. 문제 정의 (Problem Statement)
   - 어떤 문제를 해결하는가?
   - 왜 이 문제가 중요한가?

3. 대상 사용자 (Target User)
   - 누가 이 서비스를 사용하는가?

4. 핵심 기능 (Core Features) — 최대 3가지
   - 기능 1: 설명
   - 기능 2: 설명
   - 기능 3: 설명

5. 기술 스택 (Tech Stack)
   - LLM 모델: (예: GPT-4o-mini)
   - 프레임워크: (예: LangChain)
   - 프론트엔드: (예: Streamlit)
   - 데이터 저장: (예: Chroma)

6. 성공 지표 (Success Metrics)
   - 어떻게 되었을 때 성공인가?

7. 일정 (Timeline)
   - 1주차: 설계 및 환경 구축
   - 2주차: 핵심 기능 구현
   - 3주차: 테스트 및 개선
   - 4주차: 배포 및 발표 준비

구현 → 테스트 → 배포 사이클

구현 단계:

# 1. 먼저 동작하게 (Make it work)
# 2. 그다음 올바르게 (Make it right)
# 3. 마지막으로 빠르게 (Make it fast)

  • 하루에 하나씩 작은 기능을 완성하는 방식으로 진행합니다.
  • 코드를 짤 때마다 Git 커밋으로 기록을 남깁니다.

26.6 프로젝트 발표 및 피드백

프로젝트를 완성했다면, 다른 사람에게 발표하고 피드백을 받는 과정이 매우 중요합니다.

발표 구성 가이드

발표는 10분 기준으로 다음과 같이 구성합니다:

파트 시간 내용
문제 제기 1분 왜 이 프로젝트를 만들었는가?
데모 시연 4분 실제 작동하는 화면을 보여줍니다.
기술 설명 3분 어떤 기술을 어떻게 활용했는가?
배운 점과 한계 1분 무엇을 배웠고, 무엇이 아쉬운가?
Q&A 1분 질문에 답합니다.

발표에서 가장 중요한 것은 "완벽한 코드"가 아니라 "문제를 이해하고 해결하려 한 과정"입니다. 실패와 시행착오도 훌륭한 발표 내용이 됩니다.

피드백 받는 법

좋은 피드백을 이끌어내는 질문:

  • "이 기능 중 가장 유용하다고 생각하는 것은 무엇입니까?"
  • "사용하면서 불편하거나 헷갈리는 부분이 있었습니까?"
  • "이 서비스가 실제로 도움이 될 것 같습니까? 그렇다면/아니라면 왜입니까?"
  • "추가하면 좋겠다고 생각하는 기능이 있습니까?"

피드백을 받을 때 주의할 점:

  1. 방어적으로 반응하지 않습니다. 비판은 개선의 기회입니다.
  2. 모든 피드백을 다 반영할 필요는 없습니다. 프로젝트의 방향에 맞는 것을 선택합니다.
  3. 피드백을 기록해 두고, 우선순위를 정해 다음 버전에 반영합니다.

프로젝트 이후 성장 방법

  • 포트폴리오 페이지 를 만들어 프로젝트를 문서화합니다.
  • GitHub README 에 프로젝트 설명, 설치 방법, 데모 링크를 작성합니다.
  • 기술 블로그 에 개발 과정에서 만난 문제와 해결법을 공유합니다.
  • 피드백을 반영해 버전 2.0 으로 발전시킵니다.

[최종 프로젝트] 기획 → 구현 → 발표

머신러닝의 기초 개념을 이해하고, 딥러닝의 원리를 파악하고, 생성형 AI가 어떻게 작동하는지 배웠습니다. 프롬프트를 설계하고, API를 호출하고, 문서를 벡터로 변환하고, 그것을 검색해 답변을 생성하는 RAG 파이프라인을 직접 만들었습니다. 웹 애플리케이션으로 실제 서비스처럼 포장하고, 인터넷 없이도 내 컴퓨터에서 모델을 실행하는 방법까지 익혔습니다.

이 모든 것이 1~2년 전만 해도 AI 전문가들의 전유물이었습니다. 지금 여러분은 그 영역에 발을 내딛었습니다.

중요한 것은 "완벽하게 이해했는가"가 아닙니다. "직접 만들어봤는가"입니다. 코드를 한 줄이라도 직접 실행해보고, 에러를 만나고, 그것을 해결해본 경험이 진짜 배움입니다.

AI 기술은 계속 발전합니다. 오늘 배운 것이 6개월 뒤에는 바뀔 수 있습니다. 하지만 변하지 않는 것이 있습니다. 문제를 정의하는 능력, 적절한 도구를 찾아 적용하는 능력, 그리고 배운 것을 실제로 만들어내는 능력입니다. 이 책을 통해 그 기반을 닦았습니다.

이제 여러분의 차례입니다. 작은 프로젝트 하나를 시작해 보십시오. 완벽하지 않아도 됩니다. 누군가에게 유용하지 않아도 됩니다. 그냥 만들어보십시오. 그 경험이 다음 프로젝트를, 그리고 그다음 성장을 이끌어 줄 것입니다.

이 책을 끝까지 함께해 주셔서 진심으로 감사합니다. 여러분의 AI 여정은 이제 막 시작되었습니다.
