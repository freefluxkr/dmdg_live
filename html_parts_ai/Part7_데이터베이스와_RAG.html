19.1 데이터베이스의 개념과 종류

데이터베이스(Database, DB)란 데이터를 구조화하여 저장하고, 효율적으로 검색·수정·삭제할 수 있도록 관리하는 시스템입니다. 데이터베이스를 관리하는 소프트웨어를 DBMS(Database Management System)라고 합니다.

데이터베이스는 크게 관계형 데이터베이스(RDBMS)와 NoSQL 데이터베이스로 나뉩니다.

관계형 데이터베이스 (RDBMS)

관계형 데이터베이스(Relational Database Management System)는 데이터를 행(row)과 열(column)로 이루어진 테이블 형태로 저장합니다. 테이블 간의 관계를 정의하여 데이터 중복을 줄이고 일관성을 유지합니다. SQL을 사용하여 데이터를 조작합니다.

대표적인 RDBMS로는 MySQL, PostgreSQL, Oracle, SQLite, MariaDB 등이 있습니다.

NoSQL 데이터베이스

NoSQL(Not Only SQL)은 관계형 모델을 따르지 않는 다양한 형태의 데이터베이스를 통칭합니다. 대용량 비정형 데이터 처리에 적합하며 수평 확장이 용이합니다.

적합한 용도 정형 데이터, 복잡한 관계 대용량, 비정형 데이터

💡 어떤 DB를 선택해야 할까? 트랜잭션이 중요하고 데이터 관계가 복잡하다면 RDBMS, 빠른 읽기/쓰기와 유연한 구조가 필요하다면 NoSQL을 고려하세요. 실제 프로젝트에서는 두 가지를 혼합하여 사용하기도 합니다.

19.2 관계형 데이터베이스 구조

관계형 데이터베이스의 핵심 구성 요소를 이해하면 SQL을 훨씬 쉽게 배울 수 있습니다.

테이블 (Table)

테이블(Table)은 관계형 데이터베이스의 기본 저장 단위입니다. 스프레드시트의 시트와 유사하게 행과 열로 데이터를 저장합니다. 하나의 데이터베이스는 여러 개의 테이블로 구성됩니다.

예를 들어, 쇼핑몰 데이터베이스에는 users(회원), products(상품), orders(주문) 등의 테이블이 있을 수 있습니다.

행과 열 (Row & Column)

행(Row)은 하나의 데이터 레코드를 의미합니다. users 테이블에서 한 행은 한 명의 회원 정보를 나타냅니다. 열(Column)은 데이터의 속성(필드)을 의미합니다. 이름, 이메일, 가입일 등이 열에 해당합니다.

id name email created_at
1 홍길동 hong@example.com 2024-01-15
2 김철수 kim@example.com 2024-02-20
3 이영희 lee@example.com 2024-03-10

키 (Key)

키(Key)는 테이블에서 행을 식별하거나 테이블 간의 관계를 정의하는 데 사용됩니다.

기본 키(Primary Key, PK)는 테이블에서 각 행을 고유하게 식별하는 열입니다. 중복될 수 없고 NULL 값을 가질 수 없습니다. 위 예시의 id 열이 기본 키입니다.

외래 키(Foreign Key, FK)는 다른 테이블의 기본 키를 참조하는 열입니다. 테이블 간의 관계를 정의합니다. orders 테이블의 user_id가 users 테이블의 id를 참조하는 외래 키가 됩니다.

📌 스키마(Schema)란? 스키마는 데이터베이스의 구조를 정의하는 설계도입니다. 테이블 이름, 각 열의 이름과 데이터 타입, 제약 조건, 테이블 간의 관계 등을 포함합니다.

19.4 SQL 기초 문법 - SELECT, INSERT, UPDATE, DELETE

SQL의 데이터 조작 언어(DML)의 핵심 4가지 명령어를 CRUD라고도 합니다. Create(INSERT), Read(SELECT), Update(UPDATE), Delete(DELETE)를 의미합니다.

실습을 위해 먼저 샘플 데이터를 삽입합니다.

INSERT INTO users (name, email, age) VALUES
('홍길동', 'hong@example.com', 28),
('김철수', 'kim@example.com', 35),
('이영희', 'lee@example.com', 24),
('박민준', 'park@example.com', 42),
('최수진', 'choi@example.com', 31);

SELECT - 데이터 조회

SELECT는 테이블에서 데이터를 조회하는 명령어입니다.

-- 모든 열 조회
SELECT * FROM users;

-- 특정 열만 조회
SELECT name, email FROM users;

-- 열에 별칭(Alias) 지정
SELECT name AS 이름, email AS 이메일 FROM users;

INSERT - 데이터 삽입

INSERT INTO는 테이블에 새로운 행을 추가합니다.

-- 단일 행 삽입
INSERT INTO users (name, email, age)
VALUES ('정다은', 'jung@example.com', 27);

-- AUTO_INCREMENT 열(id)은 생략해도 자동으로 값이 부여됩니다

UPDATE - 데이터 수정

UPDATE는 기존 데이터를 수정합니다.

-- 특정 사용자의 나이 수정
UPDATE users
SET age = 29
WHERE name = '홍길동';

-- 여러 열 동시 수정
UPDATE users
SET age = 36, email = 'kim_new@example.com'
WHERE id = 2;

⚠️ WHERE 절 없이 UPDATE 금지 WHERE 절 없이 UPDATE를 실행하면 테이블의 모든 행이 수정됩니다. 반드시 조건을 지정하는 습관을 들이세요.

DELETE - 데이터 삭제

DELETE는 테이블에서 행을 삭제합니다.

-- 특정 행 삭제
DELETE FROM users WHERE id = 6;

-- 조건에 맞는 여러 행 삭제
DELETE FROM users WHERE age > 40;

⚠️ WHERE 절 없이 DELETE 금지 WHERE 절 없이 DELETE FROM users;를 실행하면 테이블의 모든 데이터가 삭제됩니다. 삭제 전에 SELECT로 먼저 대상 데이터를 확인하는 습관을 들이세요.

19.5 조건절(WHERE), 정렬(ORDER BY), 제한(LIMIT)

실제 데이터 조회에서는 원하는 데이터만 필터링하고 정렬하는 기능이 핵심입니다.

WHERE - 조건 필터링

WHERE 절은 조회할 데이터의 조건을 지정합니다.

-- 나이가 30 이상인 사용자 조회
SELECT * FROM users WHERE age >= 30;

-- 이름이 '홍길동'인 사용자 조회
SELECT * FROM users WHERE name = '홍길동';

-- AND / OR 연산자 사용
SELECT * FROM users WHERE age >= 25 AND age <= 35;
SELECT * FROM users WHERE name = '홍길동' OR name = '김철수';

-- BETWEEN: 범위 조건
SELECT * FROM users WHERE age BETWEEN 25 AND 35;

-- IN: 여러 값 중 하나와 일치
SELECT * FROM users WHERE age IN (24, 28, 31);

-- LIKE: 패턴 매칭 (% = 임의의 문자열, _ = 임의의 한 문자)
SELECT * FROM users WHERE email LIKE '%@example.com';
SELECT * FROM users WHERE name LIKE '김%';

-- IS NULL / IS NOT NULL
SELECT * FROM users WHERE age IS NULL;

ORDER BY - 정렬

ORDER BY는 결과를 특정 열 기준으로 정렬합니다.

-- 나이 오름차순 정렬 (기본값: ASC)
SELECT * FROM users ORDER BY age ASC;

-- 나이 내림차순 정렬
SELECT * FROM users ORDER BY age DESC;

-- 여러 열 기준 정렬 (이름 오름차순, 나이 내림차순)
SELECT * FROM users ORDER BY name ASC, age DESC;

LIMIT - 결과 수 제한

LIMIT은 반환할 행의 수를 제한합니다. 페이지네이션 구현에도 활용됩니다.

-- 상위 3개 행만 조회
SELECT * FROM users LIMIT 3;

-- 나이 높은 순으로 상위 2명 조회
SELECT * FROM users ORDER BY age DESC LIMIT 2;

-- OFFSET: 시작 위치 지정 (페이지네이션)
-- 4번째 행부터 3개 조회 (2페이지, 페이지당 3개)
SELECT * FROM users LIMIT 3 OFFSET 3;

💡 쿼리 실행 순서 SQL 쿼리는 작성 순서와 실행 순서가 다릅니다. FROM → WHERE → SELECT → ORDER BY → LIMIT 순서로 처리됩니다. 이를 이해하면 복잡한 쿼리 작성 시 오류를 예방할 수 있습니다.

19.6 조인(JOIN)과 집계 함수

실제 데이터베이스에서는 여러 테이블을 연결하거나 데이터를 요약할 일이 많습니다.

JOIN - 테이블 연결

실습을 위해 orders 테이블을 생성하고 데이터를 추가합니다.

CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    product_name VARCHAR(100) NOT NULL,
    amount INT NOT NULL,
    ordered_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

INSERT INTO orders (user_id, product_name, amount) VALUES
(1, '노트북', 1200000),
(1, '마우스', 30000),
(2, '키보드', 80000),
(3, '모니터', 350000),
(2, '웹캠', 60000);

INNER JOIN은 두 테이블에서 조건이 일치하는 행만 반환합니다.

-- 주문 정보와 주문자 이름을 함께 조회
SELECT
    orders.id AS 주문번호,
    users.name AS 주문자,
    orders.product_name AS 상품명,
    orders.amount AS 금액
FROM orders
INNER JOIN users ON orders.user_id = users.id;

LEFT JOIN은 왼쪽 테이블의 모든 행을 반환하고, 오른쪽 테이블에 일치하는 행이 없으면 NULL을 반환합니다.

-- 주문이 없는 사용자도 포함하여 조회
SELECT
    users.name AS 이름,
    orders.product_name AS 상품명
FROM users
LEFT JOIN orders ON users.id = orders.user_id;
JOIN 종류 설명
INNER JOIN 양쪽 테이블에 모두 일치하는 행만 반환
LEFT JOIN 왼쪽 테이블 전체 + 오른쪽 일치 행 (없으면 NULL)
RIGHT JOIN 오른쪽 테이블 전체 + 왼쪽 일치 행 (없으면 NULL)
FULL OUTER JOIN 양쪽 테이블 모든 행 (MySQL은 UNION으로 구현)

집계 함수와 GROUP BY

집계 함수(Aggregate Function)는 여러 행의 데이터를 하나의 값으로 요약합니다.

-- COUNT: 행의 수
SELECT COUNT(*) AS 전체회원수 FROM users;
SELECT COUNT(*) AS 주문건수 FROM orders;

-- SUM: 합계
SELECT SUM(amount) AS 총매출 FROM orders;

-- AVG: 평균
SELECT AVG(amount) AS 평균주문금액 FROM orders;

-- MAX / MIN: 최댓값 / 최솟값
SELECT MAX(amount) AS 최고금액, MIN(amount) AS 최저금액 FROM orders;

GROUP BY는 특정 열의 값을 기준으로 행을 그룹화하고, 각 그룹에 집계 함수를 적용합니다.

-- 사용자별 주문 건수와 총 주문 금액
SELECT
    users.name AS 이름,
    COUNT(orders.id) AS 주문건수,
    SUM(orders.amount) AS 총주문금액
FROM users
LEFT JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.name;

-- HAVING: 그룹화 후 조건 필터링 (WHERE는 그룹화 전)
-- 총 주문금액이 100,000원 이상인 사용자만 조회
SELECT
    users.name AS 이름,
    SUM(orders.amount) AS 총주문금액
FROM users
INNER JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.name
HAVING SUM(orders.amount) >= 100000;

💡 WHERE vs HAVING WHERE는 그룹화(GROUP BY) 이전에 개별 행을 필터링하고, HAVING은 그룹화 이후 그룹 전체를 필터링합니다. 집계 함수 조건은 반드시 HAVING을 사용해야 합니다.

20.1 RAG란 무엇인가 — LLM의 한계를 보완하는 방법

대규모 언어 모델(LLM, Large Language Model)은 방대한 텍스트 데이터를 학습하여 자연스러운 문장을 생성하는 능력을 갖추고 있습니다. 그러나 LLM은 태생적으로 몇 가지 근본적인 한계를 지닙니다.

LLM은 학습 시점 이후의 정보를 알지 못하고, 존재하지 않는 사실을 그럴듯하게 만들어내는 환각(Hallucination) 현상이 발생할 수 있습니다.

RAG(Retrieval-Augmented Generation)는 이러한 한계를 보완하기 위해 등장한 기법입니다. 질문에 답하기 전에 외부 지식 베이스에서 관련 문서를 검색(Retrieval)한 뒤, 검색된 내용을 컨텍스트로 삼아 LLM이 생성(Generation)하도록 합니다.

RAG가 해결하는 주요 문제는 다음과 같습니다.

  • 지식 최신성 문제: 학습 데이터 이후 발생한 최신 정보를 반영할 수 있습니다.
  • 환각(Hallucination) 문제: 실제 문서를 근거로 답변하므로 허구의 정보 생성이 줄어듭니다.
  • 도메인 특화 문제: 사내 문서, 법률 문서 등 비공개 전문 지식을 활용할 수 있습니다.
  • 비용 문제: 모델 전체를 재학습(Fine-tuning)하지 않고도 지식을 갱신할 수 있습니다.

RAG와 Fine-tuning의 차이를 간단히 비교하면 아래와 같습니다.

구분 RAG Fine-tuning

20.2 RAG의 전체 아키텍처

RAG 시스템은 크게 인덱싱(Indexing) 단계와 질의(Query) 단계로 나뉩니다.

각 단계를 순서대로 정리하면 다음과 같습니다.

  1. 문서 수집(Document Loading): PDF, Word, 웹 페이지, 데이터베이스 등 다양한 소스에서 텍스트를 추출합니다.
  2. 청킹(Chunking): 긴 문서를 LLM이 처리하기 적합한 크기의 조각으로 분할합니다.
  3. 임베딩(Embedding): 각 청크를 수치 벡터로 변환합니다.
  4. 벡터 DB 저장(Indexing): 변환된 벡터를 빠르게 검색할 수 있는 벡터 데이터베이스에 저장합니다.
  5. 검색(Retrieval): 사용자 질문을 임베딩하고, 가장 유사한 청크를 벡터 DB에서 찾아옵니다.
  6. 생성(Generation): 검색된 청크를 컨텍스트로 하여 LLM이 최종 답변을 생성합니다.

인덱싱은 최초 1회(또는 문서 갱신 시)만 수행하고, 질의 단계는 매 요청마다 실행됩니다.

20.3 임베딩(Embedding)의 개념

임베딩(Embedding)이란 텍스트(단어, 문장, 문서)를 의미를 담은 고차원 숫자 벡터로 변환하는 과정입니다. 의미가 비슷한 문장은 벡터 공간에서 가까운 위치에 놓이게 됩니다.

OpenAI Embeddings API 사용

OpenAI는 text-embedding-3-small, text-embedding-3-large 등의 임베딩 모델을 제공합니다.

from openai import OpenAI

client = OpenAI()  # OPENAI_API_KEY 환경변수 사용

def get_embedding(text: str, model: str = "text-embedding-3-small") -> list[float]:
    """텍스트를 임베딩 벡터로 변환합니다."""
    response = client.embeddings.create(
        input=text,
        model=model
    )
    return response.data[0].embedding

# 사용 예시
vector = get_embedding("인공지능이란 무엇인가?")
print(f"벡터 차원: {len(vector)}")  # text-embedding-3-small: 1536차원

문장 유사도 계산 — 코사인 유사도

두 벡터 간 유사도를 측정할 때는 코사인 유사도(Cosine Similarity)를 주로 사용합니다. 값이 1에 가까울수록 두 문장의 의미가 유사합니다.

import numpy as np

def cosine_similarity(vec_a: list[float], vec_b: list[float]) -> float:
    """두 벡터의 코사인 유사도를 계산합니다."""
    a = np.array(vec_a)
    b = np.array(vec_b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

# 유사도 비교
sent1 = "강아지는 귀여운 동물입니다."
sent2 = "개는 사람에게 친근한 반려동물입니다."
sent3 = "오늘 날씨가 매우 맑습니다."

vec1 = get_embedding(sent1)
vec2 = get_embedding(sent2)
vec3 = get_embedding(sent3)

print(f"문장1 vs 문장2: {cosine_similarity(vec1, vec2):.4f}")  # 높은 유사도
print(f"문장1 vs 문장3: {cosine_similarity(vec1, vec3):.4f}")  # 낮은 유사도

20.5 문서 청킹(Chunking) 전략

청킹(Chunking)은 긴 문서를 LLM 컨텍스트 윈도우에 맞는 작은 단위로 분할하는 과정입니다. 청킹 전략은 검색 품질에 직접적인 영향을 미칩니다.

고정 크기 청킹 (Fixed-size Chunking)

문자 수 또는 토큰 수를 기준으로 일정 크기로 분할합니다. 구현이 단순하지만 문장이나 문단이 중간에 잘릴 수 있습니다.

def fixed_size_chunk(text: str, chunk_size: int = 500, overlap: int = 50) -> list[str]:
    """고정 크기로 텍스트를 청킹합니다. overlap으로 문맥 연속성을 유지합니다."""
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start += chunk_size - overlap  # overlap만큼 겹치게 이동
    return chunks

text = "긴 문서 내용..." * 100
chunks = fixed_size_chunk(text, chunk_size=200, overlap=30)
print(f"총 청크 수: {len(chunks)}")

문장 기반 청킹 (Sentence-based Chunking)

문장 단위로 분할하여 의미 단위가 잘리지 않도록 합니다.

import re

def sentence_chunk(text: str, max_chunk_size: int = 500) -> list[str]:
    """문장 단위로 청킹합니다."""
    # 문장 분리 (마침표, 느낌표, 물음표 기준)
    sentences = re.split(r"(?<=[.!?])\s+", text)
    chunks = []
    current_chunk = ""

    for sentence in sentences:
        # 현재 청크에 문장을 추가했을 때 최대 크기를 초과하면 청크 저장
        if len(current_chunk) + len(sentence) > max_chunk_size and current_chunk:
            chunks.append(current_chunk.strip())
            current_chunk = sentence
        else:
            current_chunk += " " + sentence

    if current_chunk.strip():
        chunks.append(current_chunk.strip())

    return chunks

의미 기반 청킹 (Semantic Chunking)

임베딩 유사도를 기반으로 의미가 바뀌는 지점을 감지하여 분할합니다. 품질이 가장 높지만 처리 비용이 높습니다.

def semantic_chunk(sentences: list[str], threshold: float = 0.7) -> list[str]:
    """인접한 문장의 임베딩 유사도가 threshold 미만이면 새 청크를 시작합니다."""
    if not sentences:
        return []

    chunks = []
    current_chunk = [sentences[0]]
    prev_vec = get_embedding(sentences[0])

    for sentence in sentences[1:]:
        curr_vec = get_embedding(sentence)
        similarity = cosine_similarity(prev_vec, curr_vec)

        if similarity < threshold:
            # 의미가 크게 바뀌는 지점 → 새 청크 시작
            chunks.append(" ".join(current_chunk))
            current_chunk = [sentence]
        else:
            current_chunk.append(sentence)

        prev_vec = curr_vec

    if current_chunk:
        chunks.append(" ".join(current_chunk))

    return chunks

기본 RAG 파이프라인 구조

from openai import OpenAI
import chromadb

client = OpenAI()
chroma_client = chromadb.PersistentClient(path="./chroma_db")
collection = chroma_client.get_or_create_collection(name="documents")

def retrieve(query: str, n_results: int = 3) -> list[str]:
    """쿼리와 가장 유사한 문서 청크를 검색합니다.

    중요: 인덱싱 시 OpenAI 임베딩을 명시적으로 넣었으므로, 검색 시에도
    동일한 임베딩 함수로 만든 벡터를 `query_embeddings`로 넘겨야 합니다.
    `query_texts`를 쓰면 ChromaDB의 기본 임베더로 쿼리가 인코딩되어
    저장된 벡터와 공간이 달라져 검색 정확도가 크게 떨어집니다.
    """
    query_embedding = get_embedding(query)
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=n_results
    )
    return results["documents"][0]  # 가장 유사한 n개 청크 반환

def generate(query: str, context_chunks: list[str]) -> str:
    """검색된 컨텍스트를 바탕으로 LLM이 답변을 생성합니다."""
    context = "\n\n".join(context_chunks)

    system_prompt = """당신은 주어진 문서를 바탕으로 질문에 답하는 도우미입니다.
반드시 제공된 문서 내용을 근거로 답변하고, 문서에 없는 내용은 '문서에서 찾을 수 없습니다'라고 답하세요."""

    user_prompt = f"""[참고 문서]
{context}

[질문]
{query}"""

    response = client.chat.completions.create(
        model="gpt-5-mini",            # 2026년 기준 저비용 모델. 폐기 시 동급 최신 모델로 교체
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt}
        ]
    )
    return response.choices[0].message.content

def rag_pipeline(query: str) -> str:
    """RAG 파이프라인: 검색 후 생성합니다."""
    # 1. 검색
    context_chunks = retrieve(query, n_results=3)
    # 2. 생성
    answer = generate(query, context_chunks)
    return answer

20.7 RAG 성능 최적화

기본 RAG 파이프라인을 구축한 후에는 검색 품질과 생성 품질을 높이는 최적화 작업이 필요합니다.

리랭킹(Re-ranking)

리랭킹(Re-ranking)은 1차 검색으로 후보 문서를 넉넉하게 가져온 뒤(예: 상위 10개), 더 정교한 모델로 질문과의 관련도를 재평가하여 최종 상위 k개만 사용하는 기법입니다.

from openai import OpenAI

client = OpenAI()

def rerank_with_llm(query: str, chunks: list[str], top_k: int = 3) -> list[str]:
    """LLM을 사용하여 청크의 관련도를 재평가하고 상위 top_k개를 반환합니다."""
    scored_chunks = []

    for chunk in chunks:
        prompt = f"""다음 문서가 질문에 얼마나 관련이 있는지 0~10 사이의 숫자만 출력하세요.

질문: {query}
문서: {chunk}

점수 (숫자만):"""

        response = client.chat.completions.create(
            model="gpt-5-mini",        # 폐기 시 동급 최신 모델로 교체
            messages=[{"role": "user", "content": prompt}],
            max_tokens=5
        )
        try:
            score = float(response.choices[0].message.content.strip())
        except ValueError:
            score = 0.0
        scored_chunks.append((score, chunk))

    # 점수 내림차순 정렬 후 top_k 반환
    scored_chunks.sort(key=lambda x: x[0], reverse=True)
    return [chunk for _, chunk in scored_chunks[:top_k]]

하이브리드 검색 (Hybrid Search)

하이브리드 검색(Hybrid Search)은 벡터 유사도 검색(Dense Retrieval)과 키워드 기반 검색(Sparse Retrieval, BM25)을 결합하여 두 방식의 장점을 취합니다.

from rank_bm25 import BM25Okapi  # pip install rank-bm25

class HybridRetriever:
    """BM25(키워드)와 벡터 검색을 결합한 하이브리드 검색기입니다."""

    def __init__(self, chunks: list[str], alpha: float = 0.5):
        self.chunks = chunks
        self.alpha = alpha  # 벡터 검색 가중치 (1-alpha: BM25 가중치)

        # BM25 인덱스 구축
        tokenized = [chunk.split() for chunk in chunks]
        self.bm25 = BM25Okapi(tokenized)

        # 벡터 인덱스 구축
        self.embeddings = [get_embedding(chunk) for chunk in chunks]

    def search(self, query: str, top_k: int = 5) -> list[str]:
        # BM25 점수
        bm25_scores = self.bm25.get_scores(query.split())

        # 벡터 유사도 점수
        query_vec = get_embedding(query)
        vector_scores = [cosine_similarity(query_vec, emb) for emb in self.embeddings]

        # 정규화 후 결합
        bm25_norm = bm25_scores / (bm25_scores.max() + 1e-9)
        vector_norm = [s / (max(vector_scores) + 1e-9) for s in vector_scores]

        combined = [
            self.alpha * v + (1 - self.alpha) * b
            for v, b in zip(vector_norm, bm25_norm)
        ]

        # 상위 top_k 인덱스 추출
        top_indices = sorted(range(len(combined)), key=lambda i: combined[i], reverse=True)[:top_k]
        return [self.chunks[i] for i in top_indices]

def get_embedding(text: str) -> list[float]:
    """OpenAI API로 텍스트를 임베딩 벡터로 변환합니다."""
    response = client.embeddings.create(
        input=text,
        model="text-embedding-3-small"
    )
    return response.data[0].embedding

# ── 청킹 ─────────────────────────────────────────────
def chunk_text(text: str, chunk_size: int = 400, overlap: int = 50) -> list[str]:
    """문장 단위를 고려한 고정 크기 청킹을 수행합니다."""
    sentences = re.split(r"(?<=[.!?\n])\s*", text)
    chunks, current = [], ""
    for sentence in sentences:
        if len(current) + len(sentence) > chunk_size and current:
            chunks.append(current.strip())
            # overlap: 마지막 문장을 다음 청크에 포함
            current = current[-overlap:] + sentence
        else:
            current += sentence
    if current.strip():
        chunks.append(current.strip())
    return [c for c in chunks if len(c) > 20]  # 너무 짧은 청크 제거

# ── 인덱싱 ───────────────────────────────────────────
def index_file(file_path: str) -> int:
    """파일을 읽어 청킹 후 ChromaDB에 저장합니다."""
    path = Path(file_path)
    text = path.read_text(encoding="utf-8")
    chunks = chunk_text(text)

    # 이미 인덱싱된 문서 확인 (중복 방지)
    file_name = path.stem
    existing = collection.get(where={"source": file_name})
    if existing["ids"]:
        print(f"[건너뜀] '{file_name}'은 이미 인덱싱되어 있습니다.")
        return 0

    embeddings = [get_embedding(chunk) for chunk in chunks]
    ids = [f"{file_name}_chunk{i}" for i in range(len(chunks))]
    metadatas = [{"source": file_name, "chunk_index": i} for i in range(len(chunks))]

    collection.add(
        documents=chunks,
        embeddings=embeddings,
        ids=ids,
        metadatas=metadatas
    )
    print(f"[완료] '{file_name}' → {len(chunks)}개 청크 인덱싱")
    return len(chunks)

    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=n_results,

    retrieved = []
    for doc, meta, dist in zip(

        results["metadatas"][0],
        results["distances"][0]

            "content": doc,
            "source": meta["source"],

        })
    return retrieved

    """검색된 청크를 컨텍스트로 GPT가 답변을 생성합니다."""
    context_parts = []
    for i, chunk in enumerate(retrieved_chunks, 1):
        context_parts.append(
            f"[문서 {i} | 출처: {chunk['source']} | 유사도: {chunk['similarity']:.2f}]\n{chunk['content']}"
        )
    context = "\n\n".join(context_parts)

    system_msg = """당신은 회사 내부 문서를 기반으로 직원들의 질문에 답하는 AI 도우미입니다.
- 반드시 제공된 문서 내용만을 근거로 답변하세요.
- 답변 마지막에 참고한 출처 문서명을 명시하세요.
- 문서에서 찾을 수 없는 내용은 "해당 정보를 문서에서 찾을 수 없습니다"라고 답하세요."""

    user_msg = f"""참고 문서:
{context}

질문: {query}"""

    response = client.chat.completions.create(
        model="gpt-5-mini",            # 2026년 기준 저비용 모델. 폐기 시 동급 최신 모델로 교체
        messages=[
            {"role": "system", "content": system_msg},
            {"role": "user", "content": user_msg}
        ],
        temperature=0.1  # 사실 기반 답변을 위해 낮은 temperature 사용
    )
    return response.choices[0].message.content

# ── QA 파이프라인 ─────────────────────────────────────
def ask(question: str) -> str:
    """질문을 받아 RAG 파이프라인을 실행하고 답변을 반환합니다."""
    print(f"\n질문: {question}")
    print("-" * 50)

    # 검색
    chunks = retrieve(question, n_results=3)
    print(f"검색된 청크 수: {len(chunks)}")
    for c in chunks:
        print(f"  - [{c['source']}] 유사도: {c['similarity']:.3f}")

    # 생성
    answer = generate_answer(question, chunks)
    print(f"\n답변:\n{answer}")
    return answer

정리

이번 챕터에서는 RAG의 전체 흐름을 학습하고 실습했습니다.

  • RAG는 LLM의 지식 최신성·환각 문제를 외부 문서 검색으로 보완하는 기법입니다.
  • 전체 파이프라인은 문서 수집 → 청킹 → 임베딩 → 벡터 DB 저장 → 검색 → 생성 순서로 동작합니다.
  • 임베딩은 텍스트를 의미 벡터로 변환하며, 코사인 유사도로 문장 간 유사도를 측정합니다.
  • 벡터 데이터베이스는 ChromaDB(로컬), FAISS(고성능), Pinecone(클라우드) 등이 있습니다.
  • 청킹 전략은 고정 크기, 문장 기반, 의미 기반으로 나뉘며 검색 품질에 큰 영향을 줍니다.
  • 리랭킹, 하이브리드 검색, 프롬프트 최적화로 RAG 성능을 높일 수 있습니다.
