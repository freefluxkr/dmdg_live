13.1 API란 무엇인가 — REST API의 기본 개념

API(Application Programming Interface)는 서로 다른 소프트웨어가 정해진 규칙으로 대화하는 창구입니다. 식당으로 비유하면, 손님(내 코드)이 메뉴를 보고 종업원(API)에게 주문하면 주방(AI 서버)이 요리를 만들어 가져다주는 구조입니다.

REST API(Representational State Transfer API)는 웹에서 가장 널리 쓰이는 API 설계 방식입니다. HTTP 프로토콜을 사용해 요청을 보내고 응답을 받으며, 데이터는 주로 JSON(JavaScript Object Notation) 형식으로 주고받습니다.

REST API의 핵심 요소는 다음과 같습니다.

요소 설명 예시
엔드포인트(Endpoint) API 서버의 주소 https://api.openai.com/v1/chat/completions
HTTP 메서드 요청의 종류 GET(조회), POST(생성), PUT(수정), DELETE(삭제)
헤더(Header) 요청 부가 정보 인증 키, 콘텐츠 타입 등
바디(Body) 요청 본문 데이터 JSON 형식의 메시지, 모델명 등
응답(Response) 서버가 돌려주는 결과 JSON 형식의 AI 답변

AI API를 호출할 때는 항상 POST 메서드를 사용하고, 헤더에 API 키(API Key)를 담아 자신이 정당한 사용자임을 증명합니다.

내 코드(Python 클라이언트)가 헤더에 API 키, 바디에 JSON 메시지를 담아 HTTPS POST 로 AI 서버 엔드포인트를 호출하면, 서버는 모델 응답을 다시 JSON으로 돌려줍니다. 모든 통신은 TLS로 암호화되며 API 키는 헤더의 Authorization 필드를 통해서만 전달됩니다.

💡 API 키는 신분증입니다. 키가 노출되면 다른 사람이 내 이름으로 비용을 발생시킬 수 있으니 절대 공개 저장소에 올리지 않도록 주의합니다.

echo 'export OPENAI_API_KEY="sk-..."' >> ~/.bashrc
source ~/.bashrc

13.6 토큰(Token)의 개념과 비용 계산

토큰이란

토큰(Token)은 AI 모델이 텍스트를 처리하는 최소 단위입니다. 단어와 비슷하지만 정확히 같지는 않습니다.

  • 영문 기준: 1 토큰 ≈ 0.75 단어 (약 4글자)
  • 한글 기준: 1 글자 ≈ 1~3 토큰 (한글은 영문보다 토큰 소비가 많습니다)

예를 들어 "Hello, world!" 는 약 4 토큰이고, "안녕하세요, 세상아!" 는 약 8~12 토큰입니다.

토큰 계산 예시

파이썬에서 tiktoken 라이브러리로 OpenAI 모델의 토큰 수를 직접 계산할 수 있습니다.

import tiktoken

# GPT-4o 모델의 인코더 불러오기
enc = tiktoken.encoding_for_model("gpt-4o")

text = "안녕하세요. 오늘 날씨가 정말 좋네요!"
tokens = enc.encode(text)

print(f"텍스트: {text}")
print(f"토큰 수: {len(tokens)}")
print(f"토큰 목록: {tokens}")

비용 계산 공식

비용 = (입력 토큰 수 / 1,000,000) × 입력 단가
     + (출력 토큰 수 / 1,000,000) × 출력 단가

예를 들어 GPT-5 mini(입력 $0.25 / 출력 $2.00)로 입력 1,000 토큰, 출력 500 토큰을 사용했을 때의 비용입니다.

입력 비용 = (1,000 / 1,000,000) × $0.25 = $0.00025
출력 비용 = (500  / 1,000,000) × $2.00 = $0.00100
합계      = $0.00125 (약 1.7원, 2026년 환율 기준)

💡 비용 관리 팁: 각 플랫폼 콘솔의 Usage 또는 Billing 페이지에서 누적 사용량과 비용을 실시간으로 확인할 수 있습니다. 월 한도(Spending Limit)를 설정하면 예상치 못한 과금을 방지할 수 있습니다.

14.1 OpenAI Chat Completions API 구조

Chat Completions API는 OpenAI가 제공하는 핵심 API로, 대화 형식의 메시지 목록을 입력받아 모델의 응답을 반환합니다. gpt-4o, gpt-4o-mini 등의 모델을 사용할 수 있습니다.

기본 호출 구조

from openai import OpenAI

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "당신은 친절한 AI 어시스턴트입니다."},
        {"role": "user", "content": "파이썬이란 무엇인가요?"}
    ]
)

# 응답 텍스트 추출
print(response.choices[0].message.content)

필드 설명
id 응답 고유 ID
object 객체 타입 (chat.completion)

14.2 메시지 역할 (system / user / assistant)

Chat Completions API는 대화를 메시지 목록으로 관리합니다. 각 메시지는 role과 content 두 가지 필드로 구성됩니다. 역할(role)은 세 가지가 있습니다.

역할 설명 사용 시점
system 모델의 행동 방식과 페르소나 설정 대화 맨 처음에 한 번
user 사용자의 입력 메시지 매 질문마다
assistant 모델의 이전 응답 대화 이력 유지 시 
from openai import OpenAI

client = OpenAI()

messages = [
    # system: 모델의 역할과 지침 설정
    {
        "role": "system",
        "content": (
            "당신은 파이썬 전문 튜터입니다. "
            "초보자도 이해할 수 있도록 쉽고 간결하게 설명하세요. "
            "코드 예시는 반드시 포함하세요."
        )
    },
    # user: 사용자 질문
    {
        "role": "user",
        "content": "리스트 컴프리헨션이 뭔가요?"
    },
    # assistant: 이전 응답 (멀티턴 대화 시 이력으로 포함)
    {
        "role": "assistant",
        "content": "리스트 컴프리헨션은 기존 리스트를 기반으로 새 리스트를 간결하게 만드는 문법입니다."
    },
    # 후속 질문
    {
        "role": "user",
        "content": "실제 예제를 보여주세요."
    }
]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages
)

print(response.choices[0].message.content)

system 메시지 활용 팁: system 메시지는 모델의 성격, 응답 언어, 출력 형식, 금지 사항 등을 명시하는 데 활용합니다. 구체적일수록 원하는 방향의 응답을 얻기 쉽습니다.

14.3 주요 파라미터 상세

Chat Completions API에는 응답의 품질과 다양성을 조절하는 다양한 파라미터가 있습니다.

temperature

temperature는 응답의 무작위성(창의성)을 조절합니다. 값의 범위는 0.0 ~ 2.0이며, 낮을수록 일관되고 예측 가능한 응답, 높을수록 다양하고 창의적인 응답이 생성됩니다.

값 범위 특성 적합한 용도
0.0 ~ 0.3 일관적, 결정론적 코드 생성, 사실 질의, 번역
0.4 ~ 0.7 균형적 일반 대화, 요약
0.8 ~ 1.5 창의적, 다양 창작, 아이디어 브레인스토밍

max_tokens

max_tokens는 응답으로 생성할 최대 토큰 수를 제한합니다. 비용 절감과 응답 길이 제어에 활용합니다.

1 토큰 ≈ 영어 4글자 또는 한글 1~2글자. 응답이 잘리면 finish_reason이 length로 표시됩니다.

top_p

top_p (nucleus sampling)는 누적 확률 상위 p% 내의 토큰만 고려하여 샘플링합니다. temperature와 유사하게 다양성을 조절하지만, 일반적으로 둘 중 하나만 조절하는 것을 권장합니다.

frequency_penalty

frequency_penalty는 이미 등장한 단어의 반복을 억제합니다. 값 범위는 -2.0 ~ 2.0이며, 양수 값은 반복을 줄이고 음수 값은 반복을 허용합니다.

presence_penalty

presence_penalty는 아직 등장하지 않은 새로운 주제나 단어를 유도합니다. frequency_penalty가 빈도 기반 패널티라면, presence_penalty는 등장 여부 기반 패널티입니다.

파라미터 종합 예시

from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "당신은 창의적인 이야기 작가입니다."},
        {"role": "user", "content": "외계인이 서울에 나타난 이야기를 짧게 써주세요."}
    ],
    temperature=1.2,          # 창의적인 응답을 위해 높게 설정
    max_tokens=300,            # 최대 300 토큰

from openai import OpenAI

client = OpenAI()

def get_completion(prompt: str, system: str = "당신은 유용한 AI 어시스턴트입니다.") -> str:
    """프롬프트를 받아 응답 텍스트를 반환하는 헬퍼 함수"""
    response = client.chat.completions.create(

        return ""

        print("⚠️ 경고: max_tokens 한도로 응답이 잘렸습니다.")

에러 처리

from openai import OpenAI, APIError, RateLimitError, AuthenticationError
import time

client = OpenAI()

def safe_completion(prompt: str, retries: int = 3) -> str:
    """재시도 로직이 포함된 안전한 API 호출 함수"""
    for attempt in range(retries):
        try:
            response = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "user", "content": prompt}],
                max_tokens=300
            )
            return response.choices[0].message.content or ""

        except AuthenticationError:
            # API 키 오류는 재시도해도 의미 없음
            print("❌ API 키가 유효하지 않습니다. 키를 확인하세요.")
            raise

        except RateLimitError:
            # 요청 한도 초과: 잠시 대기 후 재시도
            wait_time = 2 ** attempt  # 지수 백오프: 1초, 2초, 4초
            print(f"⚠️ 요청 한도 초과. {wait_time}초 후 재시도합니다... ({attempt+1}/{retries})")
            time.sleep(wait_time)

        except APIError as e:
            # 기타 API 오류
            print(f"❌ API 오류 발생: {e}")
            if attempt == retries - 1:
                raise
            time.sleep(1)

    return ""

result = safe_completion("안녕하세요! 오늘 날씨 어때요?")
print(result)

14.5 스트리밍(Streaming) 응답 구현

스트리밍(Streaming)은 모델이 응답을 생성하는 즉시 토큰 단위로 전달받는 방식입니다. 긴 응답을 기다리지 않고 실시간으로 출력할 수 있어 사용자 경험이 크게 향상됩니다.

from openai import OpenAI

client = OpenAI()

def stream_completion(prompt: str) -> None:
    """스트리밍 방식으로 응답을 출력하는 함수"""
    print("응답: ", end="", flush=True)

    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=500,
        stream=True  # 스트리밍 활성화
    )

    full_response = ""

    for chunk in stream:
        # delta에 텍스트가 있는 경우만 처리
        delta = chunk.choices[0].delta
        if delta.content:
            print(delta.content, end="", flush=True)
            full_response += delta.content

    print()  # 줄바꿈
    return full_response

stream_completion("대한민국의 수도와 주요 도시 다섯 곳을 알려주세요.")

14.6 대화 이력(Context) 관리 — 멀티턴 대화 구현

멀티턴(multi-turn) 대화를 구현하려면 이전 대화 내용을 메시지 목록에 누적하여 매번 API에 전달해야 합니다. Chat Completions API는 상태를 저장하지 않으므로, 컨텍스트 관리는 클라이언트(코드) 쪽에서 직접 수행해야 합니다.

from openai import OpenAI

client = OpenAI()

class ChatSession:
    """대화 이력을 관리하는 멀티턴 챗봇 클래스"""

    def __init__(self, system_prompt: str = "당신은 친절한 AI 어시스턴트입니다."):
        self.messages = [
            {"role": "system", "content": system_prompt}
        ]
        self.model = "gpt-4o-mini"

    def chat(self, user_input: str) -> str:
        """사용자 입력을 받아 응답을 반환하고 이력을 갱신합니다."""
        # 사용자 메시지 추가
        self.messages.append({"role": "user", "content": user_input})

        # API 호출
        response = client.chat.completions.create(
            model=self.model,
            messages=self.messages,
            max_tokens=500
        )

        assistant_reply = response.choices[0].message.content or ""

        # 어시스턴트 응답도 이력에 추가
        self.messages.append({"role": "assistant", "content": assistant_reply})

        return assistant_reply

    def reset(self):
        """대화 이력을 초기화합니다 (system 메시지는 유지)."""
        system_msg = self.messages[0]
        self.messages = [system_msg]

    def get_history(self) -> list:
        """system 메시지를 제외한 대화 이력을 반환합니다."""
        return [m for m in self.messages if m["role"] != "system"]

    "파이썬 리스트와 튜플의 차이는 무엇인가요?",
    "그럼 언제 튜플을 사용하는 게 좋을까요?",
    "딕셔너리는 어떤 경우에 쓰나요?"
]

    print(f"[어시스턴트]: {answer}")

토큰 한도와 컨텍스트 압축

모델마다 처리할 수 있는 컨텍스트 윈도우(context window) 한도가 있습니다. 대화가 길어지면 오래된 이력을 제거하거나 요약하는 전략이 필요합니다.

def trim_messages(messages: list, max_pairs: int = 10) -> list:
    """
    system 메시지는 보존하고, 대화 이력을 최근 N쌍으로 제한합니다.
    """
    system_msgs = [m for m in messages if m["role"] == "system"]
    conversation = [m for m in messages if m["role"] != "system"]

    # 최근 max_pairs * 2개의 메시지만 유지
    if len(conversation) > max_pairs * 2:
        conversation = conversation[-(max_pairs * 2):]

    return system_msgs + conversation

import os
import time
from openai import OpenAI
import google.generativeai as genai
import anthropic

# ── API 클라이언트 초기화 ──────────────────────────────────────────────────
openai_client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

genai.configure(api_key=os.getenv("GEMINI_API_KEY"))
gemini_model = genai.GenerativeModel(model_name="gemini-1.5-flash")

claude_client = anthropic.Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))


# ── 각 API 호출 함수 ──────────────────────────────────────────────────────

def call_gpt(prompt: str, system: str = "") -> dict:
    """OpenAI GPT 호출"""
    messages = []
    if system:
        messages.append({"role": "system", "content": system})
    messages.append({"role": "user", "content": prompt})

    start = time.time()
    response = openai_client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        max_tokens=500,
        temperature=0.7
    )
    elapsed = time.time() - start

    return {
        "model": "GPT-4o mini",
        "response": response.choices[0].message.content,
        "tokens": response.usage.total_tokens,
        "elapsed": round(elapsed, 2)
    }


def call_gemini(prompt: str, system: str = "") -> dict:
    """Google Gemini 호출"""
    model = genai.GenerativeModel(
        model_name="gemini-1.5-flash",
        system_instruction=system if system else None,
        generation_config=genai.GenerationConfig(
            temperature=0.7,
            max_output_tokens=500
        )
    )

    start = time.time()
    response = model.generate_content(prompt)
    elapsed = time.time() - start

    return {
        "model": "Gemini 1.5 Flash",
        "response": response.text,
        "tokens": response.usage_metadata.total_token_count if hasattr(response, "usage_metadata") else "N/A",
        "elapsed": round(elapsed, 2)
    }


def call_claude(prompt: str, system: str = "") -> dict:
    """Anthropic Claude 호출"""
    kwargs = {
        "model": "claude-3-5-haiku-20241022",
        "max_tokens": 500,
        "messages": [{"role": "user", "content": prompt}]
    }
    if system:
        kwargs["system"] = system

    start = time.time()
    response = claude_client.messages.create(**kwargs)
    elapsed = time.time() - start

    return {
        "model": "Claude 3.5 Haiku",
        "response": response.content[0].text,
        "tokens": response.usage.input_tokens + response.usage.output_tokens,
        "elapsed": round(elapsed, 2)
    }


# ── 비교 실행 함수 ────────────────────────────────────────────────────────

def compare_models(prompt: str, system: str = "") -> None:
    """세 모델에 동일한 프롬프트를 전송하고 결과를 비교 출력합니다."""
    print("=" * 60)
    print(f"프롬프트: {prompt}")
    if system:
        print(f"시스템:   {system}")
    print("=" * 60)

    results = []
    for call_fn in [call_gpt, call_gemini, call_claude]:
        try:
            result = call_fn(prompt, system)
            results.append(result)
        except Exception as e:
            results.append({"model": call_fn.__name__, "response": f"오류: {e}", "tokens": 0, "elapsed": 0})

    for r in results:
        print(f"\n▶ [{r['model']}] (소요: {r['elapsed']}초, 토큰: {r['tokens']})")
        print("-" * 40)
        print(r["response"])

    print("\n" + "=" * 60)
    print("📊 응답 속도 비교")
    print("-" * 40)
    for r in sorted(results, key=lambda x: x["elapsed"]):
        bar = "█" * int(r["elapsed"] * 5)
        print(f"  {r['model']:<20} {r['elapsed']:>5}초  {bar}")
    print("=" * 60)

15.1 OpenAI Responses API 소개와 등장 배경

왜 새로운 API가 필요했을까?

2025년 3월, OpenAI는 기존 Chat Completions API를 대체하는 Responses API를 공개했습니다. 이 변화는 단순한 인터페이스 개편이 아니라, AI 에이전트(Agent) 시대에 맞는 새로운 패러다임으로의 전환을 의미합니다.

기존 Chat Completions API는 한 번의 요청-응답(Request-Response) 구조로 설계되었습니다. 하지만 실제 서비스에서는 다음과 같은 한계가 드러났습니다.

  • 상태 관리 부재: 매 요청마다 전체 대화 기록을 다시 전송해야 했습니다.
  • 도구 연동 복잡성: 웹 검색, 코드 실행 등 내장 도구를 사용하려면 별도의 복잡한 처리가 필요했습니다.
  • 에이전트 흐름 지원 미흡: 멀티스텝 작업을 처리하는 에이전트 패턴을 구현하기 어려웠습니다.

Responses API는 이러한 문제를 해결하기 위해 다음 특징을 중심으로 설계되었습니다.

특징 설명
서버 사이드 상태 관리 대화 기록을 OpenAI 서버가 저장하고 관리합니다.
내장 도구(Built-in Tools) 웹 검색, 파일 검색, 코드 인터프리터를 기본 제공합니다.
에이전트 친화적 구조 멀티스텝 추론과 도구 호출 흐름을 자연스럽게 지원합니다.
통합 인터페이스 Assistants API, Chat Completions API의 기능을 하나로 통합합니다.

참고: OpenAI는 Responses API가 기존 Chat Completions API를 완전히 대체하는 것은 아니라고 밝혔습니다. 단순한 단일 턴 요청에는 Chat Completions API도 계속 사용할 수 있습니다.

15.3 마이그레이션 가이드 - 코드 변환 예시

기존 Chat Completions API 코드를 Responses API로 변환하는 방법을 단계별로 살펴보겠습니다.

기본 단일 턴 요청 변환

기존 코드 (Chat Completions API):

from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "당신은 친절한 AI 어시스턴트입니다."},
        {"role": "user", "content": "파이썬의 장점을 3가지 알려주세요."}
    ],
    temperature=0.7,
    max_tokens=500
)

print(response.choices[0].message.content)

변환된 코드 (Responses API):

from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-4o",
    instructions="당신은 친절한 AI 어시스턴트입니다.",  # system 역할 대체
    input="파이썬의 장점을 3가지 알려주세요.",          # user 메시지
    temperature=0.7,
    max_output_tokens=500                              # max_tokens → max_output_tokens
)

print(response.output_text)

다중 턴 대화 변환

기존 코드 (Chat Completions API):

from openai import OpenAI

client = OpenAI()

# 대화 기록을 개발자가 직접 관리
conversation_history = [
    {"role": "system", "content": "당신은 친절한 AI 어시스턴트입니다."}
]

def chat(user_message):
    conversation_history.append({"role": "user", "content": user_message})

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=conversation_history  # 매번 전체 기록 전송
    )

    assistant_message = response.choices[0].message.content
    conversation_history.append({"role": "assistant", "content": assistant_message})

    return assistant_message

print(chat("파이썬이란 무엇인가요?"))
print(chat("그렇다면 주요 활용 분야는?"))  # 앞 대화 맥락 유지

변환된 코드 (Responses API):

from openai import OpenAI

client = OpenAI()

# 대화 기록을 서버가 관리 - 개발자는 response_id만 저장
previous_response_id = None

def chat(user_message):
    global previous_response_id

    kwargs = {
        "model": "gpt-4o",
        "instructions": "당신은 친절한 AI 어시스턴트입니다.",
        "input": user_message,
    }

    # 이전 응답이 있으면 연결
    if previous_response_id:
        kwargs["previous_response_id"] = previous_response_id

    response = client.responses.create(**kwargs)

    # 다음 요청을 위해 현재 응답 ID 저장
    previous_response_id = response.id

    return response.output_text

print(chat("파이썬이란 무엇인가요?"))
print(chat("그렇다면 주요 활용 분야는?"))  # 서버가 자동으로 이전 맥락 참조

스트리밍 응답 변환

기존 코드 (Chat Completions API):

from openai import OpenAI

client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "AI의 미래를 설명해주세요."}],
    stream=True
)

for chunk in stream:
    if chunk.choices[0].delta.content is not None:
        print(chunk.choices[0].delta.content, end="", flush=True)

변환된 코드 (Responses API):

from openai import OpenAI

client = OpenAI()

with client.responses.stream(
    model="gpt-4o",
    input="AI의 미래를 설명해주세요."
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

주요 파라미터 변환 요약

Chat Completions API Responses API 비고
messages input 단순 문자열 또는 메시지 배열
messages[system] instructions 시스템 프롬프트 전용 파라미터
max_tokens max_output_tokens 파라미터명 변경
response.choices[0].message.content response.output_text 응답 접근 경로 간소화
없음 previous_response_id 서버 사이드 대화 연결
없음 store=True/False 응답 저장 여부 제어

[실습] Responses API로 멀티모달 챗봇 만들기

이번 실습에서는 Responses API의 서버 사이드 상태 관리와 멀티모달 처리 기능을 결합하여 이미지를 이해하고 대화를 이어가는 챗봇을 만들어 보겠습니다.

실습 목표

  • Responses API의 previous_response_id를 활용한 대화 연속성 구현
  • 이미지와 텍스트를 함께 처리하는 멀티모달 챗봇 구현
  • 간단한 CLI 인터페이스로 인터랙티브 챗봇 완성

전체 코드

import base64
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

def encode_image_to_base64(image_path: str) -> str:
    """로컬 이미지 파일을 Base64 문자열로 인코딩합니다."""
    with open(image_path, "rb") as image_file:
        return base64.b64encode(image_file.read()).decode("utf-8")

def build_user_message(text: str, image_source: str | None = None) -> list:
    """
    사용자 메시지 콘텐츠 블록을 생성합니다.
    image_source가 있으면 이미지를 포함합니다.
    """
    content = []

    if image_source:
        # URL인지 로컬 파일인지 판단
        if image_source.startswith("http://") or image_source.startswith("https://"):
            content.append({
                "type": "input_image",
                "image_url": image_source
            })
        else:
            # 로컬 파일 → Base64 인코딩
            base64_image = encode_image_to_base64(image_source)
            # 확장자로 MIME 타입 결정
            ext = image_source.split(".")[-1].lower()
            mime_map = {"jpg": "jpeg", "jpeg": "jpeg", "png": "png", "gif": "gif", "webp": "webp"}
            mime = mime_map.get(ext, "jpeg")
            content.append({
                "type": "input_image",
                "image_url": f"data:image/{mime};base64,{base64_image}"
            })

    content.append({
        "type": "input_text",
        "text": text
    })

    return content

def multimodal_chatbot():
    """
    Responses API를 사용한 멀티모달 챗봇 메인 함수.
    서버 사이드 상태 관리로 대화 기록을 자동 유지합니다.
    """
    print("=" * 60)
    print("  멀티모달 챗봇 (Responses API)")
    print("=" * 60)
    print("명령어 안내:")
    print("  이미지 분석: '이미지: [경로 또는 URL]' 입력 후 Enter")
    print("  일반 대화:   텍스트를 입력하고 Enter")
    print("  종료:        'quit' 또는 'exit' 입력")
    print("-" * 60)

    previous_response_id = None  # 대화 연결을 위한 이전 응답 ID

    while True:
        user_input = input("\n나: ").strip()

        if not user_input:
            continue

        if user_input.lower() in ["quit", "exit", "종료"]:
            print("챗봇을 종료합니다. 안녕히 가세요!")
            break

        # 이미지 포함 여부 확인
        image_source = None
        message_text = user_input

        if user_input.lower().startswith("이미지:"):
            parts = user_input.split(" ", 1)
            if len(parts) > 1:
                image_source = parts[1].strip()
                message_text = input("이미지에 대해 질문하세요: ").strip()
                if not message_text:
                    message_text = "이 이미지를 자세히 설명해주세요."

        # 메시지 콘텐츠 블록 생성
        content = build_user_message(message_text, image_source)

        # Responses API 요청 구성
        request_params = {
            "model": "gpt-4o",
            "instructions": (
                "당신은 도움이 되는 AI 어시스턴트입니다. "
                "이미지가 제공되면 상세히 분석하고, "
                "이전 대화 맥락을 유지하며 자연스럽게 대화합니다. "
                "한국어로 답변합니다."
            ),
            "input": [{"role": "user", "content": content}]
        }

        # 이전 응답이 있으면 대화 연결
        if previous_response_id:
            request_params["previous_response_id"] = previous_response_id

        try:
            print("\nAI: ", end="", flush=True)

            # 스트리밍으로 응답 받기
            with client.responses.stream(**request_params) as stream:
                response_text = ""
                for text in stream.text_stream:
                    print(text, end="", flush=True)
                    response_text += text

                # 완료된 응답에서 ID 추출
                final_response = stream.get_final_response()
                previous_response_id = final_response.id

            print()  # 줄바꿈

        except Exception as e:
            print(f"\n오류가 발생했습니다: {e}")
            print("다시 시도해주세요.")

if __name__ == "__main__":
    multimodal_chatbot()
