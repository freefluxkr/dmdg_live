7.1 생성형 AI의 정의

생성형 AI(Generative AI)란 학습한 데이터를 바탕으로 새로운 콘텐츠를 스스로 만들어 내는 인공지능을 말합니다. 텍스트, 이미지, 음악, 영상, 코드 등 다양한 형태의 결과물을 생성할 수 있습니다.

기존의 AI가 "이 사진은 고양이인가 개인가?"처럼 주어진 데이터를 분류하거나 예측하는 데 집중했다면, 생성형 AI는 "고양이 사진을 하나 만들어봐"처럼 존재하지 않던 데이터를 새로 창조합니다.

💡 핵심 포인트: 생성형 AI의 핵심은 "분류"가 아니라 "창조"입니다. 학습 데이터의 패턴을 익혀 새로운 무언가를 만들어낸다는 점에서 기존 AI와 근본적으로 다릅니다.

일상적인 예를 들어보겠습니다.

  • 수천 편의 소설을 읽고 새로운 소설을 쓰는 작가
  • 수백만 장의 그림을 보고 비슷한 스타일로 새 그림을 그리는 화가
  • 수많은 음악을 듣고 새로운 멜로디를 작곡하는 음악가

생성형 AI는 이와 비슷한 방식으로 동작합니다. 방대한 데이터에서 패턴을 학습하고, 그 패턴을 활용해 새롭고 그럴듯한 결과물을 만들어냅니다.

7.2 판별 모델(Discriminative) vs 생성 모델(Generative)

AI 모델은 크게 두 가지 방식으로 나뉩니다. 데이터를 구분하고 분류하는 판별 모델(Discriminative Model)과, 새로운 데이터를 만들어내는 생성 모델(Generative Model)입니다.

아래 표에서 두 모델의 주요 차이점을 정리합니다.

구분 판별 모델 (Discriminative) 생성 모델 (Generative)
목적 입력 데이터를 분류·예측 새로운 데이터를 생성
학습 방식 입력(X)과 레이블(Y)의 관계 학습 데이터의 분포(확률) 자체를 학습
대표 예시 스팸 필터, 이미지 분류, 감정 분석 ChatGPT, DALL-E, Stable Diffusion
핵심 질문 "이것은 무엇인가?" "이것과 비슷한 새것을 만들 수 있는가?"
출력 클래스 레이블, 확률값 텍스트, 이미지, 음성 등 콘텐츠

판별 모델과 생성 모델은 서로 대립하는 개념이 아니라, 목적에 따라 쓰임새가 다릅니다. 실제로 GAN(Generative Adversarial Network, 생성적 적대 신경망)처럼 두 모델을 함께 활용하는 방식도 존재합니다.

📌 기억하세요: 판별 모델은 "A인가 B인가"를 결정하고, 생성 모델은 "A처럼 보이는 새로운 것"을 만들어냅니다. 스팸 메일 필터는 판별 모델이고, ChatGPT는 생성 모델입니다.

7.3 생성형 AI의 종류

생성형 AI는 만들어내는 콘텐츠의 유형에 따라 다양하게 분류됩니다. 현재 실용화된 주요 분야를 하나씩 살펴보겠습니다.

텍스트 생성 (GPT, Claude, Gemini)

텍스트 생성 AI는 사람이 쓴 것과 같은 자연스러운 글을 만들어냅니다. 질문에 답하고, 글을 요약하고, 번역하고, 코드를 설명하는 등 언어와 관련된 거의 모든 작업을 수행할 수 있습니다.

대표적인 서비스는 다음과 같습니다.

  • GPT(OpenAI): OpenAI가 개발한 대규모 언어 모델. ChatGPT 서비스의 기반이 됩니다.
  • Claude(Anthropic): 안전성과 정확성에 집중한 Anthropic의 언어 모델. 긴 문서 처리에 강점이 있습니다.
  • Gemini(Google DeepMind): Google이 개발한 멀티모달 언어 모델. 검색과 연동된 최신 정보 제공이 특징입니다.

💡 이 세 가지 모델은 "대형 언어 모델(LLM, Large Language Model)"이라고 부르며, 다음 챕터(Ch.8)에서 더 깊이 다룹니다.

이미지 생성 (DALL-E, Midjourney, Stable Diffusion)

이미지 생성 AI는 텍스트 설명(프롬프트)을 입력하면 그에 맞는 이미지를 만들어냅니다. "노을 지는 바다 위 등대를 수채화로 그려줘"와 같은 요청을 처리할 수 있습니다.

  • DALL-E(OpenAI): ChatGPT와 연동되어 대화 중 이미지를 생성할 수 있습니다.
  • Midjourney: 높은 예술적 품질로 유명하며, Discord를 통해 사용합니다.
  • Stable Diffusion: 오픈소스로 공개되어 로컬 설치 및 자유로운 커스터마이징이 가능합니다.

음성 생성 (TTS, 음악)

음성 생성 AI는 텍스트를 자연스러운 사람 목소리로 변환하거나, 멜로디와 가사를 갖춘 음악을 만들어냅니다.

  • TTS(Text-to-Speech, 텍스트 음성 변환): ElevenLabs, OpenAI TTS 등이 특정 인물의 목소리를 학습해 자연스러운 음성을 생성합니다.
  • 음악 생성: Suno, Udio 등은 장르, 분위기, 가사를 지정하면 완성된 노래를 만들어냅니다.

⚠️ 주의: 특정 인물의 목소리나 음악을 무단으로 학습·생성하는 것은 초상권·저작권 침해에 해당할 수 있습니다. 생성형 AI 사용 시 윤리적·법적 규범을 반드시 준수해야 합니다.

영상 생성 (Sora, Runway)

영상 생성 AI는 텍스트 설명이나 이미지를 바탕으로 동영상을 만들어냅니다. 아직 발전 단계이지만 급격한 품질 향상이 이루어지고 있습니다.

  • Sora(OpenAI): 최대 수십 초 분량의 고품질 영상을 텍스트 설명만으로 생성합니다.
  • Runway: 기존 영상을 편집하거나 새 장면을 생성하는 전문 영상 제작 도구입니다.

코드 생성 (Copilot, Cursor)

코드 생성 AI는 자연어로 설명하면 그에 맞는 프로그램 코드를 작성해 줍니다. 개발자의 생산성을 크게 높여주는 분야입니다.

  • GitHub Copilot: Microsoft와 OpenAI가 협력해 만든 AI 코딩 보조 도구. VS Code 등 에디터에서 실시간으로 코드를 제안합니다.
  • Cursor: AI 기능이 내장된 코드 에디터로, 코드 설명, 자동 완성, 버그 수정을 통합 지원합니다.

7.4 생성형 AI의 발전 역사

생성형 AI는 하루아침에 등장한 기술이 아닙니다. 수십 년간 이어진 연구의 결실입니다. 주요 이정표를 시간 순으로 살펴보겠습니다.

GAN — 서로 경쟁하며 성장하다 (2014)

GAN(Generative Adversarial Network, 생성적 적대 신경망)은 2014년 Ian Goodfellow가 제안한 혁신적인 모델입니다. "생성자(Generator)"와 "판별자(Discriminator)" 두 신경망이 경쟁하며 서로를 발전시키는 방식으로 학습합니다.

  • 생성자: 진짜처럼 보이는 가짜 이미지를 만들어 판별자를 속이려 합니다.
  • 판별자: 진짜와 가짜를 구분하려 합니다.

이 경쟁이 반복될수록 생성자는 점점 더 진짜 같은 이미지를 만들게 됩니다. GAN은 처음으로 사람 얼굴 같은 현실적인 이미지 생성을 가능하게 했습니다.

VAE — 잠재 공간에서 의미를 찾다 (2013~2014)

VAE(Variational Autoencoder, 변분 오토인코더)는 데이터를 압축된 "잠재 공간(Latent Space)"으로 표현한 뒤, 그 공간에서 새로운 데이터를 샘플링해 생성합니다. 이미지 생성뿐 아니라 데이터의 구조를 이해하는 데에도 활용됩니다.

Transformer — 언어 이해의 새 지평을 열다 (2017)

2017년 Google 연구팀이 발표한 논문 "Attention Is All You Need"는 Transformer 아키텍처를 세상에 내놓았습니다. 어텐션 메커니즘(Attention Mechanism)을 핵심으로 삼아 문장 내 단어 간 관계를 병렬로 처리합니다.

Transformer는 RNN의 한계였던 긴 문장에서의 정보 손실 문제를 해결하며, 이후 모든 대형 언어 모델의 기반 구조가 됩니다.

💡 Transformer의 원리는 다음 챕터(Ch.8)에서 상세히 다룹니다.

GPT — 대규모 사전 학습의 시대 (2018~현재)

GPT(Generative Pre-trained Transformer)는 Transformer를 기반으로 방대한 텍스트 데이터를 사전 학습(Pre-training)한 모델입니다. 2018년 GPT-1을 시작으로, GPT-2(2019), GPT-3(2020), GPT-4(2023)로 발전하며 모델 규모와 성능이 폭발적으로 성장했습니다.

2022년 11월 공개된 ChatGPT는 GPT-3.5를 기반으로 대화에 특화된 서비스로, 출시 5일 만에 100만 사용자를 돌파하며 AI 대중화의 신호탄이 되었습니다.

멀티모달 — 텍스트를 넘어 세상을 이해하다 (2021~현재)

멀티모달(Multimodal) AI는 텍스트뿐 아니라 이미지, 음성, 영상 등 여러 형태의 데이터를 동시에 처리하는 모델입니다. GPT-4V, Gemini, Claude 3 등이 대표적입니다.

"이 사진에서 무엇이 보이나요?"처럼 이미지를 입력해 텍스트로 설명받거나, 텍스트로 이미지를 생성하는 것이 모두 멀티모달 기능입니다.

7.5 왜 지금 생성형 AI가 폭발적으로 성장했는가

생성형 AI 기술은 오래전부터 연구되어 왔지만, 최근 몇 년 사이 폭발적인 성장을 이룬 이유가 있습니다. 전문가들은 이를 세 가지 요소의 결합, 즉 "데이터, 컴퓨팅 파워, 알고리즘의 삼위일체"로 설명합니다.

데이터 — 학습 재료의 폭발적 증가

인터넷과 스마트폰의 보급으로 전 세계에서 매일 엄청난 양의 텍스트, 이미지, 영상 데이터가 생성됩니다. AI 모델이 학습할 수 있는 재료가 기하급수적으로 늘어난 것입니다.

  • 위키피디아, 웹 페이지, 책, SNS, 코드 저장소 등 수천억 개의 텍스트 데이터
  • 수억 장의 이미지와 그에 달린 설명 텍스트
  • 유튜브 등 플랫폼의 방대한 영상 및 자막 데이터

📌 데이터는 AI의 "영양분"입니다. 더 많은 고품질 데이터가 더 똑똑한 AI를 만듭니다.

컴퓨팅 파워 — GPU와 클라우드의 발전

대형 AI 모델을 학습시키려면 엄청난 연산 능력이 필요합니다. GPU(Graphics Processing Unit)의 성능이 비약적으로 발전하고 가격이 내려가면서, 이전에는 불가능했던 대규모 학습이 현실이 되었습니다.

또한 AWS, Google Cloud, Azure 같은 클라우드 컴퓨팅 서비스가 등장해, 스타트업이나 연구자도 필요한 만큼 컴퓨팅 자원을 빌려 쓸 수 있게 되었습니다.

  • NVIDIA A100, H100 등 AI 전용 GPU 등장
  • TPU(Tensor Processing Unit) 등 AI 특화 반도체 개발
  • 분산 학습 기술의 발전으로 수천 개의 GPU를 동시에 활용

알고리즘 — Transformer의 혁신

아무리 데이터와 컴퓨팅 파워가 있어도, 효율적인 학습 알고리즘이 없으면 좋은 모델을 만들 수 없습니다. 2017년 등장한 Transformer 아키텍처가 바로 그 게임 체인저였습니다.

  • 병렬 처리가 가능해 학습 속도가 크게 향상
  • 어텐션 메커니즘으로 문맥(Context)을 훨씬 잘 이해
  • 스케일링 법칙(Scaling Law): 모델이 커질수록 성능도 예측 가능하게 향상

💡 삼위일체 정리: 방대한 데이터(원료) + 강력한 GPU·클라우드(공장) + Transformer 알고리즘(설계도)이 맞아떨어지며 생성형 AI의 황금기가 열렸습니다.

8.1 Attention 메커니즘 — "Attention Is All You Need"

기존 방식의 한계

번역 시스템을 예로 들겠습니다. "나는 어제 친구와 함께 맛있는 피자를 먹었다"를 영어로 번역할 때, RNN 기반 모델은 문장을 왼쪽에서 오른쪽으로 순서대로 처리합니다. 문장이 길어질수록 앞부분의 정보가 점점 희미해지는 장기 의존성(Long-term Dependency) 문제가 발생합니다.

💡 비유: 긴 전화 통화를 녹음 없이 듣고 나중에 처음 내용을 기억하려는 것과 같습니다. 대화가 길수록 초반 내용은 흐릿해집니다.

Attention의 핵심 아이디어

Attention(어텐션)은 "출력의 각 단어를 생성할 때, 입력 문장의 어느 부분에 집중(attention)해야 하는가"를 학습하는 메커니즘입니다.

예를 들어 "The animal didn't cross the street because it was too tired"에서 "it"이 "animal"을 가리킨다는 것을 파악하려면, 모델이 "it"과 "animal" 사이의 관계에 강하게 집중해야 합니다.

Attention은 바로 이 "집중도"를 수치로 계산합니다. 관련성이 높은 단어 쌍에는 높은 가중치를, 낮은 쌍에는 낮은 가중치를 부여합니다.

📌 2017년 Google Brain 팀이 발표한 논문 "Attention Is All You Need"는 RNN 없이 오직 Attention만으로 번역 모델을 구성했고, 당시 최고 성능을 기록했습니다. 이것이 Transformer의 시작입니다.

Seq2Seq에서 Attention으로

기존 Seq2Seq(Sequence-to-Sequence) 모델은 인코더가 전체 입력을 하나의 고정된 벡터(context vector)로 압축했습니다. 이 압축 과정에서 정보 손실이 발생했습니다.

Attention을 추가하면 디코더가 출력 단어를 생성할 때마다 인코더의 모든 은닉 상태를 동적으로 참조합니다. 고정된 벡터 하나가 아니라, 필요한 정보를 그때그때 찾아보는 방식입니다.

8.2 Self-Attention의 동작 원리 (Query, Key, Value)

Self-Attention이란?

Self-Attention(자기 어텐션)은 같은 문장 내에서 각 단어가 다른 단어들과 얼마나 관련 있는지 계산하는 방식입니다. 외부 문장이 아니라 자기 자신의 문장 내에서 관계를 파악하기 때문에 'Self'라는 이름이 붙었습니다.

💡 비유: 도서관에서 책을 찾는 과정을 생각해보세요. - Query(질의): 내가 찾고 싶은 것 ("머신러닝 입문서") - Key(색인): 각 책에 붙은 분류 태그 ("딥러닝", "통계", "머신러닝 기초" ...) - Value(값): 실제 책의 내용

Query와 Key를 비교해서 가장 관련 있는 책을 찾고(유사도 계산), 그 책의 내용(Value)을 가져오는 것이 Self-Attention입니다.

Q, K, V 계산 과정

단어 임베딩 벡터 $x$에서 세 종류의 벡터를 생성합니다.

$$Q = x W_Q, \quad K = x W_K, \quad V = x W_V$$

여기서 $W_Q$, $W_K$, $W_V$는 학습 가능한 가중치 행렬입니다.

Attention 점수 계산:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

  • $QK^T$: Query와 Key의 내적(dot product) → 유사도 측정
  • $\sqrt{d_k}$: 벡터 차원의 제곱근으로 나누어 값이 너무 커지는 것을 방지(스케일링)
  • $\text{softmax}$: 모든 점수를 0~1 사이로 정규화(합이 1)
  • 최종적으로 이 가중치로 Value를 가중 합산

⚠️ 수식이 어렵더라도 핵심만 기억하세요: "각 단어가 다른 단어들과의 관련도를 계산하고, 그 관련도에 비례하여 정보를 가져온다."

구체적인 예시

"나는 사과를 먹었다"에서 "먹었다"를 처리할 때:

비교 대상 유사도 점수 Softmax 가중치
나는 0.3 0.20
사과를 0.8 0.54
먹었다 0.4 0.26

"먹었다"는 "사과를"에 가장 강하게 집중합니다. 이 가중치로 Value 벡터를 합산한 것이 최종 표현입니다.

8.3 Multi-Head Attention

왜 여러 개의 Head가 필요한가?

단일 Attention은 한 가지 관점에서만 관계를 파악합니다. 하지만 언어에는 다양한 차원의 관계가 있습니다.

  • 구문적 관계: 주어-동사 관계
  • 의미적 관계: 대명사-지시 대상 관계
  • 문맥적 관계: 감정이나 어조 관계

Multi-Head Attention(멀티헤드 어텐션)은 여러 개의 Attention을 병렬로 수행하여 다양한 관점에서 관계를 동시에 파악합니다.

💡 비유: 같은 영화를 여러 사람이 각자 다른 관점(스토리, 연기, 음악, 촬영기법)으로 리뷰하고, 나중에 종합하는 것과 같습니다.

Multi-Head Attention의 구조

$h$개의 Attention 헤드를 병렬로 수행합니다.

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h) W^O$$

$$\text{where } \text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$$

각 헤드는 독립적인 가중치 행렬로 서로 다른 표현 부분 공간(representation subspace)을 학습합니다. 모든 헤드의 출력을 이어 붙인(Concatenate) 후 선형 변환을 거쳐 최종 출력을 만듭니다.

실제로 GPT-3는 96개의 Attention 헤드를 사용합니다. 헤드 수가 많을수록 더 풍부한 관계를 포착할 수 있지만 계산 비용도 증가합니다.

8.4 Transformer의 전체 구조 (Encoder-Decoder)

Transformer 개요

Transformer는 Encoder(인코더)와 Decoder(디코더) 두 부분으로 구성됩니다. 번역을 예로 들면 인코더는 입력 언어를 이해하고, 디코더는 출력 언어를 생성합니다.

입력 문장 → [Encoder × N] → [Decoder × N] → 출력 문장

Encoder 구조

하나의 인코더 블록은 다음 두 가지 핵심 레이어로 구성됩니다.

입력
  ↓
[Multi-Head Self-Attention]
  ↓
[Add & Norm]          ← 잔차 연결(Residual Connection) + 레이어 정규화
  ↓
[Feed-Forward Network]
  ↓
[Add & Norm]
  ↓
출력 (다음 인코더 블록으로)
  • Self-Attention: 입력 문장 내 단어들 간의 관계 파악
  • Feed-Forward Network(FFN): 각 위치마다 독립적으로 적용되는 완전 연결 레이어
  • Add & Norm: 잔차 연결로 기울기 소실을 방지하고, 레이어 정규화로 학습을 안정화

이 블록을 $N$번 쌓아 올립니다. 원래 논문에서는 $N=6$을 사용했습니다.

Decoder 구조

디코더 블록은 인코더보다 한 가지 레이어가 더 있습니다.

출력 임베딩 (이전 출력 토큰)
  ↓
[Masked Multi-Head Self-Attention]  ← 미래 토큰을 보지 못하도록 마스킹
  ↓
[Add & Norm]
  ↓
[Cross-Attention]   ← 인코더 출력과 상호작용
  ↓
[Add & Norm]
  ↓
[Feed-Forward Network]
  ↓
[Add & Norm]
  ↓
출력
  • Masked Self-Attention: 디코더가 아직 생성하지 않은 미래 단어를 참조하지 못하도록 마스킹합니다.
  • Cross-Attention: Query는 디코더에서, Key와 Value는 인코더 출력에서 가져옵니다. 인코더가 이해한 내용을 디코더가 활용하는 핵심 연결 지점입니다.

📌 GPT 계열은 Decoder만 사용합니다. BERT 계열은 Encoder만 사용합니다. 번역처럼 입력과 출력이 모두 필요한 경우에만 Encoder-Decoder 전체 구조를 사용합니다.

8.5 Positional Encoding

순서 정보가 없는 문제

Self-Attention은 모든 단어를 동시에 처리합니다. 이것이 병렬 처리를 가능하게 하는 장점이지만, 동시에 단어의 순서 정보가 사라지는 문제가 생깁니다.

"나는 너를 사랑한다"와 "너는 나를 사랑한다"는 같은 단어지만 순서가 다르면 의미가 완전히 달라집니다. Attention만으로는 이 차이를 인식할 수 없습니다.

Positional Encoding 방법

Positional Encoding(위치 인코딩)은 각 단어의 임베딩 벡터에 위치 정보를 나타내는 벡터를 더해줍니다.

$$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

$$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

  • $pos$: 단어의 위치 (0, 1, 2, ...)
  • $i$: 벡터의 차원 인덱스
  • $d_{model}$: 임베딩 벡터의 차원 수

💡 사인/코사인 함수를 사용하는 이유는 상대적 위치를 표현할 수 있기 때문입니다. 학습 중에 본 적 없는 더 긴 문장에서도 위치 관계를 일반화할 수 있습니다.

학습 가능한 위치 임베딩

원래 논문의 수식 방식 외에도 위치 벡터를 직접 학습시키는 방법도 있습니다. GPT, BERT 등 대부분의 현대 모델은 학습 가능한 위치 임베딩을 사용합니다.

최근에는 RoPE(Rotary Position Embedding)나 ALiBi 같은 개선된 방식도 등장하여 더 긴 문맥을 효과적으로 처리합니다.

8.6 Transformer가 바꾼 것들 — RNN/LSTM의 한계 극복

RNN과 LSTM의 한계

Transformer 이전에는 RNN(Recurrent Neural Network)과 그 개선판인 LSTM(Long Short-Term Memory)이 자연어 처리의 주류였습니다.

한계점 설명
순차 처리 단어를 하나씩 순서대로 처리하여 병렬화 불가
장기 의존성 문장이 길어지면 앞 내용을 기억하기 어려움
느린 학습 속도 병렬화 불가로 GPU 활용 효율이 낮음
정보 병목 모든 정보를 고정 크기 벡터에 압축

Transformer가 해결한 것들

개선 사항 Transformer의 접근 방법
병렬 처리 모든 위치를 동시에 처리
장거리 관계 Attention으로 어떤 거리도 직접 연결
학습 속도 완전한 병렬화로 GPU 효율 극대화
확장성 레이어/헤드 수를 늘려 쉽게 스케일 업

📌 RNN의 시간 복잡도: $O(n)$ (순차 처리) vs Transformer: $O(1)$ (병렬 처리). 단, Attention의 공간 복잡도는 $O(n^2)$으로 매우 긴 문장에서는 메모리 부담이 있습니다.

Transformer의 영향 범위

Transformer는 자연어 처리에만 머물지 않았습니다.

  • 이미지: Vision Transformer(ViT) — 이미지를 패치로 나누어 처리
  • 음성: Whisper — 음성 인식
  • 생물학: AlphaFold2 — 단백질 구조 예측
  • 코드: GitHub Copilot — 코드 자동 완성
  • 멀티모달: GPT-4V, Gemini — 텍스트와 이미지 동시 처리

8.7 대규모 언어 모델(LLM)의 개요 — 스케일링 법칙, 창발적 능력

LLM이란?

대규모 언어 모델(LLM, Large Language Model)은 수백억~수천억 개의 파라미터를 가진 초대형 Transformer 모델입니다. 방대한 텍스트 데이터로 학습하여 언어의 패턴, 지식, 추론 능력을 습득합니다.

'대규모'를 가늠하는 세 가지 축이 있습니다.

  • 모델 크기: 파라미터 수 (GPT-3: 1,750억 개)
  • 데이터 크기: 학습에 사용한 텍스트 양 (GPT-3: 약 570GB)
  • 연산량: 학습에 소요된 FLOP 수

스케일링 법칙 (Scaling Laws)

OpenAI 연구팀은 2020년 스케일링 법칙(Scaling Laws)을 발표했습니다. 핵심 내용은 다음과 같습니다.

📌 모델 크기, 데이터 양, 연산량을 동시에 늘리면 모델 성능이 예측 가능한 방식으로 향상된다.

성능 향상이 멈추는 한계가 없다는 것이 당시에는 놀라운 발견이었습니다. 더 많은 자원을 투입할수록 더 좋은 모델이 만들어집니다.

이후 Chinchilla 논문(2022)은 모델 크기와 데이터 양의 최적 비율을 제시했습니다. "모델 크기를 2배 늘릴 때 데이터도 2배 늘려야 최적"이라는 것입니다. 이전의 GPT-3는 데이터 대비 모델이 너무 컸던 셈입니다.

창발적 능력 (Emergent Abilities)

가장 흥미로운 발견은 창발적 능력(Emergent Abilities)입니다. 모델이 특정 규모 이상으로 커지면, 학습 중에 명시적으로 가르치지 않은 능력이 갑자기 나타납니다.

창발적 능력 설명
산술 계산 수식 풀기 능력이 특정 크기에서 급격히 향상
논리적 추론 단계적 추론(Chain-of-Thought) 능력 출현
코드 생성 프로그래밍 언어 작성 능력
다국어 번역 명시적으로 학습하지 않은 언어 간 번역
유추 능력 "파리:프랑스 = 도쿄:?" 유형의 관계 추론

⚠️ 창발적 능력은 왜 발생하는지 아직 완전히 이해되지 않았습니다. AI 연구의 중요한 미해결 문제 중 하나입니다.

8.8 사전학습(Pre-training)과 미세조정(Fine-tuning)

두 단계 학습의 필요성

LLM을 활용하는 일반적인 방법은 두 단계로 나뉩니다. 처음부터 특정 작업에 맞는 모델을 학습시키면 엄청난 비용이 들기 때문에, 범용 지식을 먼저 쌓고 나서 특화시키는 전략을 사용합니다.

💡 비유: 대학 교육과 직업 훈련의 관계와 같습니다. 대학에서 광범위한 기초 지식을 쌓고(사전학습), 취업 후 해당 직무에 특화된 훈련을 받습니다(미세조정).

사전학습 (Pre-training)

사전학습(Pre-training)은 인터넷, 책, 논문 등에서 수집한 방대한 텍스트로 언어의 일반적인 패턴을 학습하는 단계입니다.

학습 방식은 크게 두 가지입니다.

자기회귀 언어 모델링 (Autoregressive LM):

  • 이전 단어들을 보고 다음 단어를 예측
  • GPT 계열이 사용
  • "나는 학교에 ___" → "갔다" 예측

마스킹 언어 모델링 (Masked LM):

  • 문장의 일부를 가리고 그 단어를 예측
  • BERT 계열이 사용
  • "나는 [MASK]에 갔다" → "학교" 예측

사전학습 후의 모델을 기반 모델(Base Model) 또는 파운데이션 모델(Foundation Model)이라고 합니다.

미세조정 (Fine-tuning)

미세조정(Fine-tuning)은 사전학습된 모델을 특정 작업에 맞게 추가 학습시키는 단계입니다.

기반 모델
    ↓
[작업별 데이터로 추가 학습]
    ↓
특화된 모델 (번역, 요약, 분류, 질답 등)

미세조정의 종류:

방법 설명 특징
Full Fine-tuning 모든 파라미터 업데이트 성능 최고, 비용 최대
LoRA 저랭크 행렬만 학습 효율적, 널리 사용됨
Prompt Tuning 입력에 학습 가능한 토큰 추가 모델 변경 없음
Adapter 작은 모듈 삽입 모듈식 관리 가능

📌 LoRA(Low-Rank Adaptation)는 현재 가장 널리 사용되는 미세조정 방법입니다. 전체 파라미터의 1% 미만을 학습하면서도 Full Fine-tuning에 근접한 성능을 냅니다.

인컨텍스트 학습 (In-Context Learning)

미세조정 없이도 프롬프트에 예시를 제공하여 모델이 패턴을 파악하게 하는 인컨텍스트 학습(In-Context Learning)도 강력한 방법입니다.

  • Zero-shot: 예시 없이 지시만 제공
  • One-shot: 예시 1개 제공
  • Few-shot: 예시 여러 개 제공

LLM이 클수록 인컨텍스트 학습 능력이 향상됩니다.

8.9 RLHF (인간 피드백 기반 강화학습)

왜 RLHF가 필요한가?

사전학습만 마친 기반 모델은 "다음 단어 예측"에는 뛰어나지만, 인간이 원하는 방식으로 대답하지 않을 수 있습니다.

  • 유해한 내용을 생성할 수 있습니다.
  • 질문에 직접 답하지 않고 비슷한 텍스트만 생성할 수 있습니다.
  • 거짓 정보를 자신감 있게 말할 수 있습니다 (할루시네이션).

RLHF(Reinforcement Learning from Human Feedback, 인간 피드백 기반 강화학습)는 인간의 선호도를 반영하여 모델이 더 안전하고 유용하게 동작하도록 훈련합니다.

RLHF의 세 단계

1단계: 지도 학습 미세조정 (SFT)

기반 모델 + 인간이 작성한 고품질 응답 데이터
    ↓
지도 학습으로 미세조정
    ↓
SFT 모델

사람이 직접 작성한 이상적인 응답 예시로 모델을 학습합니다.

2단계: 보상 모델 학습 (Reward Model)

동일한 질문에 대한 여러 모델 응답
    ↓
인간 평가자가 선호도 순위 매기기
    ↓
보상 모델(RM) 학습

인간 평가자가 여러 응답을 비교하여 어느 것이 더 좋은지 순위를 매깁니다. 이 데이터로 인간의 선호도를 흉내 내는 보상 모델(Reward Model)을 학습합니다.

3단계: 강화학습으로 최적화 (PPO)

SFT 모델 → 응답 생성 → 보상 모델이 점수 부여
    ↓
높은 점수를 받는 방향으로 PPO 알고리즘으로 업데이트
    ↓
RLHF 완성 모델

PPO(Proximal Policy Optimization) 알고리즘을 사용하여 보상 모델에서 높은 점수를 받는 방향으로 SFT 모델을 업데이트합니다.

⚠️ KL 발산 제약: 너무 보상 점수만 높이려다 보면 모델이 이상한 방식으로 "점수를 조작"하려는 경향이 생깁니다(reward hacking). 이를 방지하기 위해 원래 모델(SFT)에서 너무 멀어지지 않도록 KL 발산 패널티를 적용합니다.

RLHF의 변형과 발전

방법 설명
RLHF (PPO) 전통적 방법, InstructGPT/ChatGPT에 사용
DPO (Direct Preference Optimization) 보상 모델 없이 선호도 데이터로 직접 학습, 더 간단
RLAIF 인간 대신 AI가 피드백 제공
Constitutional AI Anthropic의 방법, 원칙 기반 자기 비판으로 개선

📌 Constitutional AI(CAI)는 Anthropic이 Claude 학습에 사용하는 방법입니다. 헌법처럼 명문화된 원칙 목록을 기반으로 AI가 스스로 응답을 비판하고 개선합니다.

마치며

이번 챕터에서는 현대 AI의 핵심 기술인 Transformer와 LLM의 전체 그림을 살펴보았습니다.

2017년 Attention 메커니즘을 중심에 놓은 Transformer가 등장하며, AI는 새로운 시대를 열었습니다. Self-Attention은 문장 내 단어 간의 관계를 직접 모델링하고, Multi-Head Attention은 다양한 관점에서 이 관계를 파악합니다. Positional Encoding은 순서 정보를 보완하며, Encoder-Decoder 구조는 다양한 언어 작업에 적용됩니다.

Transformer 위에서 규모가 커질수록 성능이 향상되는 스케일링 법칙이 발견되었고, 일정 규모 이상에서는 학습하지 않은 능력이 창발적으로 나타납니다. 사전학습으로 방대한 지식을 쌓고, 미세조정으로 특화시키며, RLHF로 인간의 선호에 맞게 조율하는 방식이 현대 LLM의 표준이 되었습니다.

9.1 산업별 활용 현황

생성형 AI는 이미 수많은 산업에서 실무에 투입되고 있습니다. 각 분야별로 어떻게 활용되는지 살펴보겠습니다.

의료 — 문헌 분석과 진단 보조

의료 분야는 생성형 AI의 도입이 가장 활발한 분야 중 하나입니다. 매년 수백만 편씩 출판되는 의학 논문을 의사 혼자 모두 읽는 것은 불가능합니다. AI는 방대한 의학 문헌을 빠르게 분석하고 요약해 주는 역할을 합니다.

💡 실제 활용 사례: 미국의 의료 AI 스타트업 Nabla는 ChatGPT 기반 기술로 의사-환자 대화를 실시간으로 기록하고 진료 노트를 자동 생성합니다. 의사가 문서 작성에 쏟던 시간을 환자 진료에 더 집중할 수 있게 되었습니다.

진단 보조 영역에서는 AI가 의사의 결정을 지원합니다. 환자 증상을 입력하면 가능한 질환 목록과 추가 검사 항목을 제안하거나, 의료 영상(X-ray, MRI)을 분석하여 이상 소견을 찾아냅니다. 다만 AI는 어디까지나 보조 도구이며, 최종 진단은 반드시 의사가 내립니다.

금융 — 리스크 분석과 보고서 자동화

금융 업계는 방대한 데이터를 빠르게 분석하고 보고서를 작성해야 하는 업무 특성상 생성형 AI와 매우 잘 맞습니다.

리스크 분석에서는 수천 페이지 분량의 기업 공시 자료, 뉴스, 재무제표를 AI가 읽고 리스크 요인을 자동으로 정리합니다. 보고서 자동화는 정형화된 형식의 투자 보고서, 실적 요약 보고서 등을 AI가 초안을 작성하면 전문가가 검토하는 방식으로 업무 효율을 크게 높입니다.

💡 실제 활용 사례: 골드만삭스는 내부 코딩 보조 AI를 도입하여 개발자들의 생산성을 향상시켰고, JP모건은 계약서 검토 AI '콘(COiN)'으로 연간 36만 시간의 법률 검토 작업을 자동화했습니다.

교육 — 개인화 학습

전통적인 교육은 모든 학생에게 동일한 방식으로 가르치지만, AI는 각 학생의 수준과 속도에 맞춘 개인화 학습(Personalized Learning)을 가능하게 합니다.

AI 튜터는 학생이 틀린 문제를 분석하여 왜 틀렸는지 설명하고, 부족한 개념을 보충할 문제를 추가 제공합니다. 외국어 학습 앱 듀오링고(Duolingo)는 GPT-4를 활용하여 실제 대화 연습 기능을 제공하며, 학습자의 수준에 맞는 피드백을 즉각적으로 줍니다.

📌 [2026 업데이트] 사례에서 사용되는 모델은 계속 갱신됩니다

이 챕터에서 "듀오링고가 GPT-4를 활용", "GPT-4o mini 사용" 등으로 표기된 모델은 출시 시점 기준 사례입니다. 2026년 5월 기준 같은 회사·서비스는 대부분 GPT-5 / Claude Sonnet 4.5 / Gemini 2.5 Pro 같은 최신 세대로 업그레이드한 상태입니다. 실습 시 무료 티어 모델(예: ChatGPT 무료 플랜의 기본 모델)도 시기마다 변하므로, 코드 실행 직전에 각 제공자의 모델 라인업을 한 번 확인하세요.

마케팅 — 카피라이팅과 콘텐츠 생성

마케팅 팀은 AI 도입으로 가장 빠른 변화를 경험하고 있는 분야입니다.

  • 광고 카피라이팅: 제품 정보를 입력하면 다양한 톤과 스타일의 광고 문구를 수십 개씩 생성
  • 소셜 미디어 콘텐츠: 블로그 포스팅, 인스타그램 캡션, 이메일 뉴스레터 초안 자동 생성
  • A/B 테스트 지원: 여러 버전의 카피를 빠르게 생성하여 어떤 것이 더 효과적인지 테스트

📌 업계 현황: Jasper, Copy.ai 등 AI 마케팅 카피 전문 도구들이 폭발적으로 성장했습니다. 다만 AI가 생성한 콘텐츠는 브랜드 목소리와 일치하는지 사람이 검토하는 과정이 여전히 필요합니다.

법률 — 계약서 분석과 법률 리서치

법률 업무는 방대한 문서 검토가 필요한 분야로, AI가 큰 효율성을 제공합니다.

계약서 분석에서 AI는 수백 페이지 분량의 계약서를 읽고 핵심 조항, 위험 조항, 놓친 항목 등을 자동으로 표시해 줍니다. 법률 리서치에서는 관련 판례와 법령을 빠르게 검색하고 요약합니다.

⚠️ 주의사항: 법률 AI는 정확성이 매우 중요합니다. 2023년 미국에서는 변호사가 AI가 생성한 가짜 판례를 법원에 제출한 사건이 발생하여 큰 논란이 되었습니다. AI의 출력 결과는 반드시 전문가가 검증해야 합니다.

제조 — 공정 최적화와 기술 문서화

제조업에서 AI는 두 가지 방향으로 활용됩니다.

첫째, 공정 최적화입니다. 생산 데이터와 불량률 데이터를 AI가 분석하여 공정 개선 방안을 제안합니다. 둘째, 기술 문서화입니다. 복잡한 설비 매뉴얼, 작업 지침서, 유지보수 보고서를 AI가 초안을 작성하면 엔지니어가 검토하는 방식으로 문서 작업 시간을 크게 줄입니다.

9.3 텍스트 생성의 원리 — 다음 토큰 예측

이제 AI가 텍스트를 만들어내는 내부 메커니즘을 살펴보겠습니다. 핵심 원리는 놀랍도록 단순합니다.

📌 핵심 원리: AI는 "지금까지의 텍스트를 보고, 다음에 올 가장 적절한 단어(토큰)가 무엇인지 예측한다"는 작업을 반복합니다.

토큰(Token)이란?

토큰(Token)은 AI가 텍스트를 처리하는 기본 단위입니다. 단어 전체가 하나의 토큰이 되기도 하고, 단어의 일부가 토큰이 되기도 합니다.

예를 들어 "안녕하세요"는 여러 토큰으로 나뉠 수 있고, 영어의 경우 "unhappiness"는 "un", "happiness"처럼 나뉩니다. 일반적으로 1토큰은 영어 기준 약 4글자, 한국어 기준 약 1~2글자에 해당합니다.

다음 토큰 예측의 과정

AI가 "오늘 날씨가 정말"이라는 텍스트를 받으면 다음과 같이 작동합니다.

AI는 이 확률 분포에서 하나의 토큰을 선택합니다. 선택된 토큰을 입력에 추가한 뒤, 다시 다음 토큰을 예측합니다. 이 과정을 문장이 완성될 때까지 반복합니다.

"오늘 날씨가 정말" → "좋다" 선택
"오늘 날씨가 정말 좋다" → "네요" 선택
"오늘 날씨가 정말 좋다네요" → "." 선택 (문장 종료)

💡 왜 이게 중요한가? AI는 전체 문장을 한번에 "생각"하는 게 아닙니다. 토큰 하나하나를 순서대로 예측하며 글을 써나갑니다. 이 특성이 AI의 강점과 약점 모두를 설명합니다.

확률 분포와 어휘 사전

현대 대형 언어 모델의 어휘 사전(vocabulary)은 수만 개의 토큰으로 이루어져 있습니다. GPT-4의 경우 약 10만 개의 토큰이 있습니다. AI는 매 단계마다 이 10만 개 토큰 각각에 대한 확률을 계산하고, 가장 적절한 것을 선택합니다.

이 선택 과정을 어떻게 하느냐가 바로 디코딩 전략(Decoding Strategy)입니다.

9.4 디코딩 전략

같은 AI 모델이라도 어떤 디코딩 전략을 사용하느냐에 따라 전혀 다른 결과가 나올 수 있습니다. 주요 전략들을 살펴보겠습니다.

Greedy Decoding (탐욕적 디코딩)

Greedy Decoding은 가장 단순한 전략입니다. 매 단계마다 확률이 가장 높은 토큰을 선택합니다.

"오늘 날씨가 정말" 다음에:
- "좋다" 35% ← 항상 이것 선택
- "덥다" 28%
- "나쁘다" 15%
  • 장점: 빠르고 결정론적(같은 입력에 항상 같은 출력)
  • 단점: 창의성이 없고 반복적인 텍스트가 생성되기 쉬움

⚠️ Greedy Decoding은 전체적으로 좋은 문장이 아니라 지금 당장 가장 좋아 보이는 선택만 합니다. 마치 길을 찾을 때 항상 눈앞의 가장 넓은 길을 고르다가 막다른 길에 도달하는 것과 같습니다.

Beam Search (빔 서치)

Beam Search는 Greedy의 단점을 보완합니다. 여러 후보 경로를 동시에 추적하면서 전체적으로 가장 좋은 문장을 찾습니다.

  • 장점: Greedy보다 전반적으로 일관성 있는 문장 생성
  • 단점: 여전히 다양성이 부족하고 계산 비용이 높음

Top-k Sampling

Top-k Sampling은 확률 상위 k개의 토큰 중에서 무작위로 선택합니다. k=50이면 확률 상위 50개 토큰 중에서 랜덤으로 하나를 고릅니다.

k=5 설정 시:
상위 5개 토큰만 남기고 나머지는 제거 후 재정규화
→ 이 5개 중에서 확률에 비례하여 랜덤 선택
  • 장점: 다양하고 창의적인 텍스트 생성 가능
  • 단점: k값이 고정되어 있어 문맥에 따라 적절한 선택지 수가 달라지는 문제를 반영하지 못함

Top-p Sampling (Nucleus Sampling)

Top-p Sampling은 핵 샘플링(Nucleus Sampling)이라고도 합니다. k개가 아니라 누적 확률이 p에 도달할 때까지의 토큰들 중에서 선택합니다.

p=0.9 설정 시:
- "좋다" 35% → 누적 35%
- "덥다" 28% → 누적 63%
- "나쁘다" 15% → 누적 78%
- "춥다" 12% → 누적 90% ← 여기서 멈춤

이 4개 토큰 중에서 랜덤 선택

상황에 따라 자연스럽게 후보 수가 조절됩니다. 명확한 다음 단어가 있을 때는 소수의 후보만, 다양한 선택이 가능할 때는 더 많은 후보에서 선택합니다.

  • 장점: 동적으로 후보 수를 조절하여 자연스러운 다양성 확보
  • 단점: p값 선정이 필요하며, 완전히 예측 불가능한 상황에서 품질 저하 가능

Temperature (온도)

Temperature는 확률 분포의 "날카로움"을 조절하는 파라미터입니다. 이는 위의 전략들과 함께 사용됩니다.

Temperature 특성 적합한 용도
0에 가까울수록 예측 가능, 반복적 코드 생성, 사실 정보 답변
0.7~0.9 균형 잡힌 창의성 일반 대화, 글쓰기
1.5 이상 창의적, 무작위 브레인스토밍, 시 창작

💡 실제 ChatGPT 활용 팁: ChatGPT의 기본 Temperature는 약 0.7~1.0 수준입니다. 창의적인 글쓰기를 요청할 때와 정확한 정보를 물어볼 때 응답 스타일이 다른 것도 이 디코딩 전략과 관련이 있습니다.

9.5 생성형 AI의 한계

생성형 AI는 강력하지만, 반드시 알아야 할 한계가 있습니다. 이 한계를 모르면 AI를 잘못 활용하여 큰 피해를 입을 수 있습니다.

할루시네이션(Hallucination)

할루시네이션(Hallucination)은 AI가 사실이 아닌 정보를 마치 사실인 것처럼 자신 있게 생성하는 현상입니다. "환각"이라고도 번역합니다.

⚠️ 할루시네이션 예시

사용자: "2023년 노벨 물리학상 수상자가 쓴 책을 추천해 줘."

AI: "피에르 아고스티니 교수의 저서 '빛의 아토초 세계'를 추천합니다. 이 책은 2019년 출판되어 물리학계에서 큰 화제가 되었습니다."

→ 이 책은 실제로 존재하지 않을 가능성이 높습니다. AI가 그럴듯하게 지어낸 것입니다.

할루시네이션이 발생하는 근본 원인은 AI의 작동 방식에 있습니다. AI는 "사실"을 저장하는 것이 아니라 "그럴듯한 다음 토큰"을 예측합니다. 즉, 실제로 맞는 말을 하는 것과 그럴듯하게 들리는 말을 하는 것을 구별하지 않습니다.

할루시네이션을 줄이는 방법:

  • 중요한 정보는 항상 공식 출처에서 직접 확인
  • AI에게 "모르면 모른다고 말해줘"라고 요청
  • RAG(Retrieval-Augmented Generation) 기술 활용 (검색으로 사실을 먼저 가져온 뒤 답변 생성)

편향(Bias)

편향(Bias)은 학습 데이터에 내재된 사회적 편견이 AI의 출력에 반영되는 현상입니다.

인터넷에서 수집한 방대한 텍스트 데이터로 학습된 AI는 인터넷에 존재하는 편향을 그대로 흡수합니다. "의사"를 묘사할 때 남성을 기본값으로 가정하거나, 특정 인종이나 문화에 대한 고정관념을 반복하는 것이 그 예입니다.

⚠️ 편향의 종류

  • 성별 편향: 특정 직업군에 성별 고정관념 적용
  • 인종/문화 편향: 서구 중심적 관점, 특정 집단에 대한 부정적 연상
  • 언어 편향: 영어 데이터가 압도적으로 많아 다른 언어 문화권 이해 부족

지식 컷오프(Knowledge Cutoff)

지식 컷오프(Knowledge Cutoff)는 AI가 학습한 데이터의 시간적 한계입니다. AI는 특정 날짜 이후의 정보를 알지 못합니다.

예를 들어 학습 데이터가 2024년 초까지라면, 그 이후 발생한 사건, 새로 출시된 제품, 변경된 법률 등을 알 수 없습니다. 이 점을 모르고 최신 정보를 AI에게 물어보면 오래된 정보를 최신 정보인 것처럼 받게 될 수 있습니다.

📌 실용적 대응: AI에게 물어볼 때 해당 정보가 최신 정보가 필요한지 확인하세요. 시사, 법률, 기술 트렌드 등 빠르게 변하는 분야는 공식 출처를 병행하여 확인하는 습관이 중요합니다.

세 가지 한계 요약

한계 설명 대응 방법
할루시네이션 없는 사실을 자신 있게 생성 중요 정보는 출처 직접 확인
편향 학습 데이터의 편견이 출력에 반영 AI 출력을 비판적으로 읽기, 다양한 관점 요청
지식 컷오프 특정 날짜 이후 정보 없음 최신 정보가 필요하면 검색 엔진 병행

9.6 AI 윤리, 저작권, 규제 동향

생성형 AI가 빠르게 확산되면서 사회 전반에서 중요한 질문들이 제기되고 있습니다.

AI 윤리의 주요 원칙

AI 윤리(AI Ethics)는 AI 시스템이 인간의 가치관과 사회 규범에 부합하게 개발되고 사용되어야 한다는 원칙의 집합입니다. 주요 원칙은 다음과 같습니다.

  • 투명성(Transparency): AI가 어떻게 결정을 내리는지 설명할 수 있어야 함
  • 공정성(Fairness): 특정 집단에 불이익을 주는 차별적 결과를 방지해야 함
  • 책임성(Accountability): AI가 잘못된 결과를 낼 때 누가 책임을 지는지 명확해야 함
  • 프라이버시(Privacy): 개인 정보가 AI 학습이나 처리 과정에서 침해되지 않아야 함

저작권 문제

생성형 AI와 저작권은 현재 전 세계적으로 뜨거운 법적 논쟁의 대상입니다.

학습 데이터 저작권: AI가 저작권이 있는 텍스트, 이미지, 음악으로 학습한 경우 저작권 침해인가? 뉴욕타임스는 OpenAI와 마이크로소프트를 상대로 소송을 제기했습니다.

AI 생성물의 저작권: AI가 만든 글, 그림, 음악의 저작권은 누구에게 있는가? 현재 대부분의 국가에서 AI가 생성한 결과물은 저작권 보호를 받지 못하거나, 인간 창작자의 실질적 기여가 있어야 보호받을 수 있다는 방향으로 논의되고 있습니다.

📌 실무적 주의사항: AI가 생성한 콘텐츠를 상업적으로 활용할 때는 해당 AI 서비스의 이용 약관을 반드시 확인해야 합니다. 서비스마다 생성물에 대한 권리 귀속이 다릅니다.

질문: "한국의 인공지능 관련 정부 정책을 3가지로 요약해서 설명해 줘."

응답을 받은 후 다음을 비교해 보세요.

  • 두 AI가 언급한 정책이 서로 일치하는가?
  • 구체적인 수치나 날짜가 있다면 정확한가? (공식 출처와 대조)
  • 응답의 길이와 구조가 어떻게 다른가?

실습 2 — 창의적 글쓰기 비교

질문: "AI가 인간의 일자리를 빼앗는다는 주제로 단편 소설의 첫 문단을 써줘. 
분량은 200자 내외."

비교 포인트:

  • 어떤 AI가 더 창의적이고 흥미로운 글을 썼나?
  • 문체와 표현 방식이 어떻게 다른가?
  • 두 응답 중 어느 것이 더 마음에 드는가, 그 이유는?

실습 3 — 최신 정보 테스트 (지식 컷오프 확인)

질문: "2025년에 가장 화제가 된 AI 모델은 무엇인가요?"

⚠️ 관찰 포인트: 두 AI가 어떻게 응답하는지 주목하세요. 자신 있게 답변하는가, 불확실성을 표현하는가? 지식 컷오프를 인정하는가? 이것이 바로 AI의 한계를 인식하는 능력(자기 인식 능력, Self-awareness)의 차이입니다.

이번 챕터에서는 생성형 AI가 현실 세계에서 어떻게 활용되는지, 그리고 그 내부에서 어떤 원리로 텍스트를 생성하는지 살펴보았습니다.

핵심 요약

  • 산업 활용: 의료(문헌 분석·진단 보조), 금융(리스크·보고서), 교육(개인화 학습), 마케팅(카피라이팅), 법률(계약서 분석), 제조(공정 최적화) 등 전 산업에 걸쳐 생성형 AI가 도입되고 있습니다.
  • 도입 성공 요인: AI 역할의 명확한 정의, 사람의 검토 단계 포함, 점진적 도입이 핵심입니다.
  • 텍스트 생성 원리: AI는 다음 토큰 예측(Next Token Prediction)을 반복하여 텍스트를 생성합니다.
  • 디코딩 전략: Greedy(결정론적), Beam Search(다중 경로 탐색), Top-k(상위 k개 랜덤), Top-p/Nucleus(누적 확률 기반 랜덤), Temperature(확률 분포 조절) 등의 전략이 있습니다.
  • AI의 한계: 할루시네이션(없는 사실 생성), 편향(학습 데이터의 편견 반영), 지식 컷오프(최신 정보 없음)를 항상 인식해야 합니다.
  • AI 윤리와 규제: 투명성·공정성·책임성·프라이버시 원칙이 중요하며, 전 세계적으로 위험도 기반 차등 규제가 확산되고 있습니다.
